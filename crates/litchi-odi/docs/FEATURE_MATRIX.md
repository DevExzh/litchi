# ODI Feature Matrix

This matrix records the current public `litchi-odi` capability for packaged
OpenDocument images and flat ODI snapshots. Both surfaces expose a bounded,
inert frame, map, source, metadata, and package-resource inventory.

| Mark | Meaning |
|---|---|
| ✅ | Supported for the narrow scope in Notes |
| 🟡 | Partial, raw, detached, or preservation-only |
| ❌ | No public support |
| N/A | The direction does not apply |

| Feature | Status | Read | Write | Notes |
|---|---|---|---|---|
| ODI package snapshot | ✅ | ✅ | ✅ | Exact image MIME, namespace-aware family structure, original bytes, safe package names, inert frames, and package-local resources are exposed. |
| Raw `content.xml` | 🟡 | ✅ | 🟡 | Opening checks UTF-8, a 256 MiB ceiling, the namespace-aware document/body/image shape, and ODF 1.4's single frame/single image contract. Full Relax NG validation remains absent. |
| Fresh package builder | ✅ | N/A | ✅ | The deterministic baseline contains a valid embedded 1×1 PNG. Typed frame and image-map authoring supports linked/inline sources, accessibility, styling, geometry, layers, and z-order. Compact `styles.xml`/`meta.xml` plus bounded typed package members are accepted. |
| Compact XML | ✅ | N/A | ✅ | Fresh and changed authored XML passes the shared compact publication boundary. Indentation, tabs, padded markup, and space-only inter-element nodes return structured `XmlCompactness` errors; semantic character data and `xml:space="preserve"` content remain exact. |
| Styles and metadata | ✅ | ✅ | ✅ | Optional style XML remains exact and supports compact whole-part add/replace/remove with durable inverse and semantic package replay; frame graphic/text style references are typed and editable. Callers can classify an exact name/family dependency as absent, named, automatic, equivalent duplicate, or colliding. Cross-package frame transfer carries a bounded exact-fragment closure containing the referenced named or automatic style plus transitive `style:parent-style-name`, `style:next-style-name`, and paragraph/text `style:linked-style-name` dependencies. Compatible definitions merge into existing or deterministically created `office:styles`/`office:automatic-styles` containers; different exact XML, missing closure nodes, excessive closure size, or incompatible namespace bindings refuse instead of overwriting. Flat `office:meta` and packaged `meta.xml` share title/author/subject/description/keyword edits that preserve unknown nodes. General caller-directed granular style CRUD and closure over non-`style:style` resources such as list/data styles, gradients, master pages, fonts, and markers remain absent. |
| Frames and image sources | ✅ | ✅ | ✅ | Packaged and flat ODI durably edit source/image link semantics, frame/image XML identity, accessibility title/description, declared media/filter/XLink fields, style/layer/z-order/transform/anchor data, absolute and relative lexical geometry, and `draw:copy-of`. One shared edit trait and semantic wire cover both artifact kinds without dereferencing links. |
| Images, maps, geometry, and resources | ✅ | ✅ | ✅ | Rectangle/circle/polygon maps retain target-frame and full inert XLink type/show/actuate behavior and support ordered typed append/replace/remove plus bounded durable publication while map extensions cause lossless refusal. The resource graph includes referenced, missing, and unreferenced members and exposes an explicit presence/reference lifecycle state; safe-path auxiliary-member add/replace/remove preserves unrelated payloads. Rendering and conversion remain absent. |
| Semantic patches, merge, and transfer | ✅ | N/A | ✅ | Flat/package commits produce stable-key compare-and-set operations with exact source/target bytes, inverse and stale refusal. Join detects same-key divergence; non-mutating three-way plans report expected/actual/desired conflicts. Compatible frame/style/map/metadata operations transfer between flat and package artifacts. A package-origin frame transfer copies an absent referenced member and merges its bounded exact named/automatic style closure into a compatible existing or deterministic new style part; mismatched, unavailable, or namespace-incompatible dependencies produce explicit conflicts. Flat-origin patches cannot manufacture package bytes or detached style definitions and therefore refuse a transfer whose destination lacks them. Publication rechecks the planned source, policy-bounds dependency bytes, and fully reopens output bytes. |
| Existing-package edits and history | ✅ | N/A | ✅ | Flat and packaged ODI share frame and metadata edit contracts, exact no-ops, atomic semantic readback, inverse/apply patches, and safe package-resource CRUD. Commit-coupled history is source checked, branch safe, and bounded by both state count and exact serialized-byte budget. Signed, encrypted, or non-compact rewrite sources remain refused. |
| Flat ODI snapshots | ✅ | ✅ | ✅ | `FlatImage` requires namespace-aware `office:document/office:body/office:image/draw:frame/draw:image` placement, rejects DTDs and excessive depth, inventories supported inert sources, preserves exact bytes, and losslessly edits frame/style/geometry/source/map and embedded metadata sites. |
| Untouched-byte preservation | ✅ | ✅ | N/A | Original package and flat XML bytes are returned exactly while no mutation is attempted. |
| Encryption and signatures | 🟡 | ✅ | ❌ | `Image::from_bytes_with_password` and `open_with_password` expose lazy password decryption for inert inspection. Exact signature-member and encrypted-manifest-entry paths plus signed/encrypted rewrite disposition are public. Document/macro signature metadata is readable, and document-signature cryptographic math can be verified without making a certificate-trust claim. New encryption, signing/re-signing, trust validation, and changed-byte publication of any protected snapshot remain absent; rewrites refuse rather than strip or silently weaken protection. |
| Forms and producer extensions | 🟡 | ✅ | 🟡 | Namespace-aware bounded inventories expose `office:forms`, form-namespace and XForms elements, and unknown-namespace elements/attributes across flat XML and packaged content/styles. Each occurrence reports exact lexical QName, resolved namespace, location, exact-preservation disposition, and unsupported direct-mutation disposition; forms additionally expose inert name, control-ID, and target/link values. No value or target is activated, and non-overlapping edits retain exact source bytes. Typed control behavior, arbitrary package-XML extension discovery, and direct form/extension mutation remain absent. |
| Active content | 🟡 | ✅ | 🟡 | Namespace-aware, bounded inventories expose `office:script`, script/presentation event listeners, `text:execute-macro`, DDE constructs, and package members under producer script containers (`Basic/`, `Dialogs/`, and `Scripts/`). Language, event, target, DDE application/topic/item coordinates, element, location, and member paths remain inert; no target or member is loaded, decoded, dereferenced, activated, or executed. Active-content mutation remains absent; forms and producer extensions have the separate disposition inventory above. |
| Security policy and limits | ✅ | ✅ | ✅ | Explicit policies bound operation count, retained patch bytes, resource/inline bytes, metadata text, map areas, external links, package-member changes, and introduction of inventoried active content. Callers can inspect allowed/refused link, member, and active-content capabilities; plan lifecycle (`Ready`, conflict-refused, active-content-refused, or policy-refused); exact style dependency lifecycle; form/extension dispositions; exact protected-member inventory/disposition; and all detected package/flat rewrite blockers (signature, encryption, non-compact XML, or unreadable XML) before publication. Strict policy permits sanitizing removal but refuses an active XML value or producer script-container member in the planned result. Family inputs/output remain capped at 256 MiB, active/form/extension inventories at 100,000 items per class, style closure at 1,024 definitions, history at 1,024 states plus a caller byte budget, and XML depth at 256. Unsafe/reserved paths, stale plans, lossy map rewrites, signed or encrypted packages, and hostile policy excesses fail before publication. |
| Evidence and provenance | ✅ | ✅ | ✅ | Checked-in ODFDOM 0.13.0 original and changed ODI packages provide a pinned programmatic-producer chain: official `OdfImageDocument.newImageDocument`, exact Apache-2.0 Maven artifact checksum, original package checksum, separate load/name-change/save checksum, correct ODI MIME, and exact unchanged/differing member evidence are recorded in the fixture README. The legacy generator text inherited from ODFDOM's bundled template is explicitly not treated as identity. Earlier LibreOffice/OpenOffice/NeoOffice/Tika searches remain recorded as negative route evidence; no artifact was relabeled. `odf-1.4-normative-synthetic.fodi` remains explicitly synthetic and separate. |
