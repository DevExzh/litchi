# ODB Feature Matrix

This matrix records the current public `litchi-odb` capability. The crate is
an immutable OpenDocument database package reader with a bounded inert schema
catalog, not a database runtime.

| Mark | Meaning |
|---|---|
| ✅ | Supported for the narrow scope in Notes |
| 🟡 | Partial, raw, detached, or preservation-only |
| ❌ | No public support |
| N/A | The direction does not apply |

| Feature | Status | Read | Write | Notes |
|---|---|---|---|---|
| ODB package snapshot | 🟡 | ✅ | N/A | Exact database MIME, UTF-8, a bounded namespace-aware `office:document-content/office:body/office:database` structure, and exactly one direct `db:data-source` are required. Original bytes, raw content/styles, projected metadata, and file names are exposed. |
| Raw `content.xml` | 🟡 | ✅ | ✅ | Existing package XML remains exact and is never reformatted. Opened-document edits splice only selected tags/subtrees, including formatted LibreOffice XML. Fresh authored XML remains compactness-checked. Unknown adjacent XML is not normalized or discarded. |
| Fresh package builder | 🟡 | N/A | 🟡 | Creates a compact, structurally valid inert data-source shell plus raw content and manifest. Existing snapshots publish through the shared provenance-bearing ODF XML splice boundary. |
| Compact XML | ✅ | N/A | ✅ | Fresh input and generated content are compact: no indentation or formatting whitespace is emitted. Semantic character data and `xml:space="preserve"` content remain exact. Existing source packages are preserved byte-for-byte. |
| Connections and queries | ✅ | ✅ | ✅ | `Database::catalog()` exposes inert file, resource, or server targets plus stored-query command, escape-processing, result-column, filter, order, and qualified update-table metadata. Bounded command analysis provides source-ordered parameters/joins and conservative typed semantics for common `SELECT`/`INSERT`/`UPDATE`/`DELETE` shapes, relation roles, distinct/group/having/order/row-limit structure, and exact dependency-support reasons. Explicit dependency-aware query transfer can refuse missing relations or cascade local tables and their foreign-key closure atomically. CTEs, subqueries, set operations, table functions, multiple statements, and unresolved qualified/external relations are typed refusals rather than guessed graphs. No command is prepared or executed. |
| Schemas, tables, columns, keys, indices, forms, and reports | ✅ | ✅ | ✅ | The unified transaction provides create/replace/remove operations plus dependency-aware table/column renames and refuse/cascade deletion. Columns retain inert defaults; primary/unique/foreign keys, referential actions, ordered unique/clustered indices, incoming/outgoing projections, and local relation-resolution states are typed. Authored ambiguous duplicate columns/constraints/indices/mappings and multiple primary keys fail before mutation. Components expose link, active-content, and exact package-dependency inventories. Compact local form/report subtrees plus transitive package-local `xlink:href` files transfer byte-for-byte with shared dependency reuse; collisions, changed link meaning, active content without opt-in, encrypted donors, and producer-formatted XML relocation lacking path-bound donor provenance are explicit preflight refusals. External IRIs are never followed. |
| Existing-package edits and patches | 🟡 | ✅ | ✅ | Compact or formatted packages support ordered multi-owner transactions, atomic rebuild/full reopen, exact-source application, exact inverse restoration, semantic effect history, budgeted snapshot `History`, bounded dependency-aware semantic and linked-payload transfer, canonical durable JSON patches, deterministic disjoint joins, and non-mutating three-way conflict plans. Exact inverse, durable application, history, and collision-checked join materialization retain resource-bearing artifacts. |
| Untouched-byte preservation | ✅ | ✅ | ✅ | Original bytes are exact before mutation. Changed saves publish checked source ranges through the shared provenance-bearing ODF boundary; untouched package members remain exact and inverse patches restore the accepted source artifact exactly. |
| Encryption and signatures | 🟡 | ✅ | 🟡 | Password-encrypted packages can be opened without exposing database credentials. Signature XML can be inventoried and cryptographically checked without a PKI trust claim. Exact no-ops preserve source protection; changed encrypted publication is refused; changed signed publication is refused by default and may explicitly remove invalidated signature members. `protection_decision()` returns `Supported` for verification/removal and distinct typed `ReSigningUnavailable`/`ReEncryptionUnavailable` refusals before credentials or signing material are gathered. |
| Permanent database non-execution boundary | ✅ | N/A | N/A | No driver, network, credential, query, refresh, or database execution path exists. External configuration remains inert text. |
| Active content | ✅ | ✅ | N/A | `Database::active_content()` returns a bounded, source-located inert inventory of Basic macros, scripts, event listeners, form controls, actions, DDE declarations, and embedded objects. Linked component transfer refuses active dependencies by default and requires explicit `ActiveContentDisposition::CopyInert` to preserve their bytes. Candidate XML is namespace-aware and strictly decoded; no member is activated or executed. |
| Limits and evidence | ✅ | ✅ | ✅ | Snapshot content and changed output have 256 MiB ceilings; unified transactions cap operations at 65,536 and semantic/opaque values at 1 MiB; query analysis caps source at 1 MiB and tokens/parameters at 65,536; component closure caps files/directories at 4,096 and bytes at 64 MiB; active-content scanning caps decoded XML at 32 MiB and findings at 16,384. Forty-seven scoped tests cover typed SQL/dependency refusal and cascade, schema ambiguity/refusal, component inventory and closure, durable/inverse/history/merge/full reopen, and exact auxiliary-member preservation across three genuine resource-bearing LibreOffice Base packages. Live Base execution remains outside the crate and database content is never executed. |
