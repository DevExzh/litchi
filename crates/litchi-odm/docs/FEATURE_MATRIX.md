# ODM Feature Matrix

This matrix records the current public `litchi-odm` capability for
OpenDocument master documents. The crate is a cheaply cloneable immutable
package snapshot with bounded semantic projection and source-checked unified
transactions; detached construction values remain separate from parsed
package references.

| Mark | Meaning |
|---|---|
| ✅ | Supported for the narrow scope in Notes |
| 🟡 | Partial, raw, detached, or preservation-only |
| ❌ | No public support |
| N/A | The direction does not apply |

| Feature | Status | Read | Write | Notes |
|---|---|---|---|---|
| ODM package snapshot | ✅ | ✅ | N/A | Exact text-master MIME is required; original bytes, safe file names, raw XML, projected metadata, and title are exposed. |
| Raw `content.xml` | 🟡 | 🟡 | 🟡 | Original producer XML is accepted when it is UTF-8, bounded, DTD-free, well formed, and has namespace-aware `office:document-content/office:body/office:text` placement. Fresh authored XML remains subject to the shared compact-XML gate. Prefix aliases are accepted. Duplicate `text:section`, generated-index `text:name`, and `xml:id` identities are rejected; generated indexes require an addressable name plus an ordered kind-specific source and index body. Direct master-body lists require ordered list-header/list-item content, and tables require recognized column/row containers with row content. Paragraph and heading inline content remains intentionally open for ODF/extension mixed content. |
| Fresh package builder | ✅ | N/A | ✅ | Creates MIME, compact `content.xml`, and manifest. In addition to an explicitly validated compact XML source, callers can append bounded typed paragraphs, level 1–10 headings, non-empty lists, named rectangular tables, and generated indexes. Publication validates the complete assembled master through the same semantic codec used on open. |
| Compact XML | 🟡 | 🟡 | ✅ | Producer formatting is accepted on open and the unchanged source artifact is retained exactly. A changed transaction losslessly compacts safe producer formatting while preserving semantic text and `xml:space="preserve"` content; untouched auxiliary member payloads remain exact. Fresh and changed XML passes the shared authored audit, which rejects ambiguous all-space character nodes, indentation, padded markup, DTDs, and custom entities. Unsafe producer content is refused rather than normalized ambiguously. |
| Styles and metadata | 🟡 | ✅ | 🟡 | Named `style:style` definitions from `content.xml` and `styles.xml` are projected with family, parent, and owning part. Transactions can add minimal styles, rename definitions plus modeled references, or remove unreferenced styles. Cross-master import preserves complete style XML and can create a compact `styles.xml` owner when the destination has none. Common metadata is projected; title, author, subject, description, and keywords are atomically editable while other metadata is preserved. |
| Sections and subdocuments | ✅ | ✅ | 🟡 | The snapshot projects common direct master-body paragraphs, headings, lists, tables, declarations, sections, and generated indexes in authored order; generated-index kind, body position, `text:name`, and `xml:id` are exposed. Unified transactions can append typed paragraphs, headings, lists, tables, and generated indexes, and remove checked direct common/extension subtrees by exact source span; sections retain dependency-aware removal and declaration containers remain read-only. Dependency-free common items can be transferred from another immutable master with exact SHA-256/item/kind provenance; style- or resource-dependent fragments receive a typed refusal rather than an incomplete copy. Its complete ordered `text:section` tree exposes parent/child positions, style, `xml:id`, protection, a unified linked/local/DDE source kind, and resolved or unresolved local-section relationships. Transactions can rename addressable generated indexes; add empty or linked root sections; rename a section plus modeled local-only references; or remove a subtree after checking incoming references to every descendant. |
| Package resource graph | ✅ | ✅ | 🟡 | Safe package members expose declared media type and exact incoming linked-section positions. Transactions can add, replace, remove, or transfer resources. Cross-master linked-section transfer atomically copies its package member and complete style-parent closure, preserves complete source style XML plus source-section/filter semantics, reuses identical collisions, and deterministically renames differing style/resource collisions under explicit options. Partial/external sources are refused. Subtree cleanup removes only resources exclusively referenced by that subtree. |
| Permanent external-resolution boundary | ✅ | N/A | N/A | Subdocument references are classified only; neither safe package paths nor external targets are opened, resolved, fetched, or recursively loaded. |
| Existing-package edits and patches | ✅ | ✅ | 🟡 | `Master::edit()` stages title/link, simple metadata, typed direct body-item additions/removals, section-tree, generated-index, style, and resource changes and publishes them with compact authored XML, one full-package reopen, and typed readback. Strict security policy validates the final graph, refusing external and unresolved package targets, refusing active content unless inert preservation is explicitly selected, and bounding transferred resources/content. Exact-source reversible patches support non-mutating three-way planning, typed position/identity/body/style/resource conflicts, disjoint merge, bounded undo/redo history, deterministic durable exchange, stale-source refusal, inverse application, and forward-only sealing. Changed edits refuse signed/encrypted packages. |
| Untouched-byte preservation | ✅ | ✅ | ✅ | A no-op preserves the exact source archive. Changed publication preserves untouched auxiliary member payload bytes, but the rebuilt archive's physical ZIP records may be normalized. Exact-source inverse patches restore the complete original artifact byte for byte. |
| Encryption and signatures | 🟡 | 🟡 | ❌ | Cryptographic authoring is intentionally final-scoped as unavailable, not silently attempted. The public security inventory reports recognized signatures and manifest encryption, and its closed write-capability model distinguishes unavailable creation from exact-preservation-only lifecycle for existing cryptographic artifacts alongside the intrinsic changed-write disposition. Password-encrypted bytes can be opened with an explicit password for inert inspection. Exact no-op transactions preserve signed/encrypted bytes; any changed transaction and credential-free durable publication is refused. Signature verification, signing, resigning, and encrypted authoring are absent. |
| Active content | 🟡 | ✅ | 🟡 | The public security inventory classifies DDE, script/macro XML, conventional script resources, form controls, and script/presentation event listeners without execution. Listener trigger, action, macro target, and link remain inert typed strings. Changed writes refuse recognized active content by default; callers must explicitly select `PreserveInert`, which retains it without interpretation or execution. Broader embedded-code semantics remain preservation-only. |
| Limits and evidence | ✅ | ✅ | 🟡 | Snapshot semantic parts have explicit byte/depth/count and 16 KiB semantic-value bounds; typed lists/tables add item, row, column, and total-cell limits. DTD and non-predefined named entities are rejected while the five predefined XML entities remain valid content. Tests directly open and materially edit a checked-in original LibreOffice `.odm` without fixture repacking; append all typed common body kinds; verify compact XML, exact unchanged-source/inverse preservation, durable replay, merge/history/conflicts, provenance-preserving dependency-free body transfer, ODF MIME-first/stored output, and full reopen; and cover raw producer ZIP child-schema negatives, dependency-complete linked-section transfer/cleanup, cryptographic write dispositions, and final-graph policy. Current LibreOffice resave automation is not available in the test environment. |
