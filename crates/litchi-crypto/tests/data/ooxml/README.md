# OOXML crypto interoperability fixtures

These fixtures are independent regression inputs for `litchi-crypto`.
The encrypted files generated by `msoffcrypto-tool` below are third-party
interoperability vectors; they are not native Microsoft Office output. Native
Office provenance is tracked separately when a real Office fixture is
available.

- `component-standard-aes192-sha1.docx` and `component-standard-aes256-sha1.docx` were built by `generate_standard.py` with `msoffcrypto-tool==6.0.0` and `cryptography==50.0.1`, using the Standard AES envelope in MS-OFFCRYPTO 2.3.4.5 and the 50,000-iteration key derivation in 2.3.4.7.
- `msoffcrypto-agile-aes256-sha512-valid-graph.docx` was emitted by `msoffcrypto-tool==6.0.0` from the LibreOffice `strict.docx` source and independently password/decrypted with HMAC verification. Its CFB copy has only the third party writer's zero `EncryptionBlockSize` corrected to the normative AES block size of 16; `EncryptionInfo` and `EncryptedPackage` are unchanged. The original unmodified file is retained in the source manifest directory used to record that compatibility defect.
- `component-agile-aes128-wrap-aes256-data-sha512.docx` was built by `generate_agile_mixed.py`. It exercises the normative Agile distinction between the AES-128 encrypted-key wrapper and AES-256 keyData while keeping cipher and hash names matched as required by MS-OFFCRYPTO.
- `rust-standard-aes192.docx`, `rust-standard-aes256.docx`, and `rust-agile-aes256-sha512.docx` were emitted by the implementation and decrypted by `msoffcrypto-tool==6.0.0`; `rust-output-manifest.json` records the hashes and byte equality result.

The component and msoffcrypto-derived fixtures use the test password `Litchi synthetic crypto fixture 2026`; the implementation-produced files listed in `rust-output-manifest.json` use `Litchi rust interop output 2026`. These passwords and the deterministic salts/keys are test material only. The JSON manifests record provenance and SHA-256 hashes; the Python generators are retained to make the component vectors reproducible. Generic DataSpaces inspection remains strict. The OOXML encryption adapter has a field-local read compatibility for the third-party writer's zero advisory block-size field, while the canonical fixture copy retains the normative value of 16.
