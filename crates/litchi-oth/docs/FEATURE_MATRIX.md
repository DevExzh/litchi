# OTH Feature Matrix

This matrix records the current public `litchi-oth` capability for
OpenDocument HTML templates. The crate validates the ODF text-web package
envelope and exposes an inert, namespace-aware text-block projection.

| Mark | Meaning |
|---|---|
| ✅ | Supported for the narrow scope in Notes |
| 🟡 | Partial, raw, detached, or preservation-only |
| ❌ | No public support |
| N/A | The direction does not apply |

| Feature | Status | Read | Write | Notes |
|---|---|---|---|---|
| OTH package snapshot | ✅ | ✅ | N/A | Exact text-web MIME, bounded family-envelope validation, original bytes, safe file names, raw XML, and projected metadata are exposed. |
| Raw `content.xml` | 🟡 | ✅ | ✅ | Opening accepts bounded ordinary or compact DTD-free XML and requires exactly one namespace-aware `office:document-content/office:body/office:text` chain plus representative ODF list/form and text-inline containment constraints. Fresh authoring remains byte-minimal. Prefix aliases work; a wrong namespace, root, duplicate, misplaced family container, orphan list item, or inline element outside a text block fails. The machine-readable capability contract explicitly refuses full ODF Relax NG validation. |
| Fresh package builder | 🟡 | N/A | ✅ | Creates and reopens a compact ODF 1.4 text-web envelope with MIME, typed plain/rich headings and paragraphs, nested lists, inert forms, typed metadata/common styles, external references, embedded file payloads, and complete object member sets, or test/advanced raw content. Rich inline content is semantically reopened before publication. Raw and typed content, metadata, or styles cannot be mixed. |
| Compact XML | ✅ | ✅ | ✅ | Authored XML is bounded and byte-minimal. Existing pretty-printed producer XML opens byte-exact; changed XML parts are compacted without field evaluation, link following, or object activation before the strict package publication boundary. |
| Styles and metadata | 🟡 | ✅ | 🟡 | Named style declarations, family, parent, declaring part, and a bounded text-property subset (foreground/background RGB, weight, and posture) are typed. Metadata is projected through the common reader. Compact typed whole-part replacement or deletion participates in ordinary edits, durable inverse patches, join conflicts, and three-way plans. General property families, inheritance resolution, and per-field metadata operations remain future work. |
| Text blocks and character data | 🟡 | ✅ | ✅ | `Template::text_body()` projects ordered `text:p` and `text:h` blocks, style names, inert hyperlinks, formatting ranges, common field families and stored values, bookmarks (including cross-block ranges), and ODF whitespace without evaluation or link following. Direct-text edits remain lossless-span-only. Complete inline replacement and exact-boundary prepend/append author compact typed text, links, styled spans, stored fields, and bookmark markers; boundary splices work for nested-list paragraphs while preserving unknown producer markup byte-for-byte inside the selected inline region. These operations are durable, reversible, merge/history-aware, transferable where all dependencies are projected, and fully reopened. Destructive typed replacement of unknown inline markup remains refused. |
| Lists, resources, forms, and objects | 🟡 | ✅ | ✅ | Flat and nested list trees, numbering restarts, paragraph positions, images, embedded/linked object references, forms, and controls are inventoried as inert typed values. Nested trees support recursive authoring plus individual or outer-tree replace/remove with overlap refusal. The complete inert form/control catalog supports typed create/replace/remove. Resource references support replace/remove/append, and embedded payloads support create/replace/remove with package-path, media-type, dependency, and collision validation. Payload publication fails closed if a surviving reference would dangle. Active content remains inert. |
| Existing-package edits and patches | 🟡 | N/A | ✅ | `Template::edit()` stages bounded paragraph/heading text, rich-inline replacement or provenance-safe boundary insertion, nested-list tree replace/remove, complete form-catalog CRUD, resource reference/payload CRUD, whole metadata/style replacement or deletion, and typed tail additions. Commit compacts changed XML, rebuilds and reopens once, and checks exact inline-source preconditions plus semantic, payload, media-type, dependency, and structural readback. Exact-source inverse application is byte-exact. Independent disjoint edits join with typed conflicts, and `Patch::plan_three_way` produces a deterministic conflict plan before publication. Signed sources refuse mutation; exact no-ops share the source snapshot. |
| Durable patches | ✅ | ✅ | ✅ | `Patch::to_bytes`/`from_bytes` use a deterministic bounded envelope, fully reopen embedded source and target snapshots, preserve exact stale-source application and inverse restore, and retain paragraph, heading, rich-inline, form-catalog, nested-list-tree, resource reference/payload, exact compact tail-fragment, and optional-part semantics for inspection and three-way planning after restart. Duplicate selectors, overlapping list trees, stale payload bytes/media types, and dangling target dependencies fail closed. |
| Undo/redo history and transfer | 🟡 | N/A | ✅ | Format-owned `History` wraps the common finite step/byte budget over immutable OTH snapshots and supports checked record, undo, and redo across resource-bearing commits. `plan_transfer_from` preserves exact compact rich heading/paragraph/list XML while retaining typed readback, detaches paragraphs inside lists and nested-list selectors as standalone destination blocks, copies outer nested list trees, resolves paragraph/text-style parent closure, and copies complete embedded file or object-directory dependency sets. A resource selector transfers an inert reference with its full package closure. Missing dependencies, byte collisions, unprojected inline content, and denied security surfaces are refused. |
| Untouched-byte preservation | ✅ | ✅ | N/A | Original bytes are returned exactly before mutation. Rebuild copies untouched auxiliary members byte-for-byte; transfer adds only validated selected dependency members. |
| Encryption and signatures | ❌ | ❌ | ❌ | Explicitly final-scoped out of the OTH semantic API: password opening, cryptographic verification, signing, and changed publication of signed sources are refused. Signature members remain available only through inert inventory under an explicit read policy. |
| Permanent non-execution boundary | ✅ | N/A | N/A | Links are never followed; scripts, macros, controls, actions, DDE, and embedded code are never executed or activated. `check_security` inventories embedded/external resources, forms, script members, and signatures and enforces a default-deny explicit policy while keeping permitted surfaces inert. A machine-readable contract marks inventory/policy supported and external resolution, execution, password opening, signature verification, and changed signed publication refused. |
| Limits and evidence | ✅ | ✅ | ✅ | `content.xml` uses 64 MiB and depth-256 input ceilings plus bounded block/link/field/list/attribute projections; each direct-text replacement or boundary edit is capped at 16 MiB projected text and durable envelopes at 512 MiB. A checked-in LibreOffice Writer/Web template package is opened byte-exact, edited, enriched with an inert resource through the public API, and fully reopened; this is not presented as a native changed-save. Source tests cover unknown-inline-preserving nested boundary splices across durable replay/inverse/merge/history/transfer, fresh rich/form/style/metadata/resource/object authoring, resource reference/payload CRUD, dangling-refusal and coordinated removal, outer nested-tree replacement, object-directory closure/collision handling, compact reopen/readback, explicit validation/security capabilities, signed/script policy refusal, and test-only raw malformed/prettified ZIP negatives. |
