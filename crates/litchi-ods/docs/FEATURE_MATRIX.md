# ODS/OTS and flat ODS Feature Matrix

This document tracks the public and source-level feature coverage of the
`litchi-ods` OpenDocument Spreadsheet implementation for packaged ODS and OTS
files and bounded flat single-XML ODS documents. It is a capability matrix, not a claim of complete ODF conformance,
formula compatibility, or rendering fidelity.

The ODF common package layer is shared with the other OpenDocument families.
Rows below call out when a capability is only available as inert metadata,
package preservation, a public scalar codec, or a typed source model that is
not yet connected to the ODS facade.

## Status model

| Mark | Meaning |
|------|---------|
| ✅ | Supported for the feature scope described in the Notes cell |
| 🟡 | Bounded, partial, metadata-only, pass-through, source-level, or otherwise limited support |
| ❌ | No public typed support currently available |
| N/A | The concept does not apply to the format or direction |

`Read` and `Write` describe the public direction independently. A 🟡 direction
must not be read as full semantic CRUD. External links, database sources,
DDE, scripts, macros, and embedded payloads are inert unless a row says
otherwise.

## Audit scope

The ODS-specific source vocabulary includes cell, row, sheet, formula,
conditional-format, validation, DataPilot, database-range, protection,
scenario, consolidation, detective, sparkline, DDE, and tracked-change models.
The current crate exports the package facade, named-definition APIs, formula
codec, resource inventories, RDF APIs, and the bounded worksheet graph through
`litchi_ods::worksheet`, `Spreadsheet`, `Builder`, and
`MutableSpreadsheet`. This is a worksheet graph, not a full calculation or
rendering engine.

The Microsoft `[MS-XLSX]` Front Matter and ToC describe extensions to OOXML
SpreadsheetML, not ODS. Their Part Enumerations, Extensions, Conceptual
Overview, and listed structure families were used as a gap checklist only;
the existence of an XLSX feature is never treated as ODS support.

| Open, create, and save ODS/OTS packages | ✅ | ✅ | ✅ | `Package` and `Spreadsheet` open paths or bytes; `Builder` creates a valid spreadsheet package; `MutableSpreadsheet` saves a package after the supported package edits |
| Flat single-XML ODS (`.fods`) | 🟡 | ✅ | 🟡 | `flat::{Snapshot, Transaction, Commit, Patch}` (also `FlatSpreadsheet`) validates the flat spreadsheet MIME/root, exposes sheets/cells, metadata, DDE and scenario inspection, and publishes bounded cell edits with source-checked inverse patches and reopen validation. | ZIP package, manifest, and MIME validation | ✅ | ✅ | ✅ | Shared ODF package layer validates the manifest and spreadsheet/template media types and writes deterministic package entries |
| Unified package transactions and durable patches | ✅ | ✅ | ✅ | `document::{Snapshot, Edit, Commit, Patch, ThreeWayPlan, History}` composes worksheet, rich cell runs, row/column/sheet structure, automatic style graphs, conditional formats, sparklines, typed inert forms/events, positioned/grouped text drawings and geometry, typed package-backed charts and dependency transfer, definition, annotation, RDF, protection, DataPilot, tracked-change, and bounded resource edits into one clone-staged atomic publication. Changed signed input requires explicit stale-signature stripping; encrypted transactional input and already-protected input remain refused |

| `meta.xml` and `settings.xml` | 🟡 | ✅ | 🟡 | `meta.xml` has a typed snapshot plus bounded common-field CRUD; literal application `settings.xml` remains inert and is preserved through package edits |
| ODF metadata and document statistics | 🟡 | ✅ | 🟡 | `Spreadsheet::odf_metadata()` exposes the shared typed ODF model; the facade edits the common projection through retained-source patches while extended fields remain lossless/read-only |
| Common styles and data styles | 🟡 | 🟡 | 🟡 | The unified root can add or same-family replace closed automatic number, date, time, currency, percentage, boolean, text, and table-cell style graphs; conservatively remove unreferenced automatic styles package-wide; and resolve the supported effective cell/text projection across common and automatic package styles. Page/master/layout style families remain preserved rather than semantically authored |
| Table templates and banding (`table:table-template`) | 🟡 | ✅ | ✅ | `styles::table_template::{Snapshot, Edit, Commit, Patch}` plus `Spreadsheet`, `MutableSpreadsheet`, and `Builder` provide bounded standalone catalog CRUD, exact no-op/source checks, inverse patches, typed readback, and styles-part preservation. Fresh template XML is owned by `office:styles` and emits the four required edge selectors plus `table:body`; a worksheet exposes the normative `table:template-name` and six `table:use-*` selection flags. Legacy producer copies of those flags and `text:*` axis aliases on `table:table-template`, plus records missing required selectors, remain readable as exact no-ops, while changed rewrites refuse to discard or canonicalize those source tokens. | Images and package media inventory | ✅ | ✅ | 🟡 | Package, inline, missing, and external image references are discovered; verified package/inline bytes can be read. The unified transaction can add, transfer, replace, and remove bounded inert package resources with explicit collision policy and atomically publish named or positioned image-frame references |
| Embedded objects and OLE-like payload inventory | 🟡 | ✅ | 🟡 | Package, linked, flat, and missing object sources can be classified as inert resources; payloads are not opened, executed, rendered, or semantically edited |
| Embedded charts | ✅ | ✅ | ✅ | `charts::{Snapshot, Edit, Commit, Patch}` and `MutableSpreadsheet::{chart_snapshot, edit_charts, apply_chart_patch}` provide exact-name/checked-position selection and replacement. The unified root can serialize a typed chart definition, create its manifest-backed subdocument and drawing occurrence atomically, or transfer a compact chart content root and every relative package dependency to a new object root. Publications require compact XML, typed readback, and reversible exact-source patches. Rendering remains outside this slice |
| Annotations/comments | ✅ | ✅ | ✅ | Shared annotation trees plus contextual `annotations::{Snapshot, Transaction, Commit, Patch}` provide bounded rich bodies, exact sheet/cell selection, source-preserving CRUD, and failure-atomic package publication; non-cell collaboration semantics remain outside ODS |
| Hyperlinks and external references | 🟡 | 🟡 | 🟡 | Typed ODF/XLink values and ODS source metadata preserve targets and activation hints; links are never followed, fetched, or refreshed |
| Forms and controls | 🟡 | 🟡 | 🟡 | Unified transactions replace the common scalar ODF button, check-box, radio, list-box, combo-box, text, image, date, time, fixed/formatted text, number, file, password, textarea, hidden, value-range, frame, image-frame, and generic-control families with checked bindings, optional package image dependencies, and inert event/macro metadata using compact provenance-spliced XML. Structured grids/columns and producer extensions remain outside the typed replacement scope; events and macros are never executed |
| Scripts, events, and macros | 🟡 | 🟡 | 🟡 | Script/event artifacts may remain inert package data; no script, macro, or event execution is performed |
| RDF metadata graphs | ✅ | ✅ | ✅ | `metadata_graphs::{Snapshot, Edit, Commit, Patch}` provides clone-staged graph/triple CRUD, checked triple positions, full package readback, compact authored XML, exact no-op retention, and reversible exact-source patches; `Spreadsheet` and `MutableSpreadsheet` retain concise compatibility verbs |
| ODF encryption | 🟡 | ✅ | 🟡 | `Spreadsheet::{open_with_password, from_bytes_with_password}` fully reopens password-encrypted ODS owners. `Snapshot::encrypt_to_bytes` provides bounded terminal compatible or authenticated encryption with password reopen evidence and explicit stale-signature stripping. Machine-readable capabilities distinguish available encryption, signed-source policy refusal, encrypted-source credential-owner refusal, decrypt credential requirements, and unsupported transactional re-encryption; encrypted archives are not editable unified snapshots |
| ODF digital signatures | 🟡 | 🟡 | 🟡 | Shared XMLDSig inspection remains available. Changed unified publications default to refusal and require `SignatureWritePolicy::StripInvalidated` to deliberately omit stale signature containers. Snapshot capabilities explicitly report signing/resigning as unsupported |
| Unknown package-part preservation | 🟡 | ✅ | 🟡 | Unified transactions retain unrelated members while supported owners and bounded resources are edited; explicit resource removal conservatively refuses paths referenced by retained XML. Preservation and transfer do not imply semantic understanding, relationship authoring, or execution of payloads |

## Spreadsheet data model

| Feature | Status | Read | Write | Notes |
|---------|--------|------|-------|-------|
| Sheets, rows, columns, and cells | ✅ | ✅ | ✅ | Public `worksheet::{Sheet, Row, Cell, Snapshot, Edit, Commit, Patch}` graph with logical lookup over physical repetition runs, exact-name/checked-position selection, clone-staged structure/cell CRUD, compact authored XML, typed readback, and exact-source reversible patches; `Builder` and `MutableSpreadsheet` retain concise authoring verbs |
| Positional existing-cell publication | 🟡 | ✅ | 🟡 | `SourceBackedSpreadsheet::{cell_snapshot,edit_cells}` and `SourceCell{Snapshot,Edit,Commit,Patch}` replace bounded existing ordinary scalar cells without materializing a complete package. Changed rows receive typed readback and `content.xml` is published to a sequential sink while untouched ZIP members are raw-copied. Repeated physical rows, formulas, merges, unknown values, style retargeting, protected owners, changed signatures, encryption, and unsupported row markup are refused. The patch is an in-memory semantic `content.xml` inverse, not a durable or byte-exact ZIP patch; atomic filesystem save remains outside this narrow path |
| Cross-document scalar worksheet transfer | 🟡 | ✅ | ✅ | `document::Edit::transfer_plain_scalar_sheet_from` copies one bounded dependency-free worksheet between immutable snapshots while preserving the source lexical table fragment apart from `table:name`. Only plain string/number/boolean/date/time cells, bounded repetitions, and direct text paragraphs are accepted; formulas, styles, ranges, merges, validation, drawings/charts/images, scripts/events, external references, unknown/MCE XML, security-sensitive input, and ambiguous destination names are refused. Destination patches retain exact source checks, durable inverse metadata, candidate reopen, and untouched-member preservation; no performance claim is made |
| Cell scalar types | ✅ | ✅ | ✅ | Typed string, number, boolean, date/time, percentage, currency, and unknown value tokens are validated and serialized without expanding repeats |
| Rich cell text, spans, whitespace, fields, and hyperlinks | 🟡 | 🟡 | 🟡 | `document::{RichText, RichRun}` authors bounded paragraphs, text spans, explicit spaces, tabs, line breaks, and inert safe hyperlinks in existing non-repeated cells through provenance splices. The ordinary worksheet projection remains collapsed plain text, and arbitrary fields/foreign inline markup are not structurally editable |
| Formula strings and references | ✅ | ✅ | ✅ | Public `codec::formula` recognizes all 393 ODF 1.4 Part 4 chapter-6 function names and tokenizes supported literals, A1 references, ranges, operators, and sheet references. Function calls take precedence over A1-shaped names; UTF-8 strings and doubled quotes retain their values; decoded literal storage is sized to its content and U+0000 is refused under Part 4 §5.4. The bounded `codec::formula::reference` reader represents ODF 1.4 Part 4 §5.8 source IRIs, whole-axis ranges, nested sheet locators, inheritance, absolute markers, and reference errors; external sources remain inert. Worksheet and unified transactions retain, set, or clear inert formula strings. Complete expression grammar, function arity, host-defined identifiers, and evaluation remain outside this tokenizer. [Catalog evidence](../../../docs/report/spec-gap-validation-evidence/ods-formula-functions/README.md), [reference evidence](../../../docs/report/spec-gap-validation-evidence/ods-formula-references/README.md), [literal validation](../../../docs/report/spec-gap-validation-evidence/ods-formula-string-performance/README.md) |
| OpenFormula expression syntax | ✅ | ✅ | N/A | `codec::formula::expression::Expression` parses ODF 1.4 Part 4 chapter 5 into a bounded immutable flat tree with source-preserving node views, precedence, arrays, missing parameters, names, labels, errors, and inert external references. Explicit byte/node/depth/array-cell/reference limits and fallible storage apply. It does not perform function arity/type validation, name/reference resolution, evaluation, or recalculation. [Grammar and measurement evidence](../../../docs/report/spec-gap-validation-evidence/ods-formula-expression-grammar/README.md). |
| Formula evaluation and recalculation | 🟡 | 🟡 | N/A | `evaluation::evaluate_scalar` provides the resolver-free constant scalar profile; `evaluation::value::evaluate` adds bounded local references, ordered reference lists, rectangular arrays, broadcasting, implicit intersection, and per-cell lazy `IF`/`IFERROR`/`IFNA`. Both profiles retain the implemented scalar operators, logical, bitwise, and number-representation families. Both implement the 24 trigonometric/hyperbolic and angle/constant functions from §6.16, with shared scalar and elementwise kernels, explicit domains, stable reciprocal hyperbolic tails and a finite binary64 numerical profile; see the [trigonometry evidence](../../../docs/report/spec-gap-validation-evidence/ods-formula-trigonometry/README.md). Both implement eleven elementary real functions (`ABS`, `EXP`, `LN`, `LOG`, `LOG10`, `MOD`, `POWER`, `QUOTIENT`, `SIGN`, `SQRT`, `SQRTPI`) with shared scalar/array/reference kernels, stable remainders and factored square roots; see the [elementary math profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-elementary-math/README.md). Both also implement the eight §6.17 rounding functions with scalar and elementwise array/reference evaluation; finite arithmetic, optional-argument semantics, and evidence are recorded in the [rounding profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-rounding/README.md). Both also implement `SUM`, `PRODUCT`, `SUMSQ`, `SUMPRODUCT`, `SUMX2MY2`, `SUMX2PY2`, and `SUMXMY2`, with streamed numeric sequences, equal-shape forced arrays, and bounded cancellation-preserving accumulation; conversion and numerical choices are recorded in the [aggregate profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-aggregates/contract.md). Both implement `COMBIN`, `COMBINA`, `FACT`, `FACTDOUBLE`, `GCD`, `LCM`, `MULTINOMIAL`, `EVEN`, `ODD`, `DELTA`, and `GESTEP`, using bounded exact integer intermediates and streamed sequence reducers; domain, conversion, fractional-sum, and representability choices are recorded in the [discrete math profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-discrete-math/contract.md). The value profile implements `SUMIF`, `SUMIFS`, `COUNTIF`, `COUNTIFS`, `AVERAGEIF`, and `AVERAGEIFS` over streamed cell references with compiled criteria and bounded exact sums/averages; reference geometry and host matching choices are recorded in the [conditional aggregate profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-conditional-aggregates/contract.md). The value profile also implements `COUNT`, `COUNTA`, `COUNTBLANK`, `AVERAGE`, `AVERAGEA`, `MIN`, `MAX`, `MINA`, and `MAXA`, with streamed reference reductions and exact averages; the resolver-free profile implements their scalar forms and retains the reference boundary for `COUNTBLANK`. Distinct coercion, error-counting, empty-value, and signed-zero rules are recorded in the [statistical reducer profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-statistical-reducers/contract.md). Both implement all 26 §6.8 complex functions with checked fixed-size Complex values, streamed reference aggregates, and owned results; conversion, principal-branch, and numerical policies are recorded in the [complex profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-complex-functions/implementation-profile.md). The value profile implements all twelve §6.9 database functions over bounded rectangular inputs, with borrowed criteria, lazy field reads, and stable numeric aggregates; selected host and conversion rules are documented in the [database profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-database-functions/implementation-profile.md), with performance acceptance still pending. The value profile also implements all five §6.5 matrix functions with finite work/storage/depth admission; numeric element conversion and numerical error choices are documented in the [matrix profile](../../../docs/report/spec-gap-validation-evidence/ods-formula-matrix-functions/implementation-profile.md). `worksheet::formula::Resolver` reuses a borrowed physical-run index with explicit finite grid dimensions; `Evaluated::to_owned` provides a separately budgeted lifetime-free result. Eight dispersion reducers (`VAR`, `VARA`, `VARP`, `VARPA`, `STDEV`, `STDEVA`, `STDEVP`, `STDEVPA`) share bounded scalar and streamed reference admission; sample/population cardinality, typed-value conversion, list admission, and numerical limits follow the [dispersion contract](../../../docs/report/spec-gap-validation-evidence/ods-formula-dispersion/contract.md). Formula caches are inert. Dependency recalculation, spilling/cache publication, names/labels, external sources, host services, and remaining function families are unsupported. This is not a complete ODF Small Group evaluator. [Public API example](../src/codec/formula/evaluation/value.rs), [current value/reference evidence](../../../docs/report/spec-gap-validation-evidence/ods-formula-array-reference-evaluation/README.md) |

## Explicit gaps from the audited feature families

| Feature family | Status | Read | Write | Notes |
|----------------|--------|------|-------|-------|
| Full public worksheet authoring | 🟡 | ✅ | ✅ | Bounded worksheet and unified transactions cover sheet/cell CRUD, row append/removal, column declaration append/removal, formulas/styles, and checked rich text. Repeated-run structural splitting, arbitrary column/row grouping, calculation, rendering, and the complete extension vocabulary remain outside this slice |
| Full OpenFormula semantics | 🟡 | 🟡 | ❌ | Chapter 5 expression syntax is separate from the compatibility tokenizer. The bounded scalar and local reference/array evaluation profiles are described above; they do not provide complete Part 4 function coverage, dependency recalculation, result spilling, volatile behavior, data-table execution, or host-service execution. Standard and host-defined calls, names, labels, and external workbook references can be parsed without resolving or executing them |
| XLSX slicers and timelines | ❌ | ❌ | ❌ | `[MS-XLSX]` ToC families for slicer caches, slicers, timelines, and their extension parts are OOXML features, not typed ODS support |
| XLSX PivotTable/data-model extensions | ❌ | ❌ | ❌ | OOXML PivotTable caches, OLAP/data-model structures, rich pivot data, pivot UI/version/auto-refresh extensions, and related XML parts are not implemented; ODF DataPilot metadata is not an equivalent claim |
| XLSX external data and code services | ❌ | ❌ | ❌ | Query tables, connections, database/model tables, external links, web/rich values, external code services, Python environments/scripts, and refresh behavior are not supported or executed |
| XLSX threaded comments and rich values | ❌ | ❌ | ❌ | The `[MS-XLSX]` threaded-comment, mentions, rich-value, property-bag, and web-image families have no ODS typed counterpart in this crate |
