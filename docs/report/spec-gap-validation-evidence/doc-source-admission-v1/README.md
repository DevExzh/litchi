# Common CFB and DOC source admission

Common object Editor::open consumes its input Vec, completes CFB/package/target admission, and retains that allocation. A uniquely owned unchanged finish returns it directly. APIs returning both the editor and parsed OleFile copy source only after common admission. DOC embedded-object snapshot retention follows DOC reference validation and makes one explicit slice-to-Arc copy. New OleFile reader accessors let an owner recover its input after validation without reparsing or copying it.

Whole-storage replacement can be prepared before cloning the outer DOC editor. Preparation enforces source size, protected-CFB policy, package capture bounds, and existing per-object stream/storage bounds. Token-owned target metadata is captured only after fallible replacement validation succeeds. Opaque prepared tokens bind source identity, target key/path, prior compound bytes, and limits. Changed publication remains atomic; no-op, stale, cross-editor, malformed, oversized, per-object-boundary, and replacement forward/inverse tests cover the handoff. A pointer/capacity regression verifies the consumed-Vec ownership contract through open and unchanged finish.

Root Rust 1.95.0 gates passed 1,701 unit/integration tests and 28 doctests, with three existing integration and thirteen doctest ignores, strict all-target/all-feature Clippy, formatting, and whitespace checks. Independent review cleared ownership, admission, token binding, metadata, and inverse behavior; root reviewed and retested the final deferred token-capture change. The receipt binds eight source files and compressed gate logs.

The original implementation batch made no measured performance claim. A preliminary allocation harness exercised tracked-revision snapshots and shared-source common finish; those workloads cannot establish results for the changed embedded-object snapshot or uniquely owned finish. [Corrected direct-owner allocation evidence](../doc-source-admission-allocation-v2/README.md) now records those workloads, with an independently audited supplemental run and a portable reproduction. It establishes no latency, RSS, or I/O improvement. Validation used the recorded c859 base; intervening XLSB, Survey, and OLEPS commits do not change these eight paths.
