# XLSB model-identity profile

This directory contains the source-backed XLSB table-name identity profile.
The committed requirements define the table/relationship matrix and sealed
evidence rules. The ordinary runner executes a bounded 11-lane smoke profile:
one process, zero warm-ups, and one retained sample for each lane, followed by
the complete correctness matrix using the same built binary. The matrix records
semantic and byte gates without collecting timings or allocator/RSS
measurements.
The exact-cap lane derives the generated workbook-stream size from an
unconstrained public commit, then checks an exact boundary and a one-byte-under
refusal on a fresh source.

The smoke corpus is generated by including the committed
crates/litchi-xlsb/tests/data_model_identity.rs complete XLDM 140 fixture
builder. The scaled generator in `harness/scaled_fixture.rs` expands the same
validated templates into the twelve T/R cases, two endpoint layouts, and five
name profiles. The correctness run currently records 110 accepted points and
10 explicit `limit_exceeded` refusals for the 64-table/256-relationship case,
where the public host graph-work ceiling is reached. This is correctness
evidence only; it does not measure scaling behavior and contains no native XLSB
Data Model acceptance evidence.
Successful matrix points retain complete forward member-hash manifests; the
verifier recomputes renamed semantic vectors and checks native, generated,
opaque, and unrelated member preservation independently of producer booleans.
The separate `OlapProofLimits::DEFAULT` receipt records `max_work=4_000_000`.
Graph-limit refusals explicitly mark full source proof as unavailable.
The refusal lanes retain the public error variant exactly as returned by the
host; this smoke currently observes InvalidFormat wrappers for both opaque
closure and rewrite-limit refusals, with the typed messages retained in each
receipt.

The smoke runner requires the host implementation commit
1b0d4864804d666aaf4ae5039bd6300996ca32a5 and the neutral XLDM baseline
4f53be2d31e14b215d6eeaee56d11eefeae94107. The sealed correctness smoke was
built from descendant commit 2a726ded6feb79f36b23980ed89c350aafd3cb55;
1b0d48648 is the host API anchor recorded in the corpus, while 2a726ded6 is
the source and build receipt commit. The source manifest and provenance
file bind the actual build inputs to a clean committed checkout. The isolated
harness uses its own committed `harness/Cargo.lock`; the repository root
lockfile is not an input. The committed toolchain file is included in the
manifest.

The historical `results/smoke/` and `results/smoke-fixed-6/` receipts are
retained as provisional evidence from pre-freeze scaffolds. A sealed rerun
must use a committed clean checkout: the source manifest compares every local
Cargo input and explicit harness input with its `git cat-file` blob at the
pinned commit, so staged, unstaged, untracked, and `assume-unchanged` edits are
refused. It also binds the exact Cargo metadata and profile binary hashes.
The runner writes a fresh result directory and refuses to reuse an existing
target or result directory.

Run from the repository root with:

    docs/report/spec-gap-validation-evidence/xlsb-model-identity-performance/run_smoke.sh

The script uses a private Cargo target directory, records source and toolchain
provenance, runs each timed lane in a fresh process, then runs the correctness
matrix with the same binary and retains its exact command, stdout, stderr, and
exit status. It invokes `verify.py` separately for the smoke receipts and the
matrix receipt. The timed 11-lane portion remains a bounded correctness check;
the matrix is also correctness-only and makes no performance claim.

Run the correctness matrix from the repository root with:

    cargo run --manifest-path docs/report/spec-gap-validation-evidence/xlsb-model-identity-performance/harness/Cargo.toml --locked --offline -- --matrix-correctness

The JSON receipt can be checked without accepting performance claims:

    python3 docs/report/spec-gap-validation-evidence/xlsb-model-identity-performance/verify.py --correctness-receipt matrix.json --manifest docs/report/spec-gap-validation-evidence/xlsb-model-identity-performance/corpus-manifest.json --root .

The checked-in `corpus-manifest.json` freezes the complete twelve-case
table/relationship catalog (`T=1,4,16,64` with the required `R` values), both
selected-table and distributed endpoint layouts, five name profiles, the
caller-limit field set, and the semantic identity fields required by receipts.
The harness emits that recipe metadata together with staged/candidate/output
byte boundaries. The matrix receipt explicitly sets `timings_collected=false`;
the clean-2a726ded6 receipts remain the sealed 11-lane smoke evidence.
