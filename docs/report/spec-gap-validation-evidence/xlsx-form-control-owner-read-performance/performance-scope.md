# XLSX form-control owner read performance scope

This candidate characterization measures commit `1ae5d7b4504a248ea24ac52cb2bdd1f08859ddd7` from an exact detached clean checkout. The parent worktree has unrelated in-progress scalar-write changes; none are used by this run. The harness uses a private Cargo target and temporary source/fixture work areas.

The measured public read paths are paired eager and source-backed worksheet ownership calls:

- package open (`Workbook::from_bytes` vs `SourceBackedWorkbook::from_read_at`);
- owner projection (`form_controls()`), including retained properties, shape/VML mirrors, read-set/source-version provenance, and diagnostics;
- warm single-position selection, full iteration plus position selection, and cheap collection/view clone;
- diagnostic projection on an admitted mirror-warning package;
- typed refusal on a representative unsupported graph edge.

The native corpus includes one-control and two-control packages. A deterministic admitted many-control package is generated by repeating a canonical worksheet control graph with fresh identities; it is labeled synthetic and is used only to characterize scaling of the accepted owner graph. Unsupported graph fixtures are not mixed into accepted workload timings: refusal cases are measured and reported separately.

Every accepted workload asserts eager/source semantic equality for control count/order, authored names, typed object tokens, shape identity, exact properties bytes, diagnostics, and owner profile. Source-backed results additionally assert a non-empty source version/read set and exact retained worksheet/drawing/VML/properties bytes. Refusal workloads assert both public facades return the same typed error class and do not publish a collection. These assertions run before timed repetitions.

Receipts retain elapsed latency, Linux RSS samples when available, global allocator requested-event bytes, live-byte delta, peak live bytes, source read calls/bytes/request sizes, source version/length calls, fixture/member hashes, compiler/toolchain/build provenance, exact source/harness locks, and repeated raw JSONL measurements. The fields are observations of this run; they are not a runtime baseline, speedup, or implementation-wide claim. No cold page-cache, save/rewrite, concurrency, decompression-isolation, or native Office claim is made.

Input preparation is asymmetric in the open lanes: eager timing includes a full input `Vec` copy, while source-backed preparation occurs outside timing. Global allocator instrumentation is enabled during every timing phase. The seven repetitions have no discarded warm-up and report medians without tail or uncertainty estimates. Retained-object “warm” queries are distinct from benchmark warm-up. These limitations preclude direct production-latency or eager/source open-efficiency conclusions.
