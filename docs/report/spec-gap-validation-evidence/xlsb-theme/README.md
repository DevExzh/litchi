# XLSB Theme part validation

This batch implements the workbook Theme owner from MS-XLSB §2.1.7.52,
which delegates to ISO/IEC 29500-1 §14.2.7 and DrawingML §20.1.4. The
implementation reuses `litchi-drawingml`; it adds no XLSX dependency.

## Supported scope

`Workbook::theme` reads a bounded, immutable Theme snapshot. The source-backed
accessor retains managed Theme bytes and exposes the same name, twelve color
slots, and major/minor font projection without loading image payloads.
`Snapshot::edit` supports detached changes; commits and inverse patches publish
atomically after source checks. `Workbook::edit_theme_owner` additionally
supports optional-part creation and removal. `WorkbookWriter::set_theme`
authors a custom typed Theme using schema-valid format-scheme defaults.

Theme inventory validates the unique Workbook owner, content type, internal
owner edge, package-wide inbound ownership, permitted Image relationships,
leaf image targets, and Strict/Transitional namespace profile. External images
remain inert. Removal preserves image resources; inverse publication restores
Theme XML and exact relationship/content-type source tokens, including the
presence of an empty physical `.rels` member. Stale lexical metadata is a
conflict. Changed signed sources require an explicit signature policy; no-op
publication preserves the source.

The typed API is a source-preserving projection. Format/effect styles, object
defaults, extra/custom schemes, extensions, and unsupported color/font fields
are not fully modeled. Unrelated XML survives edits; replacing a scheme with
unsupported content or foreign declarations is refused. The reader is not a
complete XSD validator and may admit schema-invalid structure outside its
projection. MCE preprocessing uses the shared hard ceiling rather than smaller
caller limits. Source XML, node/depth, namespace declarations, and generated
output have finite bounds. This batch does not provide rendering or resource
fetching.

## Verification

The frozen Rust 1.95.0 checks passed:

- 1,060 XLSB/DrawingML tests and 11 doctests; 12 existing ignores.
- Three PowerPoint Theme unit tests and two integration tests for the shared
  codec consumer.
- Strict all-feature/all-target Clippy, rustdoc with warnings denied, pinned
  formatting, and whitespace checks.
- Sixteen eager Theme integration tests, seven source-backed tests, and seven
  focused XML edit tests are included in the totals above.

The source-backed tests prove pre-I/O stale/cancellation refusal, declared byte
limit preflight, retained managed-view lifetime, independence from an invalid
unselected worksheet, and no image payload load with a 1 MiB image resource.
Lifecycle tests cover creation/removal/inverse, occupied part names, exact
physical metadata, empty relationship members, and stale atomic refusal.

[Library gate commands and logs](gates/commands.txt) record the exact source
hashes, toolchain, locked dependency graph, and unchanged source before/after.
The [final review](review.md) clears this bounded scope.

The [independent schema validator](verify-theme-schema.py) resolves imports
only from vendored ECMA archives through lxml. Both native XLSB themes, the
actual Rust-authored fixture, and four Rust-emitted edited XML fixtures pass
Transitional/Strict XSD validation. The edited fixtures are regenerated by the
gate runner; this is external schema evidence rather than a production claim
of complete schema validation. See [native results](native-schema-validation.json),
[authored results](authored-schema-validation.json), and
[edited results](generated-schema-validation.json).

## Measured behavior

The final matrix contains 54 fresh-process reports and 1,620 timed samples:
two native workbooks and a deterministic 1 MiB comment control, six API scopes,
three processes per scope, three warmups and 30 retained samples per process.
Both retained-view query lanes allocated zero bytes; source-backed warm queries
made zero additional observed `ReadAt` calls.

Median process p50 elapsed times in this allocator-instrumented run:

| Fixture | Source open + Theme read | Eager open + Theme read | No-op workflow | Change + inverse workflow |
| --- | ---: | ---: | ---: | ---: |
| `testVarious.xlsb` | 0.216 ms | 1.391 ms | 1.642 ms | 2.151 ms |
| `62815.xlsb` | 0.153 ms | 0.201 ms | 0.405 ms | 0.834 ms |
| 1 MiB comment control | 2.652 ms | 3.825 ms | 6.931 ms | 13.493 ms |

These lanes perform different validation and lifecycle work. The numbers are
scoped observations, not equivalent-work speedups or production latency.
Allocation values describe requested bytes; read counters describe logical
source calls, not RSS, cache misses, or physical storage I/O. The control
stresses raw XML retention, not a large typed font model.

[Profile methodology and reproduction](performance/README.md),
[environment](environment.json), and the [independent root receipt](root-verification.json)
retain scope and provenance. `verify-root.py` independently recomputes raw
statistics and allocation/read intervals, checks source/build hashes, and
compares native XML metadata and exact raw byte digests with the reports. Its
XML oracle covers the fields exercised by the warm query; it does not recreate
the complete typed encoder.
