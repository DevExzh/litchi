# 0711 — DOCX `alt::scan` ownership pilot rejected at the native gate

Status: rejected measured pilot. `performance_claim: none`. The candidate is
not retained and this record makes no production performance claim.

This pilot measured a source-compatible ownership change in
`litchi_docx::alt::codec::scan`: XML events and the namespace resolver were
borrowed for the existing scan iteration, while the existing validation,
relationship checks, source offsets, and typed errors remained in place. The
candidate source delta was limited to
[`crates/litchi-docx/src/alt/codec.rs`](../../crates/litchi-docx/src/alt/codec.rs).
The final checkout and `source-final.json` are byte-for-byte the baseline
source; the 0710 custom-properties correction remains retained.

The frozen native acceptance rule required at least 3% improvement in both p50
and mean edit time for each corpus in both paired windows. Lifecycle p50 and
mean could regress by at most 3%, and allocator allocation-request counts and
requested bytes could regress by at most 3%. The pilot passed output parity and
47 of 48 hard metric gates, but pair 2's `NumberedList` edit p50 improved only
2.888465327%. The candidate was rejected without retiming or lowering the
threshold.

## Correctness and mechanism evidence

The normalized deterministic output comparison passes for all 32 reports. It
retains scalar output hashes, decoded real-file manifest facts, phase identity,
edit outcomes, and deterministic corpus evidence while excluding only timing,
operation instrumentation, and repeated sample-vector cardinality. The strict
0711 differential oracle also produced byte-identical baseline and candidate
reports: each has 49 cases, 28 successful outcomes, and 21 typed errors. The
matrix includes the existing DOCTYPE event acceptance case; it was observed as
an acceptance, not reclassified as a refusal. The equal report SHA-256 is
`f222dcf20328c9ae05750cdcca2d3755a067f323503ac86ac819f420ba83b946`.

The oracle is a scanner differential for the public `litchi_docx::alt::scan`
API. It does not certify all DOCX preservation behavior or native Office
compatibility. No candidate cfg(test) run, candidate full quality suite,
conditional RSS capture, or candidate Callgrind run was executed at any point
in this pilot; the native rejection stopped those conditional follow-ups. The
historical attribution that selected this boundary is
kept separately: `alt::codec::scan` accounts for 3,714,595 inclusive Ir
(37.325609% of the generated document-body owner) on the generated corpus and
692,247 Ir (18.179624% of the admitted numbered-list document-body owner) on
the contrasting real corpus. The latter's larger historical child is
`active_block_ranges` at 69.938847%, so the attribution is not a universal
DOCX hotspot claim.

The candidate patch and source manifests remain in the packet for audit. The
production checkout was restored to the exact baseline source before cleanup;
the rejected candidate is not shipped. Owned scratch cleanup is complete, with
six exact binary/cleanup identity witnesses retained for post-cleanup custody.
