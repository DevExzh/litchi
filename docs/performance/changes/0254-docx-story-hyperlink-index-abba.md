# Change 0254: DOCX story-hyperlink planning index ABBA evidence

Date: 2026-08-22

Status: accepted for the scoped planning operation; no end-to-end or broad
DOCX performance claim is made

## Decision

Retain the independently audited release ABBA package recorded by
`fcb3104a5` as accepted evidence for the four p50/mean/p95/p99 statistics of
the opt-in `docx_story_hyperlink_plan` case. The candidate replaces per-selector
repeated story/relationship scans with immutable preindexed story ranges and
target ordering. Every reported statistic is favorable in both paired
directions, with reductions from 88.225897% through 91.592577%.

The claim is deliberately limited to eight repeated
`Snapshot::plan_target_urls` calls on a prepared immutable 49-story/1,152-link
snapshot. It does not cover DOCX open, package ingress, relationship discovery,
publication, output writing, filesystem or physical I/O, allocations, RSS,
resource usage, or general DOCX speed.

## Change and timed scope

The source-backed DOCX story-hyperlink snapshot now builds immutable indexes
when it captures the complete story inventory: ranges into the canonical
relationship list for each story and a URL-sorted order of relationship
positions. Planning uses those indexes for target membership and story-local
selection. This removes the old per-selector repeated scans while retaining
the same bounded selector handling, source lineage, and publication path.

The deterministic corpus is generated by
`litchi-docx-story-hyperlink-plan-v1` as a DOCX/OPC/ZIP archive with 49
reachable stories and 1,152 external hyperlink relationships (48 story Parts
with 24 links each plus the main story). Its archive is 47,677 bytes across
100 members, with archive SHA-256
`88aaed9b547d9af0079ad7685f7ba5a43f5b5df32254695ea2891d764065cb5f` and
canonical corpus SHA-256
`5a924ad4ffba528aef52724cbc463495f5272772b3970ada66e933ad70cbd439`.
The shared external hyperlink target entry is 41 bytes; the uncompressed
payload total is 101,960 bytes. All legs produced the same output SHA-256
`9d51dd76638bf230b40031e3948d1e3cdcef410d5be7c69fa0e572a782d2fd6e` and the
same source static projection SHA-256
`ef4b06efa1d7d9f02a83b4a2c0ab28cd762e974aa6613d31ff4353e0701a1b5b`.

The release protocol was pinned to CPU 0 in A1/B1/B2/A2 order, with 20
untimed warmups and 500 retained samples per leg, Rust 1.95.0, one visible
logical CPU, `CARGO_INCREMENTAL=0`, and one Cargo build job. Corpus creation,
source-backed inventory capture, selector preparation, one untimed semantic
publication/readback, one repeat publication for deterministic-output
comparison, and the output checks were outside the timed interval.
Each retained sample timed only the eight repeated planning calls on the
already-prepared immutable snapshot.

## Correctness gates and audit caveats

The retained reports set the complete inventory, inventory, plan effect,
duplicate-selector deduplication, missing-selector refusal, publication,
output-inventory, output-relationship, output-text, and deterministic-output
gates to true on every leg. The source archive, source static projection,
selected target, relationship inventory, and final output are identity-equal
across the four legs. These are correctness and identity gates around the
plan-only measurement; they do not broaden the timing claim to publication or
resource behavior.

`source_immutability_verified` is retained as a harness-reported flag, but is
not independent proof: the harness verifies its own generated corpus/source
path. The independently retained corpus, output, binary, and raw-report
hashes are the stronger identity evidence.

The generic `tools/perf_abba_summary.py` was incompatible with these committed
reports. The current helper requires `binary_identity`, which the reports from
the committed harness do not emit; the older control helper lacks the fixed
custom-corpus exception; and the DOCX source object includes `plan_ns`, which
is measured data rather than source identity. The summary is therefore a
fail-closed custom recomputation from the retained raw samples using the
harness's Rust p50, nearest-rank, and Welford rules. No measurement gate was
silently bypassed.

The package's full audit narrative and raw artifacts remain the authority for
the leg-level statistics, hashes, environment, and gate details. This
documentation-only record adds no Cargo or test run and makes no claim about
end-to-end latency, I/O, allocation, RSS, cold-cache behavior, real producers,
or general DOCX CRUD performance.

After artifact verification, the dedicated control/candidate worktrees,
staging directory, and approximately 1.4 GiB Cargo target were removed; the
repository's unrelated pre-existing dirty files were left untouched.
