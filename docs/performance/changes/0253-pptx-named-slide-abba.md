# Change 0253: PPTX named-slide selector ABBA evidence

Date: 2026-08-21

Status: rejected on latency evidence; the production candidate is not landed

## Decision

Do not land the PPTX named-slide production candidate from this run. None of
the 12 measured statistic cells is accepted. The tiny one-edit selector has
one adverse-both statistic (p99); both large repeated-edit selectors have
paired directions that disagree for every statistic. The candidate remains
available for a future run, but this package supports no latency or broad PPTX
performance claim.

## Protocol

The order was A1 control, B1 candidate, B2 candidate, A2 control, pinned with
`taskset -c 4`, with 30 warmups and 500 retained samples per result row.
Drift ceilings were 5%/5%/10%/15% for p50/mean/p95/p99. The release builds
and all measurements used Rust 1.95.0 on an AMD EPYC 9575F host with one
logical CPU visible to the process. Positive values below mean lower candidate
elapsed time; negative values mean the candidate was slower. All candidate and
control drift checks were within their declared ceilings.

## Tool-schema compatibility note

The current-main `tools/perf_abba_summary.py` was checked first, but rejected
the measured base reports with `a1.tool.binary must be a non-empty string`.
The unchanged base-197 harness schema does not emit the newer `tool.binary`
and `tool.instrumentation` fields. The clean base-compatible summary and
package tools from the measured candidate worktree were therefore used; they
validated the existing schema, exact configuration, corpus/target identity,
independent oracle output, and all report identities before packaging. This
was a tool compatibility issue, not a relaxed identity/oracle/schema gate; no
measurement gate was bypassed.

## Claim boundary and verification

This note covers only the fixed named-slide ABBA latency package. It makes no
claim about numeric-slide semantics, other PPTX shapes, physical I/O,
allocations, RSS, cold-cache behavior, real-world producers, or general PPTX
CRUD performance. In particular, the large numeric selector is retained as a
paired harness case over the same fixed named-slide corpus and does not create
a numeric-target claim.

Verification for this documentation-only update is package/hash inspection
and `git diff --check`; no Cargo command or benchmark is part of this commit.
