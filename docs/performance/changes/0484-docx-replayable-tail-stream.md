# 0484: replayable DOCX paragraph tail stream

The source-backed DOCX package now accepts borrowed plain-paragraph events
for logical append to an existing document. A deterministic source supplies
fresh cursors; a one-shot producer supplies an explicit replay store. Both
paths authenticate generated bytes and candidate semantics before sequential
publication, preserve untouched raw ZIP members, and retain typed resource,
cancellation, source-change and partial-output behavior. Compact durable
forward patches resolve authored replay through an explicit provider; durable
exact inverse uses an explicitly authorized original archive provider.

This is a correctness enabler for the separately required very-large authored
stream scenario. The [contract checkpoint](../results/change-0484/docx-stream-checkpoint.md)
records ownership, finite limits, supported plain-story grammar and refusal
boundaries. The [OPC foundation](../results/change-0484/opc-foundation.md)
provides authenticated replay splices and exact artifact restoration. The
[ADR matrix](../results/change-0484/adr-matrix.md) maps the architecture to its
accepted constraints.

Latest DOCX suites report 1,408 all-feature and 1,389 no-default-feature tests
passing, with 31 ignored in each. The sanitizer smoke first requires 27 known
valid seeds to complete, then runs two 10,000-input mutation rounds. Lint,
rustdoc, focused report-validator tests and scoped formatting also pass;
individual source manifests and the later formatting-only delta are described
in the checkpoint. Retained failed development attempts remain diagnostic
evidence. LibreOffice independently reads source/candidate fixtures generated
by the earlier debug harness; that evidence is scoped to those exact fixtures.

The deterministic harness measures source admission through publication and
operation-owned drops into a non-retaining hashing sink. It includes source
read distributions, authored event/cursor counts, output write distributions,
and separate normal/allocator instrumentation. Independent XML, semantic,
untouched-member and exact-inverse oracles validate each generated case.
The [measurement review](../results/change-0484/measurement-plan-review.md)
and [store extension plan](../results/change-0484/store-measurement-plan.md)
record the remaining work.

Formal captures, before/after comparisons, phase profiles, and storage/input/
sink/compression measurement arms are still required. No speedup, constant
memory, RSS reduction or concurrency improvement is claimed. The measured
0483 memory/latency tradeoff remains unchanged, and the full performance/CRUD
goal remains open.
