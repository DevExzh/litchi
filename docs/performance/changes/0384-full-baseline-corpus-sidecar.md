# Change 0384: full-baseline corpus sidecar binding

## Scope

The scheduled and manually dispatched full performance workflow now emits the
additive schema-2 corpus catalog beside its schema-1 benchmark report. The
catalog is uploaded in the same always-run artifact as the report, so a full
run retains the exact catalog/content-set hashes, corpus metadata, member
identity, case bindings, build provenance, and limit metadata generated by the
harness. The default smoke matrix and its non-claiming hosted-run policy are
unchanged.

The workflow invokes a standard-library-only validator before later matrices
run. Validation is fail-closed: duplicate JSON object keys, unexpected catalog
schema, unsupported canonicalization, malformed SHA-256 values, unsorted or
duplicate corpus/binding identities, unknown corpus references, catalog or
content-set hash drift, report/catalog corpus disagreement, incomplete or
extra timed bindings, and a mismatched report-side catalog reference all
reject the full job. The validator compares every schema-1 result corpus with
the catalog's retained legacy identity rather than trusting only the sidecar's
self-reported hashes.

## Verification

The focused validator, workflow-policy, and existing corpus-manifest suites
passed 27 tests. They cover a valid pair, recomputed semantic-hash tampering,
duplicate JSON keys, invalid result-case types, missing nested fields, binding
metadata drift, the checked 198-binding catalog, report-reference tampering,
the full-workflow command and validation step, artifact upload, path triggers,
and preservation of the smoke matrix. An end-to-end smoke used the actual
release Rust harness to emit one deterministic OPC result and its schema-2
catalog; the Python validator accepted exactly one corpus and one timed
binding. Python bytecode compilation and `git diff --check` passed.

This change strengthens artifact reproducibility and provenance. It does not
alter benchmark operations, sample counts, corpus bytes, production code, or
accept a hosted timing result.
