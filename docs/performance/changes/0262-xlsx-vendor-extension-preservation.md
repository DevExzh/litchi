# Change 0262: XLSX vendor-extension preservation corpus

## Status

Landed in `15a9f3a15`. This change adds an opt-in XLSX correctness corpus for
unknown, orphaned vendor Parts. It adds no latency, allocation, RSS,
throughput, decompression, or physical-I/O claim.

## Scope

`vendor-extension` is an explicit `XlsxCellCrudShape`, but it is deliberately
excluded from `XlsxCellCrudShape::ALL`. It is selected through the existing
`--xlsx-cell-crud-shape` CLI option and adds no `Case` entry. The selectable
case count therefore remains **381**, and the default matrix remains **36
cases / 198 records**.

The shape extends the existing deterministic cell-values corpus generated by
`litchi-xlsx-cell-values-source-edit-media-multi-sheet-v1`:

- four worksheets, each 48 by 48 cells, for 9,216 scalar cells;
- the existing eight deterministic media entries;
- an orphan `/xl/vendor/litchi-extension.xml` Part and
  `/xl/vendor/litchi-extension.bin` Part;
- one internal `/xl/vendor/_rels/litchi-extension.xml.rels` manifest linking
  the XML Part to the binary Part;
- exactly 20 ZIP members, 4,227,295 archive bytes, and
  4,231,356 logical uncompressed payload bytes;
- source archive SHA-256:
  `b031d236b0f48b45ab357126ff238a40e2a2e147c1471cf82e429ab6f6d250fb`.

The XML and binary payloads, vendor content types, relationship type, ID,
internal target, and target mode are deterministic. The vendor relationship is
not attached to the package root, workbook, or any selected worksheet; the
verification rejects any such relationship leak. The XML Part's one local
relationship is the only intended edge in this vendor topology.

## Correctness gates

The corpus is built twice and must have byte-identical archives. Reopening it
through `OpcPackage` and the typed XLSX owner checks the exact vendor payloads,
content types, relationship manifest, package topology, and 8-media corpus.
The existing source-backed cell-value lifecycle gates additionally cover exact
no-op bytes, clear/remove state, durable forward/inverse replay, stale and
foreign source refusal, deterministic output, semantic reopen, and source
immutability.

For a one-cell source-backed edit, all 19 untouched ZIP members—including the
orphan XML, binary, and relationship members—retain their raw local records
and central-directory records after normalizing each central record's local
offset. The focused one-sample output recorded the untouched-member digest
`ad609f5f1640cf544614b19cdfbdf671e30f6b8cb8eb40c7972891438f8cb395` and
semantic output digest `3cd21160d4f74fa0f097ab40be08e211b3e460cea788aa2b6705a55fdece07de`.
The managed source-backed variant retains the same preservation checks and
finite `PartData` cache Budget; its one-byte-under output replay requires a
typed refusal with zero accepted sink bytes. The vendor-specific positive
prefix replay requires a typed incomplete-output error after a non-empty
prefix.

Signed, protected, formula, markup-compatibility, macro, relationship, and
other unsupported/unknown-owner refusal behavior remains the existing
source-editor production contract; this generated shape does not broaden that
contract. The vendor-specific checks ensure that an accepted supported cell
edit cannot silently rewrite or re-root the unknown vendor Parts.

## Reproduction and verification

The shape can be inspected with the existing source-backed selector:

```sh
CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=1 \
  cargo run --manifest-path tools/perf-baseline/Cargo.toml \
  --bin litchi-perf-baseline -- \
  --case xlsx_source_backed_cell_values_one_edit_save \
  --xlsx-cell-crud-shape vendor-extension --warmup 0 --samples 1 \
  --json target/perf/xlsx-vendor-extension.json
```

The focused unit gate is
`xlsx_vendor_extension_cell_crud_shape_is_opt_in_and_preserved`.
The selector remains opt-in and its timer, when used, is ordinary cell-value
phase evidence only; this change registers no performance result.
