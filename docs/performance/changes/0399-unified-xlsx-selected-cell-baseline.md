# Change 0399: unified XLSX selected-cell filesystem baseline

Date: 2026-09-04

Status: opt-in candidate baseline implemented and validated. This change adds
no production optimization and no performance claim.

`performance_claim: none`

## Selector and corpus

0399 adds exactly one opt-in filesystem selector:

```text
xlsx_file_selected_cell
```

The selectable registry rises from **419** to **420**. The default matrix is
unchanged at **36 cases / 198 rows**. This is a descriptive candidate-only
baseline for the existing unified XLSX facade; it is not an A/B comparison or
CRUD-completion evidence.

The selector uses the pinned medium corpus generated by
`litchi-xlsx-cell-values-source-edit-media-multi-sheet-v1`: four worksheets of
48 rows by 48 columns, for 9,216 deterministic numeric cells; 17 ZIP members;
4,226,429 archive bytes; and archive SHA-256
`dfff7ec0c749d9e404091776f15a8fb690985af7f58efdfe659dbeaed7145036`.

## Fixed selected-cell oracle

The target deliberately exercises the second canonical worksheet and a
non-first cell:

| Field | Fixed value |
| --- | --- |
| Canonical sheet | `Bench01` |
| Zero-based sheet position | `1` |
| Prepared mixed-case selector | `bEnCh01` |
| Zero-based row / column | `28 / 12` |
| A1 address | `M29` |
| View and value kind | stored number |
| Stored lexical value | `1028012` |
| Selected-cell evidence digest | `36e53d9002ae8c433ad918b400196fb886fa675f850076808ac51327d1f42ac1` |

The selected-cell digest is a dedicated stable evidence field, computed from
the versioned `litchi-xlsx-file-selected-cell-v1` prefix, zero-based sheet
position, canonical sheet identity, prepared selector, address, view, value
kind, and lexical value. It is independent of the full-workbook semantic
digest.

## Timed boundary and evidence

Each sample runs in a fresh child process. `litchi::Workbook::open(path)` and
the mixed-case selector/address strings are prepared before the allocation
region and `Instant` start. The timer includes only case-insensitive
`Workbook::sheet` selection followed by the exact `SelectedWorksheet::cell`
read. Both the selected worksheet handle and owned selected-cell view remain
live through elapsed-time, allocation, and process-metric snapshots.

The full semantic projection, exact source hash, and independent eager typed
`litchi_xlsx::Workbook` selected-cell oracle run after timing. The oracle checks
canonical worksheet identity, zero-based position, exact address, stored
numeric state, and lexical value. Allocation and process metrics are
operation-scoped observations. Logical source counters are
`not_applicable_filesystem_xlsx`; the selector makes no physical-I/O or
locality claim.

Because the workbook and query are prepared before the timer, the selector is
explicitly ineligible for `cold-verified`; a cold-requested run is advisory
only and cannot establish a verified cold-query claim. No latency, allocation,
RSS, throughput, cache, physical-I/O, or generalization claim follows, and no
candidate/control speedup is authorized.
