# Change 0092: bounded validation and DOCX section-inventory evidence

This change adds six opt-in selectors to `tools/perf-baseline`:

- `rtf_validation_report`
- `xls_validation_report`
- `docx_validation_report`
- `docx_section_inventory`
- `pptx_validation_report`
- `odf_validation_report`

The selectors use deterministic corpora already generated by the harness. RTF
uses the plain semantic RTF corpus and validates borrowed bytes through
`ValidationReport::from_bytes`; the raw CP-1252 and LZFu variants are also
accepted. The producer-watermark fixture is intentionally excluded because
its opaque drawing surface yields an unknown safety status rather than a
complete terminal validation report. Generic ODF uses the semantic ODT corpus and
`litchi_odf_common::validate_package`. XLS uses the tiny/large writer corpora
through the public `ReadAt` validator. DOCX and PPTX use their generated
semantic corpora through the source-backed `ReadAt` validators. The DOCX
section case uses the same source-backed DOCX corpus and captures the hardened
section inventory, including exact ownership, paragraph ranges, page size and
margins, section start, and header/footer relationship references.

The default matrix remains 36 cases and 198 records. The `Case` enum now
exposes 190 selectable names, but these six selectors are not included in the
default set. No iWork crate or corpus is involved.

Timed scope is explicit. Corpus generation, source construction, report or
inventory canonicalization, hashing, and all verification gates are outside
the timed interval. RTF and generic ODF time only borrowed-byte validation.
XLS, DOCX, and PPTX time the public source-backed validator, including its
positional `ReadAt` requests; source setup is outside timing. The DOCX section
case times source-backed package open plus `section_inventory_snapshot`.

Every measured sample checks source SHA-256 before/after equality. Validation
summaries retain a canonical report hash, ordered check IDs and status classes,
issue codes/counts, completion/error flags, format counts, source bytes, and
ReadAt call/byte counters where available. The section summary retains the
complete descriptor list and exact section/paragraph counts. ReadAt counters
are recorded only for measured samples, not warmups, and the summary topology
must remain identical across samples. Borrowed-input cases explicitly report
no source-read counters. The focused warmup regression smoke report is an
ephemeral, untracked correctness artifact; its hash is intentionally not
treated as durable evidence.

Focused test and smoke commands:

```text
cargo test --locked --manifest-path tools/perf-baseline/Cargo.toml \
  bounded_validation_cases_exclude_warmups_and_preserve_topology
cargo run --locked --manifest-path tools/perf-baseline/Cargo.toml -- \
  --warmup 1 --samples 2 --semantic-shape tiny --writer-shape tiny \
  --rtf-variant plain \
  --case rtf_validation_report,xls_validation_report,docx_validation_report,\
docx_section_inventory,pptx_validation_report,odf_validation_report \
  --json target/perf/validation-sections-smoke.json
```

This is deterministic correctness/baseline evidence only. It makes no
latency, speedup, allocation, RSS, peak-memory, or materialization claim.
Any performance comparison requires a frozen release build, CPU-pinned
balanced ABBA ordering, retained raw samples, and independent allocation and
memory evidence.
