# 0909 — qualify the existing PPTX owning-input preservation control

The existing `Package::from_vec` route passes a bounded preservation control
on the exact 0907 media-rich multi-slide fixture. All 64 requested text edits
are verified. Only the eight selected slide members change; the remaining
**437 of 445 ZIP members** preserve their raw components, with central-directory
relocation offsets excluded from equality. Physical and central member order
and the archive comment are unchanged. The result qualifies this generated
fixture for a later owning-input benchmark; it is not a performance result or
a production optimization.

## What changed

A standalone [example](../../tools/perf-baseline/examples/pptx_owned_control.rs)
and private [harness module](../../tools/perf-baseline/src/pptx_owned_control.rs)
export the source, no-op, edited, inverse and forward-replay archives plus
machine-readable gates. A small library hook exposes the exporter. The CLI
selector registry and existing benchmark timers are unchanged. No production
library or dependency changes are adopted.

```sh
cargo run --manifest-path tools/perf-baseline/Cargo.toml \
  --release --example pptx_owned_control -- /path/to/new-pptx-control
```

The directory must be new. The probe clones the generated bytes into each
owning package and moves the clone into `from_vec`. All cloning, allocation,
opening, editing, patch replay, publication, disk output and verification are
untimed. The materialized ReadAt route is not rerun as a native comparison.
Historical 0907 identities are used only to bind the corpus and output.

## Ownership, patch and failure gates

Public OPC observations confirm exact owned-source authorization at ingress:
source length and digest match the fixture. An empty transaction and commit
preserve that authorization and the full archive. A changed commit revokes
the exact-output shortcut while retaining the admitted source archive's read
limits. Successful preservation publication follows; no new provenance API
or format-to-source-backed routing is introduced.

The semantic oracle checks requested and untouched text, slide topology,
relationships, content types, untouched logical Part payloads and all media.
The following additional gates pass:

* Live inverse restores the complete source archive; forward replay restores
  the complete edited archive.
* Forward and inverse patches each serialize to 60,953 bytes and round-trip
  through `Patch::from_bytes`. Fresh forward application matches the output.
  Applying the decoded inverse to an owning reopen of the edited archive
  restores the complete original bytes.
* A changed write-set resource and a foreign presentation both return
  `UnsafeEdit` for a stale patch resource, with the destination unchanged.
  This does not claim blanket rejection of every unrelated-resource change.
* A 17,017,139-byte input limit admits the source. A limit of 17,017,138 rejects
  it with the exact `ReadLimit` error with the `InputBytes` resource and actual/maximum values.
* A partial sink accepts exactly 8,508,572 bytes matching the successful output
  prefix and returns `OpcError::IncompleteOutput` with that count. A zero-byte
  sink returns the existing preservation writer's `OpcError::ZipError` mapping
  with the injected cause. Fresh publication remains byte-identical after
  both failures. The zero-byte error does not retain a typed `io::ErrorKind`.

Full archive equality to the already admitted source establishes resource
and semantic equality for these inverse results. It does not establish a
general raw-archive inverse contract for arbitrary producer files: the generic
opened patch stores resource deltas, not a raw source-archive witness.

## Independent physical census

The [independent Python helper](results/change-0909/zip-census.py) parses ZIP
framing and compressed ranges separately from Litchi and uses `zipfile` for
decoded readback. Four [census runs](results/change-0909/census-runs.json) compare
source to edited output, source to no-op, source to inverse, and edited output
to forward replay. The [reducer](results/change-0909/analysis.json) additionally
compares physical member order by sorting the raw local-header offsets.

Exactly the eight selected slide names differ in decoded payload, compressed
payload, data descriptor and central metadata. All other local headers, names,
extras, compressed payloads, descriptors, central metadata and member comments
match. Every comparison preserves both member orders and the archive comment.
The fixture uses data descriptors and no ZIP64. This exercises its generated
descriptor form, not malformed, boundary or general ZIP64 coverage. Nine
synthetic checker cases cover stored/Deflate comparisons, allowed edits,
untouched payload/metadata/order/comment refusals, and a 445-member archive
with metadata preceding slides.

Raw byte equality establishes an output property. It does not prove that the
writer skipped decompression, compression or copying, nor expose private
`Copy`/`Regenerate` decisions. A targeted profile and native benchmark remain
necessary before any cost claim or production provenance bridge.

## Retained corrections and validation

[Attempt history](results/change-0909/attempt-history.json) preserves all
initial failures. Build v1 needed an explicit collection type and the correct
`maximum` error field. Capture v2 passed output generation but failed a probe
assumption that zero-byte sink errors were `IoError`; the source maps these to
`ZipError`. The corrected gate is documented before v3 execution, with zero
accepted bytes, injected cause and retry invariants unchanged. No production
error behavior was modified.

The first census helper incorrectly treated semantic slide indexes as central
ZIP indexes. Review corrected it before the primary comparison, and the new
445-member regression checks that distinction. The first formatting check
lacked the repository's `rustfmt.toml`; the corrected check uses a retained
copy from the parent commit. Original helpers, source overlays, logs and
receipts remain available. Scoped formatting and warning-denied Clippy pass.

Independent review, exact source reconstruction, four census replays and
canonical reduction replay are retained. Cleanup removes the owned source and
build roots (1,539,086,302 logical bytes); no worktree was created. The generated
archives and two qualification binaries remain locally as explicit Gitignored
evidence, with tracked descriptors. A fresh clone must rebuild and regenerate
those artifacts before replay; this packet does not claim to embed them in Git.

## Scope and next step

This is a correctness-qualified generated-fixture control. It does not certify
unknown-member variants, signed/encrypted/malformed inputs, arbitrary physical
source variants, cancellation, allocation failures, producer round trips or
cold/range/concurrent performance. Existing production guarantees remain
required and broader `docs/GOAL.md` work remains open.

| ADR | Qualification boundary |
| --- | --- |
| 0003 | Existing transaction, atomic patch publication and inverse APIs; no changed semantics. |
| 0005 | Explicit owning input and caller sink; all work untimed, no inferred performance result. |
| 0006 | Raw and semantic preservation checked for the named fixture; broader cases remain unqualified. |
| 0011 / 0024 | Physical ZIP work stays in OPC/ZIP owners; no production dependency changes. |
| 0030 | Uses the existing owning facade; no new direct facade routing onto `SourceBackedPackage`. |

Next, add a comparable owning-input benchmark control with explicit input-copy
and production/replay boundaries, then measure it before proposing a bridge.
The present eager/source ratio must not be used to describe all owning-input
workflows. Target-branch integration remains pending the unrelated shared
iWork cherry-pick; ODF is deferred and iWork is excluded from this program lane.
