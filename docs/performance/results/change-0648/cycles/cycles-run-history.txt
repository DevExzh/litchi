Three perf stat windows were run for change 0648. All three are recorded here
because their cycle columns disagree where their instruction columns do not.

Windows 1 and 2 ran against earlier after-probe builds: window 1 before a
defensive edit to sst_region (a segment table reaching past the declared stream
now disables the window rather than being clamped into it), and window 2 before
the review fixes (an OOM on the window falls back to the per-entry path, a
checked_sub in place of a saturating_sub, and one cancellation check moved
earlier in the multi-segment branch). None of those can change what these
scenarios execute -- the corpus sweep and the allocation counts were re-run
against every build and are byte-identical -- but each changed the binary, so
each window was re-taken. WINDOW 3 is the retained one: it is the build whose
SHA-256 is in binaries.sha256, and its raw files are the perf-*.txt here.
