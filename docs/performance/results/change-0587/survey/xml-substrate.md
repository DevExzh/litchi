# Survey: XML substrate (litchi-ooxml-common, xml-minifier, litchi-drawingml, escaping, number lexing, writers)

HEAD 2fc5fc657, read-only. Scratch evidence: `$SCRATCH/agents/xml-substrate/EVIDENCE.md` (numbers), `cg-*.{inclusive,self}.txt` (callgrind tables), `xmlprobe/` (probe source), `strip_markers.py`. All fresh numbers below are **synthetic single-run callgrind Ir on one real fixture** (Excel_file_with_trash_item.xlsx, sheet1 209,931 B, 11,578 elements) versus a byte-identical control with only the `mc`/`x14ac` markers removed; they rank work, not latency.

## 1. Path map

- **One reader everywhere: quick-xml 0.41** (`memchr` feature only; workspace `Cargo.toml:159`). No hand-written tokenizer. Hot readers are `NsReader` loops: XLSX worksheet parser `raw/worksheet/codec.rs:273-297` (`check_end_names=true`, per-attribute `decoded_and_normalized_value(...).into_owned()` at `codec.rs:215-223`, attributes iterated with duplicate checks on), value-only validator `cell_values/validation.rs:224-232`, x14ac collector `raw/worksheet/x14ac.rs:508-552`, DOCX text `paragraph/codec/text.rs:86` and PPTX text `shape/text.rs:69` (both on the hand-rolled `BindingTracker`, `litchi-ooxml-common/src/binding_tracker.rs:85-286`, which stores bindings in one byte buffer and memmem-prefilters `xmlns`).
- **Two MCE implementations sit between the reader and every semantic parser.** (a) The *codec* `mce/codec.rs::process_markup_compatibility` (`codec.rs:529-`): naive `windows()` presence scan (`codec.rs:286-293`, `539-541`); if the MCE namespace string occurs anywhere it re-tokenizes the whole part with `Reader::read_event_into` and re-emits every byte into `BoundedOutput` (`codec.rs:551-`). Called from 47 litchi-xlsx, 19 litchi-docx, 34 litchi-pptx, 6 litchi-drawingml files; on the XLSX planning/eager path via `raw/worksheet/mod.rs:198,209`; on PPTX semantic text via `parts/slide.rs:812`; on DOCX source-backed reads via `source_backed.rs:748`. (b) The *semantic stream* `mce/stream.rs` used by the XLSX selected-cell scan (`raw/worksheet/selected.rs:20`, entered from `workbook/source.rs:829-841`): every Start/Empty builds an owned `ElementData` (qualified name `Vec`, expanded `Name{String,String}`, per attribute `qualified_name` Vec + `raw_value` Vec + `decoded_value` String + expanded `Name`, `stream.rs:2440-2497`), then `SemanticEvent::from_element` clones the expanded name again (`stream.rs:2557-2570`); `Namespaces::with_local` allocates an `Arc<NamespaceLayer>` only when declarations exist (`stream.rs:1485-1525`). `mce::model::Name` is a public type with owned `String`s (`mce/model.rs:13`).
- **Passes per worksheet.** Fallback planning (`raw::worksheet::parse`, `mod.rs:187-205`): memmem `dyDescent` → full x14ac `NsReader` pass (`x14ac.rs:508`) → codec (scan or full rewrite) → `from_utf8` of the (possibly rewritten) buffer → parser pass; preceded by the validator pass at `cell_values/snapshot.rs:392-393,449-451`. The fused validate+parse of 0546 (`validation.rs:198-221`, driver `codec.rs:1120-1172`) is admitted only by `source_stream_eligible` (`mod.rs:60-68`): no `mc` namespace, no `AlternateContent`, no `x14ac` namespace, no `dyDescent`, ≤8 MiB, UTF-8.
- **Selected-cell path**: the semantic stream always runs to EOF; ineligibility is only recorded (`selected.rs:1328-1332`) and published at EOF (`selected.rs:474-476`), after which the caller re-parses through the eager store (`source.rs:651-660,672-678`). `<cols>` marks `NotEligible(Styles)` (`selected.rs:650-651`).
- **Writers**: publication builds `Vec<u8>` by `extend_from_slice` (`raw/worksheet/edit/codec/snapshot/write/sheet_data.rs`), numbers are retained lexically (`sheet_data.rs:653-655`), attribute values via small `to_string()`s (`:327,420,451-471,512`), `escape_xml` (`litchi-core/src/xml/escape.rs:21`) always allocates one `String`. `ryu`/`itoa` appear only in `streaming.rs`, `sparklines.rs`, `page_breaks`; no `fast-float2`/`atoi_simd` on OOXML read paths (u32 metadata via `str::parse`, `codec.rs:225-238`). Every eager save regenerates and audits every part's `.rels` (`litchi-opc/src/pkgwriter.rs:147-158`) and byte-compares every XML part against the source (`package.rs:526-530`); the source-backed splice streams the shared auditor over the whole rewritten part (`source_backed/splice.rs:2127-`, `xml_splice.rs:786-800`).
- **xml-minifier**: `audit.rs` is the compactness/limits auditor (`verify_with_policy` `audit.rs:1300-1440`, per-tag checked attribute iteration `1504-1542` plus a second scalar tag scan `1573-1595`); macros are compile-time template minifiers, not on any runtime path. Runtime callers: OPC publication (`pkgwriter.rs:138-158,988`), splices, DOCX tail append.

## 2. Remaining opportunities (ranked)

### 2.1 The MCE codec re-declares every in-scope namespace on every element, expanding real-producer parts 14-17x — GOAL step 1 (and 2)
- **Mechanism.** `write_start` (`mce/codec.rs:1145-1194`) calls `ctx.ns.for_each_effective` (`codec.rs:361-372`) and emits *all* effective bindings on *every* emitted start tag, including the MCE namespace itself; attribute values and URIs are re-escaped char-by-char through `esc` (`codec.rs:1196-1212`) into `BoundedOutput`, whose `reserve` grows by `try_reserve_exact(additional)` (`codec.rs:486-497`) and whose `raw` attribute vector grows one element at a time (`codec.rs:657-662`); `expand` allocates a `Name` per attribute (`codec.rs:1178`). Fix: emit only the element's own declarations (hoisting a wrapper's declarations onto the first emitted child when an `mc:Choice`/`AlternateContent` wrapper is unwrapped), copy unchanged start-tag byte spans verbatim, amortized output growth, borrowed names.
- **Measured** (`EVIDENCE.md`). Codec alone on the real sheet: 209,931 → 3,540,261 B (16.9x; 46,312 `xmlns` in output vs 4 in input), 841.8M Ir = 4,008 Ir/input byte, `esc` 687.4M (81.7%), 2,833,883 `extend_from_slice` calls, 2,954,106 `__rust_realloc` calls (38.8%); control: borrowed, 4.66M Ir. Public eager open + one cell: **1,037.8M Ir real vs 80.5M control (12.9x)**, codec 849.5M (81.9%), and the parser then parses the expanded stream (152.6M vs 59.4M). Source-backed read of the same cell: 1,075.5M vs 221.1M. Word 2013 `document.xml` (31 root namespaces): 3,108 → 50,987 B (16.4x); PPTX slide: 27,582 → 385,997 B (14.0x). Breadth: 41 of 60 fixtures' `sheet1.xml` declare `mc` (scratch loop; Excel writes `mc:Ignorable="x14ac ..."` by default).
- **Record status.** None found: grep for `process_markup_compatibility`, `BoundedOutput`, `reserve_exact`, `for_each_effective` in the record set yields only the presence-scan work (0530 identified the scan at 5.18% of planning, 0531 rejected memmem for it) and 0032, which explicitly notes the generated benchmark worksheets contain neither `dyDescent` nor MCE markup. The rewrite path has no retained profile.
- **Scenarios.** Read/snapshot (open valid input, real producer), opened-document CRUD (every XLSX planning/edit route through `raw::worksheet::parse`), PPTX semantic text (`pptx_file_*_selected_slide`, `pptx_drawingml_extract`), DOCX source-backed reads; also the "Unknown data is bounded" row, because output limits are applied to the self-inflicted expansion (see 4).
- **Constraints/risk.** Read-side transform only (the processed stream is not published — to be confirmed in the design record; if any writer publishes it, the CRUD "Compact XML output" row is violated today). Namespace scoping when unwrapping `AlternateContent` must stay exact: medium risk, differential tests against the current output modulo redundant declarations. Frozen design record required; no ADR change. **Falsified if** a corpus of real Excel/Word/PowerPoint parts shows the rewrite path taken on <5% of opens, or if a native ABBA on such a corpus moves <2%; the fixture breadth above makes the first unlikely.

### 2.2 The selected-cell stream keeps streaming after the worksheet is known ineligible, then the eager store re-parses everything — step 1
- **Mechanism.** `mark()` only records the reason (`selected.rs:1328`); the scan continues to EOF and the caller falls back to `store()` (`source.rs:672-678`). A `<cols>` element (which precedes `sheetData`) marks `NotEligible(Styles)` at `selected.rs:650-651`. Fix: pre-gate with memmem (`<cols`, row `s=`/`customFormat`, merges...) before opening the stream, or stop at the first mark. Mandatory validation (ADR 0005) is still performed in full by the fallback parser; what changes is which typed error is reported for inputs malformed after the mark, so a 0541-style error-identity guard is needed.
- **Measured.** Control fixture, source-backed read of H680: selected stream 140.7M Ir (63.6%; `Processor::start` 101.5M) then `eager_cell` → `store` 76.5M (34.4%); neither dependency streamer ran (`cg-source-control.*`). On the real fixture the fallback also pays 2.1 and the x14ac pass: 1,075.5M total. Breadth: 27 of 60 fixtures' `sheet1.xml` contain `<cols>`, 8 have row styles.
- **Record status.** 0362/0363/0365 designed EOF-only publication and mandatory fallback ("deliberately narrow" subset, 0362 §Residual scope); 0574 opp 6 rejected an early exit that would have *skipped* validation (XLS), which this does not. No record measures the ineligible case.
- **Scenarios.** `xlsx_file_selected_cell`, `xlsx_range_source_first_cell`, `xlsx_narrow_column_range_scan` on real producer files. Risk low-medium; frozen design record (error-order guard) required. **Falsified if** the stream's post-mark share on ineligible real worksheets is <10% of the read, or if most real worksheets are eligible (they are not: 27/60 ineligible on `<cols>` alone).

### 2.3 The fused planning traversal (0546) excludes every real Excel worksheet — step 1
- **Mechanism.** `source_stream_eligible` refuses any part containing the `mc` namespace, `AlternateContent`, `x14ac`, or `dyDescent` (`mod.rs:60-68`); such parts take the four-pass fallback (validator + x14ac collector + codec rewrite + parser, plus `from_utf8` of the expanded buffer). Extending admission to `x14ac`-only and namespace-only `mc` declarations (the observer for x14ac already exists: 0361) lets the 0546 fusion (−21.8 to −22.4% planning Ir, −24.8 to −26.5% planning p50 on the generated corpus) apply to producer files; with 2.1 fixed the codec pass becomes a scan. Dropping `x14ac:dyDescent` attributes (ignorable, not understood by `Capabilities::ooxml_baseline`, `mce/model.rs:38-60`) must remain semantically neutral for the validator (`validation.rs:459`).
- **Size.** Modelled from 2.1's eager numbers (x14ac collector 26.6M = 2.6% even on the expanded path; 0032 priced `capture_inner` at 4.46% exclusive) and 0540 (validator and parser each ~13.7M/27.5M `read_event_impl` Ir on the generated corpus, i.e. the two passes are equal). Breadth: only 19/60 fixtures pass all gates.
- **Record status.** 0546 (gate as landed), 0032 (corpus lacks markers), 0540-0545 (fallback and "historical x14ac retry" preserved). Risk medium (error precedence, 0541 guards). Frozen design record required. **Falsified if** a marker-bearing planning row shows the fused path <5% better than the fallback once 2.1 has landed.

### 2.4 Owned expanded names in the MCE semantic stream — step 2
- **Mechanism.** Per element and attribute the stream clones names into `String`s twice (`stream.rs:2455-2497`, `2557-2570`, `3187-3212`) although consumers only compare them (`selected.rs:1377-1394`). Borrowed or interned `Name<'a>` (namespace as an index into the `NamespaceLayer`, local name as a byte range) removes the clones; `Name` is public, so this is an API-shaped change.
- **Size.** 0409/0410 retained profiles: `clone_bounded_name_part` 16.2% → 10.9% of selected leaf weight after 0410, `Processor::start` 10.4%, `with_local` 3.6%, drop glue 5.0%. Fresh control run: `clone_bounded_name_part` 16.4M = 7.4% of the whole read; the stream costs 12,150 Ir/element vs 5,160 for the raw `NsReader` parser on the same bytes.
- **Record status.** 0409 (identified "lexical borrowed ElementData"), 0410 (partial, −3.9/−4.1% p50), 0539/0527 (allocation-count wins that failed native gates — the warning for this candidate). Risk medium; frozen design record. **Falsified if** native ABBA on `xlsx_file_selected_cell` moves <2% after 2.2 (which removes the stream from most real reads anyway; rank accordingly).

### 2.5 Publication audits proportional to the package, not the touched closure — step 1
- **Mechanism.** Eager save regenerates and audits every part's relationships (`pkgwriter.rs:147-158`) and byte-compares every XML blob (`package.rs:526-530`); the source-backed splice streams the auditor over the whole rewritten part. A source-version-keyed compactness proof for the untouched prefix/suffix plus a fragment audit would bound the audit to the changed window.
- **Size.** 0528: OPC overlay XML validation 56.2% of publication Ir, attribute inspection 11.6%; publication ≈31% of edit/save time.
- **Record status.** 0528 (owner), 0529 (attribute probe rejected under native gates), 0517/0519 (proof reuse for the topology path only), 0482 (streaming auditor). 0528 states both audits must stay, so a proof-composition argument needs an ADR proposal; risk high. **Falsified if** boundary conditions (`xml:space`, whitespace runs across the splice) cannot be proven without re-auditing the part.

### 2.6 DOCX sink text path copies every event twice — step 2
- `write_text_to_with_operation_check` reads with `read_event_into(&mut buffer)` and then `event.into_owned()` (`paragraph/codec/text.rs:472-476`) although the source is a byte slice; the sibling `for_each_word_text_chunk` borrows (0229). Size unknown (no retained profile of `write_text_to`; `Document::text()` uses the borrowing path, `document/package/model.rs:47`). Low risk, no record covers it. **Falsified if** the sink path's copies are <3% of `docx_file_source_full_text`-style sink runs.

## 3. Looks like an opportunity but is not

- **`memchr::memmem` for the codec presence scan** (`codec.rs:286-293`): rejected in 0531 (−0.89% total p50, gate 1%). The fresh control shows it is 17.2% of an eager open+cell (13.85M/80.5M Ir), a different denominator, but it is subsumed by 2.1 (the scan disappears when the scan result of `source_stream_eligible` is reused), so do not re-propose standalone.
- **Borrowing attribute decoding in the raw parser** (`codec.rs:215-223`): 0537 sized it, 0539 rejected it (allocation calls −13.7%, bytes −0.3%, native gates failed).
- **Row arena / span layout**: 0527 rejected; **attribute probe in the auditor**: 0529 rejected; **event preflight / exact-bound scanner**: 0544/0545 rejected (0545: the inner loop is scalar, auto-vectorization is not evidence).
- **Lazy `.rels` reads** and **early exit from mandatory validation**: refused on ADR 0005/0006 (0577, 0574 opp 6).
- **SIMD (Workstream G).** No retained profile shows escaping, UTF-8 validation or delimiter scanning hot: quick-xml already dispatches `memchr2/3` AVX2 (0540 rows: memchr3 6.7M of 27.5M `read_event_impl` inclusive, i.e. <5% of planning); `from_utf8` is 1.7% of the eager control; `escape_xml`/`esc` are hot only because of 2.1's expansion. Number lexing is not on OOXML hot paths (lexical retention). UTF-16 conversion belongs to the OLE2 survey. Auto-vectorization status of `escape_xml`: unknown, not checked.
- **PPTX text `unescape` after `xml_content`** (`shape/text.rs:164-171`): redundant scan since quick-xml 0.38 splits references into `GeneralRef`, but both are `Cow`-borrowed on the common path; no allocation to remove.
- **`escape_xml` always allocating** (`escape.rs:21-28`): per changed cell only; publication is dominated by the auditor and physical writer (0528).
- **xml-minifier macros**: compile-time; not a runtime cost.

## 4. Measurement blockers and defects noticed

- **The harness corpus cannot exercise the substrate's real-producer path.** Generated worksheets (`tools/perf-baseline/src/lib.rs:17784`, streaming writer) contain no `mc`, `x14ac`, `dyDescent` or `<cols>`; the "vendor-extension" shape adds an unknown package part, not worksheet markup; no `--xlsx-file`-style option exists. Every planning record (0530-0546) and the selected-cell records measured the marker-free fast paths; 0032 says so explicitly. Real fixtures with markers are all small (largest `sheet1.xml` with `dyDescent`: 210 KB), so latency A/A on them will be noisy; Ir is the usable metric until a large real-producer fixture is added.
- **No retained DOCX/PPTX read profile on producer files**; the DOCX/PPTX expansion numbers above are codec-only.
- **Correctness/limits defect (report only).** Output limits are enforced on the codec's self-expanded stream: `Limits::default().max_output_bytes` (512 MiB, `mce/model.rs:133`), litchi-pptx `MAX_SEMANTIC_TEXT_PROCESSED_XML_BYTES` (`parts/slide.rs:812-815`), litchi-docx `mce_limit` (`source_backed.rs:748-752`), and the XLSX `within_mce_limits` gate (`mod.rs:70-73`). With 14-17x expansion a legitimately sized part (a ~30 MB worksheet, a slide or document with dozens of root namespaces) can be refused as "output bytes" although nothing in it is oversized. Also the codec re-declares `xmlns:mc` itself in its output.
- **Eligibility gates depend on substring presence anywhere** (`mod.rs:60-68`, `x14ac.rs:644`): a comment or string containing "dyDescent" disables the fused path (documented as conservative in 0032/0544).
- Scratch state after cleanup: 196 KB (probe source, extracted tables, two 47 KB fixture copies); the 805 MB build tree and XML dumps were deleted.
