## 1. Path map

**Ordinary documented save (Path A, eager), all three formats.** `docs/OFFICE_API_GUIDE.md:146/426/568` → docx `Package::save` `crates/litchi-docx/src/package/codec.rs:517` → `atomic::replace_with` `:532` → `write_plain` `:697`; xlsx `Workbook::save` `crates/litchi-xlsx/src/workbook/model.rs:952` → `writer::save` `crates/litchi-xlsx/src/writer.rs:33`; pptx `Package::save` `crates/litchi-pptx/src/package/codec.rs:287` → `flush_presentation` `:352` → `PackageWriter::write` `crates/litchi-opc/src/pkgwriter.rs:884`. All end in `atomic::replace_with_impl` `crates/litchi-opc/src/atomic.rs:48-93`: tempfile in the destination directory, the writer closure receives a bare `&mut File` (no `BufWriter` anywhere on the path), `set_permissions`, `sync_all`, `persist` (rename), directory `sync_all` (`:111`).

**Semantic → package step (whole-document-proportional).** docx `write_plain` regenerates `document.xml` plus every model-owned part (headers, footers, footnotes, endnotes, images) whenever the single whole-model flag `is_modified` (`crates/litchi-docx/src/writer/doc/model.rs:737`) is set. pptx `materialize_presentation` `codec.rs:395` removes every `/ppt/slides/*` and notes part and regenerates all of them from the mutable model (`slide.generate_slide_xml_with`) although `MutableSlide::is_modified` exists per slide (`crates/litchi-pptx/src/writer/slide.rs:382`); it first clones the whole OPC graph (`codec.rs:368`, Arc-shared blobs). xlsx `Edit::commit` (`crates/litchi-xlsx/src/workbook/edit/semantic/transaction.rs:1023`, `set_blob_shared` `:2505`) rewrites only touched parts — measured: 2 of 44 members for a three-cell edit, 1 of 132 for a tab hide.

**`PackageWriter::write_counted` `pkgwriter.rs:922`.** Unedited package: exact-source stream in 64 KiB chunks, zero allocations (0581 axis 3). Otherwise: signature policy check; `PublicationPlan::from_package` `:110-168` collects and sorts every part, rebuilds `[Content_Types].xml` from all parts and XML-audits it (`:139-140`), reserializes `_rels/.rels` and audits it (`:146-147`), audits changed XML parts (unchanged ones exempt via `is_exact_source_xml` `package.rs:526`, a full memcmp against the same Arc), and for every part with relationships reserializes its `.rels` (`try_to_xml_bytes`) and audits it (`:151-160`) — regardless of whether the relationships changed. `try_write_preserved` `:189-706` re-parses the resident source (`ZipArchive::from_slice` `:196`), allocates a 64 KiB buffer, rebuilds `PreservationIndex` (validates all central records and every local header, `:203-208`; deferred here from open by 0313), builds member-count-proportional hash maps, then decides per member: part blob byte-compare against the provenance Arc (`:552-553`, same allocation when untouched, no `ptr_eq` shortcut), `.rels` byte-compare against `CanonicalRelationshipsXml` captured at open (`package.rs:1285`), content types compared per part (`:519-525`). Unchanged → `PreservationAction::Copy`; changed → `regenerated_shared_action` (Arc borrow, no copy). Fallback to the full `PhysPkgWriter` only for non-preservable topologies (owned sources refuse instead, `:1005`).

**ZIP emission `crates/soapberry-zip/src/preserve.rs`.** `write_to_with_accounting` `:766` → `prepare`: each regenerated member is compressed *fully into a Vec* sized `payload + payload/8 + 2·name + 4 KiB` through a one-entry `ZipArchiveWriter` and a **fresh** `DeflateEncoder::new(.., Compression::default())` (`:2167`, level 6, zlib-rs backend), then the mini-archive is re-parsed to locate framing (`:2181-2226`) and retained as one Arc. Sizes are therefore known before any byte is emitted (ADR 0005:39-41 satisfied by planning, not spooling); all regenerated members' compressed bytes are resident simultaneously. Copies stream through a 64 KiB stack buffer (`copy_range` `:2374`, `COPY_CHUNK_SIZE` `:31`): one memcpy from the resident source per chunk. Central records are written one small write each (`write_prepared_central` `:1195`). Locks: none on the save path. Validation repeated per save: 42 `verify_authored` calls on the 132-member fixture (see below), the ZIP structural proof, `is_signed`.

## 2. Remaining opportunities (ranked)

### 2.1 Pristine-member proof reuse in the publication plan (GOAL step 1)
**Mechanism.** For every part whose relationships are unchanged, the plan reserializes the `.rels` XML, XML-audits it, and then *discards it*: `try_write_preserved` byte-compares it with the open-time canonical form and raw-copies the source member. The same happens to `[Content_Types].xml` when `content_types_changed` is false, and the part-blob compare memcmps an Arc against itself. None of the audited bytes reach the output on the Copy path, so the audits validate nothing. Add a revision counter to `Relationships` (private fields `rel.rs:218-224`; 4 public + 2 crate `&mut self` methods, plus `rels_mut` on `Part`), record it in `SourcePart` at open, and when unchanged skip `try_to_xml_bytes`/`verify_authored` and take `Copy` directly (keep the byte-compare as the fallback for replaced parts); compute `content_types_changed` from provenance *before* building and auditing the content-types XML; use `Arc::ptr_eq` before the blob memcmp. **Code:** `pkgwriter.rs:139-160, 519-525, 552-553, 566-575`; `package.rs:1284-1285`. **Records:** 0519 exempts unchanged XML *parts* only; 0489/0517 concern the splice route; 0008 designed "build and audit the normal plan first"; grep for unchanged-relationship reuse, `CanonicalRelationshipsXml` (0313, 0581 only): none found. **Size (measured):** on the 132-member hide save, 40 of the 42 audits and all 41 reserializations are for unchanged members: ≈0.95 M + 0.50 M + 0.22 M + 0.06 M ≈ 1.7-1.9 M Ir = **32-36% of the save**, ≈4.5-5% of the whole operation; proportionally larger on PPTX (one `.rels` per slide/layout/master), smaller on single-rels DOCX. Open-side `CanonicalRelationshipsXml` capture (529,644 Ir, 40 calls) is a second, related whole-package cost. **Scenarios:** every opened-document CRUD update/save (checklist "Opened-document CRUD"), unchanged-member preservation; harness: none for Path A (see §4). **Constraints/risk:** low; ADR 0006 unaffected (audited bytes never published); ADR 0005:341-348 planning-evidence rule unchanged; no ADR needed. **Falsified if:** an A/B on the 132-member fixture shows <2% save-Ir reduction, or the plan's serialization is needed for the `PhysPkgWriter` fallback more often than provenance predicts.

### 2.2 Buffer the temporary file inside `atomic::replace` (GOAL step 2)
**Mechanism.** The preservation writer issues one `write` per local header, payload chunk, descriptor and central record into an unbuffered `File`: measured **531 syscalls** for a 654 KB output (≈4 per member); a 64 KiB `BufWriter` between `Counted` and the tempfile reduces that to ≈11, and to 1-2 for typical DOCX. Wrap only inside `atomic::replace_with_impl` (`atomic.rs:75`) so caller-supplied `to_stream` sinks keep exact `IncompleteOutput.written` accounting; on failure the tempfile is discarded, so the over-report is harmless there. **Code:** `atomic.rs:68-93`, `pkgwriter.rs:25-38` (`Chunked` caps writes at 64 KiB), `preserve.rs:2310-2345, 1195-1260`. **Records:** none — `BufWriter` appears only in 0502 (ODG); 0490 counted 3,205 writes per child on the source-backed tiny route but attributed medians to `fdatasync` and did not evaluate buffering. **Size:** modelled 0.8-1.6 ms per 132-member save at 1.5-3 µs per page-cache write, against ≈1-2 ms of save CPU; the two fsyncs (0490: 79-82% of tiny-route time on a real store) are unchanged. **Scenarios:** every `save(path)` in every OOXML format, both create and update. **Risk:** low; durability/atomicity unchanged. **Falsified if:** `strace -c`/`perf trace` shows write syscall time <5% of save wall time on the target file store after fsync.

### 2.3 PPTX eager save regenerates every slide (GOAL step 1)
**Mechanism.** `materialize_presentation` (`crates/litchi-pptx/src/package/codec.rs:395-470`) deletes all slide and notes parts and regenerates, audits and deflates all of them for any modification, renumbering `slideN.xml`; per-slide `is_modified` (`writer/slide.rs:382`) is ignored. Retaining unmodified slides' source parts (Copy) requires keeping their names/rIds — a design change in the mutable model, not the writer. **Records:** none (grep `materialize_presentation`, slide regeneration); 0475/0478 cover the streaming writer; 0158 additive topology (source-backed). **Size:** unmeasured — no example opens a real deck and edits through the presentation model; modelled as N slides × (serialize + audit + zlib init + deflate) versus 1. **Scenarios:** PPTX opened-document update/save; exact no-op is unaffected (exact-source path). **Risk:** medium-high (lossy model fidelity, relationship renumbering); needs a frozen design record; belongs jointly to the docx-pptx area.

### 2.4 Fresh deflate state per regenerated member in the preservation writer (GOAL step 2)
**Mechanism.** `preserve.rs:2167` constructs a new `DeflateEncoder` (zlib-rs state + buffers) per regenerated member; 0476's reuse (`OwnedDeflateState` `writer.rs:2431`) covers only the owned writer. **Size (measured):** on a 3.8 KB member the deflate side is ≈1.6 M Ir (init/flush dominate); modelled 0.3-1 M Ir plus one ~300 KB allocation per extra regenerated member — matters for DOCX saves that regenerate headers/footers/footnotes and for §2.3 until it lands. **Records:** 0476 (owned writer only). **Risk:** low; output bytes identical if the reset semantics match 0476's. **Falsified if:** an A/B on a 5-member regeneration shows <2% save-Ir change.

### 2.5 Lazy part decode behind the fallible package accessors ("C2′"), and the C2/C3 question (GOAL step 2)
0581's C2 (fallible `Part::blob`) costs 1,049 call sites; C3 (route to `SourceBackedPackage`) needs a general save that does not exist (45 per-editor entry points, 64-part ceilings) and would add the ADR 0003:33-34 typed readback that Path A does not pay today. A narrower C2 shape: decode on first access inside `OpcPackage::get_part`/`get_part_mut`/`main_document_part` (already `Result`), add `try_iter_parts`, and let `PublicationPlan` treat never-decoded parts as pristine (`Copy` without decoding) — the plan is the one consumer that touches every part (`pkgwriter.rs:119`). Migration surface: 289 `iter_parts()` sites instead of 1,049 `.blob()` sites. Retention prediction stays 0581's C2 column (3.58× corpus, 2× media-heavy); the save-side gain is the elimination of the 131 blob memcmps and, with C2′, of decompressing untouched parts at open (`load_parts_eager` = 49% of the hide operation here). **Records:** 0581 (C1 refused, C2/C3 frozen with gates 1-6). **Constraints:** proposed ADR required (gate 1); limits `PartBytes`/`TotalPartBytes` must still refuse at open (gate 2) — declared central-directory sizes can be charged at open with a decode-time recheck, which is a reviewed relocation. **Recommendation:** C2′ first; C3 remains the end state. **Risk:** medium.

### 2.6 Compression policy and bounded parallel deflate for regenerated members (GOAL steps 2/5)
Level is fixed at `Compression::default()` (`preserve.rs:2167`, `writer.rs:2441`, `office.rs:6662/6896`); `SaveOptions` has only `fonts` (`package.rs:24-27`). No record has measured compression level (grep: none). Deflated bytes for a one-cell edit are the whole worksheet member, never the changed closure (deflate streams cannot be spliced without producer flush points), so the only levers are level and parallelism. Per-member parallel deflate under an explicit `ExecutionContext` keeps output byte-identical; 0498/0499 evidence says gate it at ≥2 regenerated members of ≥256 KiB (four 1 MiB parts: 576 → 82 µs at width 4; sixty-four 16 KiB parts regress 95 → 480-560 µs). One-cell XLSX and one-paragraph DOCX saves regenerate one member and gain nothing; only DOCX multi-part and PPTX (§2.3) qualify. Level changes alter output bytes and break the byte-identical corpus gates — policy decision, low priority.

## 3. Looks like an opportunity but is not
- **Skip or defer fsync / directory sync** — 0490: data sync is 79-82% of the tiny route but "remains required"; 0497 atomic publication.
- **Retain the `PreservationIndex` at open or cache it across saves** — 0313 deliberately deferred it to publication; it is 4.7% of the save (252,747 Ir, 132 members) and the ordinary scenario saves once.
- **Precompressed passthrough (`write_precompressed_file`)** — 0578: no production caller; unchanged members already flow as `Copy(Range<u64>)` through a 64 KiB stack buffer, peak flat at 12,971 B.
- **Widen the 64 KiB copy/exact-source chunks** — copies are memcpy-bound from a resident slice; 0572 found read-ahead width indistinguishable; with §2.2 the chunk size stops mattering.
- **Skip audits of *changed* authored XML** — ADR 0006; 0528: "Both original and replacement OPC audits must stay".
- **Infallible lazy `Part::blob` (C1)** — refused in 0581 (no error channel; relocates typed limit refusals).
- **Intra-member parallel deflate** — changes output bytes, fails 0581 gate 3 / byte-identical checks.
- **Drop `source_archive` retention to halve eager memory** — ADR 0005:341-348 requires the exact source artifact for exact passthrough.
- **Treat the save as the eager XLSX edit bottleneck** — measured: `Edit::commit` is 70-94% of the operation (1.07 G Ir for a tab rename on the 6.8 MB fixture), the save 0.5-14%; that is the 0520/0521 owner.
- **Partial output on preservation refusal** — GOAL rule 3; `owned_source_preservation_error` before any byte (`pkgwriter.rs:1005`).

## 4. Measurement blockers and defects
- **Defect (report only):** the ordinary eager XLSX save refuses two ordinary edits on a real Excel-produced file: `target/release/examples/tabs test-data/poi/test-data/spreadsheet/ConditionalFormattingSamples.xlsx OUT Home rename Home2` → `Package(XmlPublication { part: "/docProps/app.xml", source: NotCompact(Violation { kind: FormattingWhitespace, offset: 55 }) })`; `... Products1 activate` → same on `/xl/worksheets/sheet10.xml`. Offset 55 is the `\r\n` Excel writes after the XML declaration; the edit rewriters preserve it and `validate_authored_xml` (`pkgwriter.rs:988`) then refuses the whole save. `hide` (workbook.xml) and `edit_cells` (sheet1.xml) succeed. Not recorded anywhere (0525's `NotCompact` mention is a fixture fix). This blocks measuring sheet-view edits through Path A on real producer files.
- **No Path A harness scenario.** `tools/perf-baseline` measures only source-backed publication (`docx_managed_edit`, `docx_provider_lifecycle`); `PackageWriter::write_to_stream` has no accounting variant; the only opened-document save vehicles are examples (`edit_cells` uses `to_bytes` + `fs::write`, `tabs`/`copy_style`/`grid_styles`/`sheet_defaults` use `save(path)`; no DOCX or PPTX example opens a real file and edits through the model then saves). The 132-member fixture has no `Sheet1`, so only tab operations were measurable there.
- **Path A performs no candidate readback** (docx `codec.rs:1193`, pptx `codec.rs:296`, xlsx `writer.rs:33`), whereas ADR 0003:33-34 requires typed readback for staged CRUD and Path B pays it (0489). Compliance observation; also means C3 would add a cost Path A does not carry today.
- Cold-cache/real-device fsync distributions (0490 tails), peak RSS for Path A saves on real corpora beyond 0581's synthetic axes, and any PPTX eager-save profile remain unmeasured.
