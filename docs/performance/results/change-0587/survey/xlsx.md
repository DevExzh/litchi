# Survey: litchi-xlsx remaining optimization opportunities
HEAD 2fc5fc657, 2026-09-15. Scratch: `$SCRATCH/agents/xlsx/` (alloc-read.json, alloc-commit.json, alloc-eager-commit.json, alloc-summary.txt, sizes-output.txt). Fresh numbers are single-leg (taskset-pinned, 3 samples, 1 warmup, no A/A control); phase allocation counters are deterministic and match the 0538 packet within 0.2%.

## 1. Path map

**Eager door (the documented one, 0581).** `Package::open` (package.rs:44-51) and `Workbook::open` (workbook/model.rs:432-439) go through `OpcPackage::open_with_limits`: every member is inflated and retained (0581). `Inner` construction (model.rs:600-720) parses workbook.xml, validates the sheet graph, SST and styles relationships and builds one `Arc<SheetData>` per sheet; cells, SST and styles are `OnceLock`s (model.rs:114, 388-391). First `Worksheet::cell()` (model.rs:1303-1306) calls `store()` (model.rs:1442-1460): whole-worksheet `raw::worksheet::parse` + `validate_styles`, retained for the workbook's life. The SST is materialized as `Box<[Text]>` = one `Arc<str>` per string on first shared-string cell (model.rs:1464-1480, raw/strings.rs:56). `Store::from_unsorted` (cell.rs:735-800) sorts all cells, checks duplicates, builds row index and three extents. Measured sizes (sizes-output.txt): `Cell` 72 B, `Option<Cell>` 72, `Value` 24, `Formula` 72, `Text` 16 (Arc<str>), `Number` 16 (Box<str>), `Address` 8, `Rect` 16; modelled `Stored` (pub(crate), cell.rs:631-660) = 184 B per stored cell plus one heap numeral per numeric cell (semantic.rs:108-123). Iteration (`Cells`, cell.rs:1019-1060) allocates nothing. Fresh timings (alloc-read.json), dense-wide 2×256×256: open 1.41 ms; `xlsx_first_cell` 34.5 ms; `xlsx_full_cell_scan` 35.0 ms, so the "first cell" on this door is a 65,536-cell parse at ~0.50 µs/cell, 24× the open. Eager `Workbook::edit` commit (edit/semantic/transaction.rs:2498-2542) clones the `OpcPackage` (Arc blobs), re-derives the whole catalog via `from_package_with_styles` and adopts validated stores; save re-deflates only regenerated members and passes the rest through (writer.rs:32-34, pkgwriter.rs:922-945; 0578). Fresh: dense-wide one-cell commit+save 180 ms, 1,311-cell 364 ms; medium 2.64/10.67 ms (alloc-eager-commit.json; no allocation counters for these cases).

**Source-backed read door.** `SourceBackedWorkbook` (workbook/source.rs:75-100) retains the pinned catalog payload, sheet metadata and lazy SST/styles. `cell()` (source.rs:651-760) streams a selected-cell scan under `selected_stream_limits` (source.rs:1037-1046), resolves only the needed SST/style dependency (0364), and falls back to the whole-sheet Store on ineligibility or once a Store exists. `cells()`/`visit_cells()` (source.rs:757-800) run `scan_range` (source.rs:830-990) which collects `SelectedCells` records, then builds `Vec<SourceCell>` (80 B + cloned value each); `visit_cells` only iterates that Vec.

**Source-backed edit (cell_values).** Planning `from_source_selected` (cell_values/snapshot.rs:426-485): refuses worksheets with any relationship (:441-443), pins the worksheet bytes, runs the fused validator+parser when `source_stream_eligible` (raw/worksheet/mod.rs:60-68: ≤8 MiB, UTF-8, no mc/AlternateContent/x14ac/dyDescent) else two passes, `validate_style_references`, `validate_scalar_cells` (:1754-1763). `capture_auxiliary_source` (:1954-1998) fully parses styles.xml for a count and retains styles+theme bytes. Commit (cell_values/source.rs:1126-1236): per touched sheet `rewrite_value_only_with_provenance` (raw/worksheet/edit/package.rs:163-260) does a complete `scan()` into a `Layout` (per-row `RowSlot`, per-cell `CellSlot` with `primary: Box<[Span]>`, scan.rs:830-854), writes output, then `Snapshot::from_rewritten_value_source` (snapshot.rs:715-760) runs the complete `validation::worksheet_xml` on the output, the reduced readback parse (0525) and `Store::merge_omitted_cells` (cell.rs:802-850: clones every omitted `Stored`, re-sorts, rebuilds indexes) — but only if no entry of source or output has a shared string/inline-rich/metadata (`stored_entry_is_supported`, snapshot.rs:365-371), otherwise the whole candidate is parsed. Any changed cell also rewrites and re-validates workbook.xml (`invalidated_workbook_xml`, snapshot.rs:761-770; raw/recalc.rs:8-13) and drops calcChain. Publication (source.rs:537-600 → litchi-opc `write_topology_to_stream` source_backed.rs:6584) audits BOTH original and replacement bytes with `xml_minifier::audit::verify_authored` (source_backed.rs:7683-7698, 10871; xml-minifier audit.rs:696-733) because litchi-xlsx never supplies a `SourceXmlPart` proof (grep: no use; the 0519 skip at :7687-7691 never fires), then deflates replacements and transfers preserved members. Fresh (alloc-commit.json, dense-sparse = one 128×128 sheet + 3 sparse, no SST): ONE-cell edit — plan 116,915 allocs / 13.65 MB (≈7.1 allocs and 830 B per cell of the sheet), commit 151,522 / 12.0 MB (≈9.2/cell), publication 33,342 / 4.18 MB (≈2/cell), p50 41.1 ms; 178-cell edit 45.7 ms. A one-cell edit therefore costs ≈2.5 µs per cell of the touched sheet on either door (eager: 180 ms/65,536 = 2.7 µs) — roughly six whole-sheet passes (validate+parse, layout scan, output validation, reduced parse+merge, two audits, deflate). Locks: `OnceLock`/`OnceCell` for stores, SST, styles, web bindings; a `Mutex` page-break projection cache (model.rs:9, 278-312); no Rayon.

**Streaming creation** (streaming.rs:193-212, 350-445, 826-880): one reusable `row_scratch` bounded by `max_row_bytes`, rows written straight into a `PartWriter`, no per-cell heap allocation (`IntegerBuffer`/`FloatBuffer`, `push_escaped`); 0432 measured a flat 420,110 B incremental peak over a 2,048× row range. There is no XLSX append API.

## 2. Remaining opportunities (ranked)

**R1. Compact per-cell source facts from planning to remove the commit's second whole-sheet layout scan (GOAL step 1/2).** Mechanism: the planning traversal already visits every row/cell with positions; commit re-scans the same bytes into `Layout` (package.rs:176) — 53.24-54.94% of commit Ir (0550), and commit is ≈45% of the edit interval (0520). Evidence: package.rs:163-260, scan.rs:830-854, snapshot.rs:426-450. Records: 0550 names it next; 0551 selected compact cell facts over full-Layout caching and row reparsing and narrowed prerequisites (results/change-0551/next-target.md); 0553 rejected a commit-local variant on gates; 0514/0516 fusion rejected. Nothing is implemented (no proof-builder code in the tree). Size: modelled ≤ ~25% of a one-percent edit interval (share × share, not additive); fresh commit = 151k of 302k allocation calls for a one-cell edit. Scenarios: Update each field family, Exact no-op, Reversible patch; selectors `xlsx_source_backed_cell_values_{one,one_percent}_edit_save`, `xlsx_source_backed_managed_*`. Constraints: 0541 first-error guards, validator/parser semantics unbypassed, builder refusal must not trigger authoritative reparse, managed retention gates. Risk high; frozen design exists (0551) — needs an implementation batch with the differential oracle first. Falsified if: the proof builder's retained state or checks cost more than the scan on sparse/refusal rows (0553 pattern), or native p50 gain <3%.

**R2. Extend the 0525 omission readback (and the source-backed value editor) to real-producer worksheets (step 1).** Mechanism: `stored_entry_is_supported` disables the 96% reduced-parse win whenever ANY cell in source or output is a shared string, so on Excel-produced files commit parses the complete candidate; planning also refuses any worksheet with relationships (printerSettings, tables, drawings). Fresh fixture scan (95 real .xlsx): 77 have sharedStrings.xml, 57 have worksheet rels, 63 have x14ac/dyDescent/AlternateContent in their first sheets (which also disables the 0546 shared traversal). Every harness XLSX corpus has `shared_strings: null` (alloc-read/commit.json), so the retained commit evidence never exercises these fallbacks. Evidence: snapshot.rs:365-371, 441-443, 447-450; raw/worksheet/mod.rs:60-68. Records: 0525 leaves "shared-string ... boundaries authoritative" (limitations); 0542-0545 rejected extending the shared traversal past its gate; none found on relationship-bearing worksheets or an SST-aware omission proof. Size: measured 96.0-96.5% raw-parser Ir reduction and 30% commit p50 on synthetic (0525); currently 0 on SST files; unknown absolute. Scenarios: Open valid input, Update each field family, Independent producer evidence. Constraints: omitted cells are reused from the source Store, so the proof does not need the SST, but the reduced parse of edited rows must tolerate `t="s"` neighbours (supply the retained SST or omit them); relationship-bearing worksheets need a preservation proof that rels are untouched (ADR 0006). Risk medium; needs a frozen design and an SST-bearing harness shape first. Falsified if: on `ConditionalFormattingSamples.xlsx`-class inputs the complete candidate parse is <10% of commit Ir.

**R3. Publication audit reuse for the unchanged original (step 2).** Mechanism: for each replaced XML part litchi-opc audits the ORIGINAL bytes and the replacement (source_backed.rs:7696-7697, 8121-8122); the original was already fully validated by litchi-xlsx at planning, and for repeat publications from the same source it is audited again each time. `validate_overlay_xml` is 56.2% of publication Ir (0528); fresh publication ≈ 2 allocs/cell (33k calls for one changed 16k-cell sheet). Records: 0528 requires both audits to stay and says XLSX validation is not a substitute (different contract); 0519 reuses a proof only for `SourceXmlPart` replacements; 0517 removed a duplicate OPC pass for DOCX. New mechanisms not covered: (a) memoize the original-audit verdict per (source lineage, partname) inside `SourceBackedPackage` so the second publication from one source skips it; (b) a proof-carrying replacement door where litchi-xlsx hands the planning-validated original through `SourceXmlPart`/`try_replace_source_xml_part` (source_backed.rs:1521-1550) — requires litchi-opc to admit the XLSX rewrite as source-compatible: proposed ADR. Size: modelled ≤ ~28% of publication Ir; publication ≈ 11% of one-cell-edit allocation calls; time share unmeasured. Scenarios: Exact no-op, Atomic failure, Compact XML output. Risk medium.

**R4. Candidate Store as an overlay instead of clone-and-resort (step 2/4).** Mechanism: `merge_omitted_cells` clones every omitted `Stored` (one `Box<str>` allocation per numeric cell), appends the parsed cells and re-runs `from_unsorted` (sort, duplicate check, indexes, extents). 0550: provenance merge 4.64-6.03% of commit Ir; 0525: Store merge 5.97% secondary. An `Arc<Store>` source plus a sorted overlay of ≤256 changed cells (MAX_BATCH_EDITS, source.rs:24) merged at iteration would remove ~16k of the 151k one-edit commit allocations. Records: none propose an overlay; 0527 (row arena) is a different layout. Constraints: `Store` equality/readback semantics, `view`/`cells`/`rows` iterators, no weakened duplicate/ownership checks. Risk medium; design record needed. Falsified if: merge share <5% of commit Ir and native p50 unchanged (0539-style outcome).

**R5. Stop parsing the whole stylesheet at every planning (step 1).** `capture_auxiliary_source` runs `raw::styles::parse` on styles.xml only for `.len()` and retains styles+theme bytes per snapshot (snapshot.rs:1974-1980). Proportional to the stylesheet, not the touched closure; harness styles.xml is minimal so the packets never show it. Records: none found. Mechanism: count-only `cellXfs` scan or reuse of an already-built catalog. Risk low. Size unknown — falsified if styles parse <2% of planning Ir on a real-producer fixture.

**R6. Skip recalc invalidation when the workbook provably has no formulas (step 1).** Every value commit rewrites and re-validates workbook.xml (snapshot.rs:761-770, recalc.rs:8-13), then publication audits it twice and deflates it. Proxy: no calcChain relationship and no `<f>` in the planned sheets is not sufficient for other sheets, so this needs an ADR-0006 discussion (non-Excel producers omit calcChain). Records: none found for XLSX (0046/0337/0347 cover semantics, not cost). Size unknown; O(sheets + defined names). Risk semantic; low priority.

**R7. Make `visit_cells` stream (step 2).** source.rs:777-800 builds the full `Vec<SourceCell>` (80 B + cloned value per cell) on top of the scan's own record vector, then visits. Modelled: 65,536 cells → ≥5.2 MB + one heap clone per text cell. Records: 0365/0366 introduced the path; none measured the visitor. Scenarios: full text, scan all cells (source-backed); `xlsx_source_narrow_column_range_scan`. Risk low. Falsified if Vec building <10% of the scan's allocation calls.

**R8. Inline short numerals in `Number` (step 2/3, hypothesis 10).** Every numeric cell allocates its lexical numeral at parse (semantic.rs:108-123, selected.rs:1341) and again on every clone (R4 merge, `SourceCell`). Public `Number::new(impl Into<Box<str>>)` could keep its signature over an inline ≤23-byte form; `Cell` would grow from 72 B. Records: none on numeral representation; 0539 (transient attributes: −13.6% calls, −0.3% bytes, native rows failed) predicts the likely outcome. Modelled: −1 of ≈7 planning and ≈9 commit allocations per cell. Rank low; falsified if native p50 does not move ≥3% on dense-sparse.

## 3. Looks like an opportunity but is not
- Lazy/edited-row-only worksheet validation at planning: ADR 0005 mandatory validation; 0540/0541/0546; 0551 shows edited rows cover 16,769 of 17,792 cells.
- Fusing candidate-output validation/parse with the writer: 0514, 0516 rejected; 0521 keeps candidate validation and readback.
- Row-owned span arena / per-cell span vectors: 0526/0527 rejected (1.82% < 2% gate); combined cell-reference/tag scan: 0522 rejected; transient attribute borrowing: 0539 rejected; commit-local compact proof: 0553 rejected.
- Widening the shared traversal past x14ac/MCE with event caps or preflight: 0542-0545 rejected.
- Dropping or substituting the publication audits: 0528 ("both ... must stay"); only reuse/proof mechanisms (R3) remain.
- Recompressing unchanged members on save: already passthrough (pkgwriter.rs:922-945; 0578).
- Eager-door retention (`Workbook::open` inflating everything; 24× cost of a first-cell read): 0581 froze C2/C3 with admission gates and a required ADR; quantified here, not re-proposed. Eager lazy SST is subsumed by C3 (source door already streams dependencies, 0364/0365).
- Widening the 4,096-cell/1 MiB validated-store handoff: failed its memory gate (0025/0466).
- Streaming writer memory: bounded (0432) and allocation-free per cell; nothing left except that no append API exists.

## 4. Measurement blockers and observations
- Every harness XLSX corpus has no sharedStrings part and integer-only payloads; the x14ac/noncompact CRUD shapes exist but no SST shape, so R2's fallbacks are never on the measured path. Real fixtures ≥500 KB: `no_drawing_patriarch.xlsx` (3.38 MB worksheet), `StructuredRefs-lots-with-lookups.xlsx` (1.56 MB), `deep-data.xlsx`, `stress024.xlsx`.
- The source-backed value editor refuses 57/95 real fixtures (worksheet rels), Unknown cells and cell metadata, and caps commits at 256 actions (source.rs:24): the 1,311-update dense-wide workload exists only on the eager door.
- `litchi-perf-baseline-alloc` reports allocation counters only for cases with operation regions; read selectors (`xlsx_first_cell`, `xlsx_full_cell_scan`, `xlsx_open_owned`) return elapsed only, so per-cell read allocations are modelled (184 B `Stored` + numeral), not measured. Eager read selectors time the lazy parse and exclude the open.
- No A/A control for this session's timings (host noise p50 4%); the allocation counts are deterministic.
- To verify (not a confirmed defect): publication applies the authored-compactness audit to the ORIGINAL part bytes (source_backed.rs:7696, 8121); a real-producer worksheet with indentation-only whitespace could be refused at publication although planning accepted it. `visit_cells` is documented as a visitor but materializes the whole range first.
- Harness binary `litchi-perf-baseline-alloc` was built this session (tools/perf-baseline/target/release, 45 s, ~60 MB) and left in place; scratch is 332 KB; the size probe crate lives in `$SCRATCH/agents/xlsx/sizes` and built into the workspace target.
