## 1. Path map

**Source layer (litchi-core).** `ReadAt` is copy-out by contract: `read_at(&self, offset, &mut [u8])` (`crates/litchi-core/src/source.rs:84`), so every consumer copies source bytes into its own buffer; there is no borrowing accessor, no `read_vectored`/`preadv`, no `mmap` (no `memmap` dependency anywhere in the workspace; ADR 0001:48 allows audited mmap only in low-level owners, GOAL.md:381 only after proof). `FileSource::read_at` is one `pread` per call with an EINTR loop and no lock (`source/file.rs:131-145`, `:192-193`). Two observations are syscalls: `FileSource::len()` = one `fstat`/`statx` (`file.rs:127-129`) and `FileSource::version()` = mutex + `statx` + fingerprint compare (`file.rs:146-166`). `FileSource::from_file` itself calls `metadata()` twice (`file.rs:93`, `:102`). `OwnedSource`/`SliceSource` observations are free (`source.rs:172-227`).

Measured cost on this host (M, `$S/microbench-results.txt`, scratch project `$S/microbench/src/main.rs` on litchi-core alone, `taskset -c 3`, best of 5×200k/2M): `FileSource::version()` 167 ns, `len()` 157 ns, `read_at` 512 B 144 ns, 4 KiB 161 ns; `OwnedSource::read_at` 4 KiB 16.8 ns; `SourceVersion ==` 0.6 ns. So one observation costs the same as one 4 KiB pread.

**Facade ingress (crates/litchi).** Path opens go through `FileSource` and dispatch to source-backed readers for XLSX/XLSB/XLS (`detection_smart/detected.rs:808`, `:842`, `sheet/workbook.rs:310-373`), DOCX (`detected.rs:2393`, `document/doc.rs:745+`), PPTX and native PPT (`detected.rs:3014`, `:3069-3150`, `presentation/prs.rs:569-760`). Two fallbacks read the whole file into a `Vec<u8>` via `read_path_source_bytes` (`detected.rs:1198-1225`, capped at 2 GiB by `UNIFIED_*_FALLBACK_MAX_INPUT_BYTES`, `:738`, `:2105`, `:2148`) and then run `from_bytes`: (a) **every `.doc`** — `DocumentSourcePathDetection` has only `Odt`/`Docx`/`Bytes` variants (`detected.rs:2156-2171`), so a `.doc` path becomes `DetectedFormat::Doc(OleFile<Cursor<Vec<u8>>>)` (`detected.rs:42`) and an eager `doc::Package::from_ole_file` + `package.document()` (`document/doc.rs:928-941`); the facade never references litchi-doc's `SourceSnapshot::open(Arc<dyn ReadAt>)` (`crates/litchi-doc/src/body_text/source.rs:490`); (b) non-OOXML, non-ZIP inputs with no native owner (RTF etc., out of scope). `from_bytes(Vec<u8>)` entry points wrap the vector in an `OwnedSource` and reach the source-backed package for XLSX/XLSB/PPTX/DOCX (`workbook.rs:442-470`, `prs.rs:760-872`), so the eager `OpcPackage` retention documented in 0581 is the format crates' own `Package::open`, not the facade. The dead helper `refine_workbook_format` still slurps a `Read` (`sheet/workbook_types.rs:133-160`, `#[allow(dead_code)]`).

Per open, the facade adds fences: the XLS route runs 6 `ensure_path_source_current` + 1 `len()` + 1 `version()` (`detected.rs:835-1000`); the PPT route 8 (`:3069-3150`). Measured whole-process syscall deltas per open (M, strace 1 vs 11 samples, `$S/strace-54016-*-open-s{1,11}.txt`): `54016.xls` facade-file 42 `pread64` + 36 `statx`; direct file-source 40 + 30; `ConditionalFormattingSamples.xls` 55 + 40 and 53 + 34. The tool's own attribution of the file-source open (`$S/attribution-54016-file-source-open.json`) is `version_calls: 25`, `len_calls: 1`, `read_bytes: 317,171` of a 984,576-byte file. The 25 fences come from `SharedOleFile::open_with_limits` (3: `crates/litchi-cfb/src/shared.rs:599`, `:601`, `:623`) and `check_source_version` on each `read_stream_range_hinted` (`shared.rs:1047`, 12 call sites, one `statx` each, `:2391-2392`).

**Budget/ExecutionContext.** `Budget::consume` is one `fetch_update` CAS per hierarchy level (`budget.rs:160-186`); `reserve` additionally clones an `Arc<Node>` per level into a `SmallVec<[_;4]>` and releases on drop (`:198-227`, `:269-272`). Measured (M): consume 6.0 ns at depth 1, 15.8 ns at depth 3; reserve+drop 44 ns / 99 ns. It is **not** charged on OLE2 per-read paths (litchi-cfb 2 sites, both in `shared_bulk.rs:138,151`; litchi-xls/ppt 0; litchi-doc 1); OPC charges per part in batches (`source_backed/batch.rs:317-324`, one `Memory` + one `Objects` reserve per `PartData`), per read-ahead chunk (`read_ahead.rs:305`) and per splice fragment (`source_backed/splice.rs:1028-1841`). `ExecutionLimits` carries workers, max_in_flight_tasks, max_in_flight_bytes, min_parallel_bytes, affinity (`execution.rs:38-44`); `ExecutionContext` = Budget + CancellationToken + limits (`:205-260`). Resources: Memory, InputBytes, OutputBytes, Objects, Depth, Work (`budget.rs:18-25`).

**Parallel sites.** Exactly three, all opt-in and all serial by default: (1) `soapberry_zip::office::ParallelReadSession` builds its own `rayon::ThreadPool` per session (`office.rs:259-290`), batches by task/byte caps and goes parallel only when `batch.len() > 1 && batch_bytes >= min_parallel_bytes` (`:396-403`); reached from `litchi_opc::execution::OpenSession::from_bytes/from_vec` (`litchi-opc/src/execution.rs:36-42`, `pkgreader.rs:659`) — the eager path only; (2) `SourceBackedPackage::read_parts_ordered` admits scoped-thread waves (`source_backed.rs:5865` → `batch.rs:517-545`, `std::thread::scope`, not rayon) when a context with workers > 1 is attached — no format crate or facade caller exists (grep); (3) `SharedOleFile::bulk_read` (`litchi-cfb/src/shared.rs:541`, pool in `Mutex<Option<Arc<ThreadPool>>>` built lazily, `shared_bulk.rs:77`, `:210-225`) — no caller in litchi-xls/doc/ppt or the facade. Save/compression paths have no parallel code at all (`litchi-opc/src/pkgwriter.rs`, `atomic.rs`, soapberry-zip writers, `litchi-cfb/src/writer/*`: zero rayon/scope hits).

**Locks on hot paths.** OLE2 read: only the `FileSource::version` mutex (`file.rs:146-151`, inside the 167 ns above), the MiniFAT single-flight slot (`shared.rs:345`, `:1463`) and the ministream cache (`shared.rs:507`, `:2446`) on mini-stream reads. OPC: cache/flight-state mutexes (`source_backed.rs:4080`, `:4276`), read-ahead mode/state mutexes (`read_ahead.rs:166-169`), `PhysPkgReader` `Arc<Mutex<PartBudget>>` (`phys_pkg.rs:59-77`). Retained contention evidence: 0088 (no improvement accepted), 0405 (observation seam only; "lock nanoseconds cannot be compared with an uninstrumented run"), 0240 ("process thread count and lock wait remain unavailable").

**Whole-document-proportional work in litchi-core.** `JoinedSubEdits::join` scans every accepted sub-edit per incoming edit with three `BTreeSet::intersection`s each (`patch.rs:1754-1790`, `:1889-1920`) — O(n²·k) per composition, bounded only by `CompositionLimits`. `Patch::inverse` clones two `BlobBundle` maps of `Arc<[u8]>` (`patch.rs:529-540`, O(entries), not O(bytes)). `BlobBundle::insert` hashes the blob with SHA-256 (`:244`), and `DiagnosticFingerprint::of` hashes a whole serialized patch (`:47`, `:589`).

**Hashing.** Std `HashMap`/`HashSet` with SipHash-1-3 everywhere in scope; no `ahash`/`fxhash`/`rustc-hash`/`hashbrown` dependency and no custom `BuildHasher` (grep). Map-heavy crates: litchi-pptx 135 HashMap sites, litchi-xlsx 87, litchi-docx 79, litchi-opc 39, litchi-ppt 27 (+82 BTreeMap). No hashing symbol appears in the top 25 of any retained XLS profile (`results/change-0584/ranking.txt`).

## 2. Remaining opportunities (ranked)

**R1. Route `Document::open(.doc)` through a source-backed DOC reader instead of slurp + eager parse.** GOAL step 1-2. Mechanism: the facade reads the entire `.doc` into a `Vec` (`detected.rs:2470-2489`), builds an in-memory `OleFile<Cursor<Vec<u8>>>`, and parses every stream eagerly (`doc.rs:928-941`), while litchi-doc already has `SourceSnapshot::open(Arc<dyn ReadAt>)` (`body_text/source.rs:490-500`) that PPT and XLS analogues use from the facade. Code evidence above. Record status: 0584 (first DOC measurement; open Ir is not size-driven — folded totals `docsmall/open` 5.40 M Ir > `docbig/open` 4.96 M Ir, `results/change-0584/folded-docppt.json`), 0586 (paragraph hint rejected, states `SourceSnapshot::open` refuses most fixtures), HOTSPOTS.md:15-16 ("49 of 57 `.doc` fixtures are refused by `SourceSnapshot::open` outright"). No record covers the facade route itself (grep `DocumentSourcePathDetection|unified DOC|DetectedFormat::Doc`: none). Size: U for the facade delta; the eager DOC open is 3.5-5.4 M Ir per fixture (M, 0584), 26-58% of it memset+memcpy, and the whole-file read is a second full copy (Mo: file size bytes of memcpy + one `Vec` of file size retained for the document's lifetime). Scenarios: Read/snapshot "Open valid input" via the public facade; OFFICE_API_GUIDE `Document::open` (guide:645); harness has no `.doc` facade selector (blocker B1). Constraints: ADR 0005 immutable positional source, ADR 0006 typed refusals — the source-backed reader must refuse exactly what the eager reader refuses or the route must fall back per fixture, which is a preservation question. Risk high; a frozen design record is required first (admission coverage of `SourceSnapshot` is the gate, per 0586). Falsified if: on the eight admitted fixtures the source-backed open is not lower in Ir *and* peak RSS than eager, or if widening admission requires weakening a validation the eager path performs.

**R2. Collapse the 25 per-open `version()` fences on the file-backed XLS open to one per operation boundary.** GOAL step 2 (I/O). Mechanism: `read_stream_range_hinted` calls `check_source_version` on every stream read (`shared.rs:1047`, `:2391`), and the facade re-fences after every probe (`detected.rs:835-1000`, 6 fences), so an open issues 30-36 `statx` for 40-55 `pread`s (M, strace, files above). ADR 0005 requires observing before work and comparing after; it does not require a `statx` per read. Records: 0558 (two fences per read → one), 0560 (one observation per freshness check), 0563 (one fewer per warm OPC part read; "24 removed statx at roughly 0.2 µs each … explains at most a third of the observed movement") — the residual 25 is not attributed by any record. Size: Mo 25-36 × 167 ns ≈ 4-6 µs per open against ≈ 1.19 M cycles for the same open (0579 table, ≈ 0.4 ms at 3 GHz) ≈ 1-1.5%: below the p50 noise floor on a warm local file, so the claim would have to be a **count** claim (statx per open), which is what matters on network filesystems where `statx` is a round trip. Scenarios: Read/snapshot opens and one-cell queries on `FileSource` (harness `xls_source_attribution --mode file-source|facade-file`). Constraints: fence placement must keep every typed `SourceChanged` refusal at the same operation boundary; risk medium (the per-read fence is what makes a mid-operation truncation surface as `SourceChanged` rather than a garbled read). No ADR change; a frozen design record stating the fence boundary is advisable. Falsified if: moving fences to operation boundaries changes any `SourceChanged` outcome in the existing change-under-read tests, or if the count cannot drop below ~10 per open.

**R3. `ExecutionContext` completeness (prerequisite, not a speedup).** GOAL Workstream F list vs `execution.rs:38-44`: present — max workers, in-flight task/byte caps (the decompression-in-flight budget is the byte cap), `min_parallel_bytes` task threshold, cancellation, affinity, hierarchical Budget. Missing — an I/O concurrency limit (nothing bounds concurrent `read_at`s; the zip session and the CFB bulk session both issue reads from workers), a CPU task budget distinct from byte-denominated `Work`, and a caller-provided executor/scoped-worker facility (each session builds its own rayon pool: `office.rs:276`, `shared_bulk.rs:217`; OPC batches use `std::thread::scope`, `batch.rs:517`), so three pools can coexist in one process. Records: 0009, 0088, 0240, 0498, 0499 use the current shape; none proposes the missing fields. Size: n/a (design). Constraint: ADR 0005:50-52 names "scheduling, affinity, cancellation, thread and memory budgets"; adding I/O concurrency and executor injection is an ADR 0005 amendment → proposed ADR required. Risk low. Falsified if: no measured scenario ever admits more than one session at a time (then pool duplication is theoretical).

**R4. Parallel compression of changed members on multi-part saves.** GOAL step 5. Mechanism: GOAL F lists "compression of changed output members" as independent work; every writer is serial (grep above) and 0578 shows unchanged members are bounded passthrough, so the only CPU-heavy save work is deflating changed members. Records: 0473/0474/0479 (streaming creation memory), 0491-0501 (DOCX save: "publication dominates named phases"), 0578; none tries parallel deflate. Size: U. The retained scaling evidence (0009) says few-large tasks scale (OPC 4.52x at 12 workers, Amdahl serial fraction ≈ 15%; CFB 5.93x, ≈ 9.3%) and many-small regress (0.73x/0.52x), so the gate is "≥ 2 changed members each ≥ `min_parallel_bytes`", which ordinary single-part edits never meet. Scenarios: Opened-document CRUD saves with many changed parts (e.g. style + several slides/sheets). Constraints: no hidden pool (GOAL rule 9), output byte order must be preserved, `OutputBytes` budget and cancellation must cover in-flight compressed buffers. Risk medium. Frozen design record required. Falsified if: a corpus scan shows the median multi-part edit changes < 2 members above the threshold, or if deflate of the changed set is < 20% of save wall time.

**R5. Invert the effect index in `JoinedSubEdits`.** GOAL step 4. Mechanism: `join_failure` iterates all accepted edits (`patch.rs:1775-1782`) and intersects effect sets pairwise; an `effect → edit id` map would make a join O(k log n). Records: none found (grep `JoinedSubEdits|sub-edit|SubEdit` over all records: 0). Size: Mo n²·k with n bounded by `CompositionLimits::sub_edits`; in-tree users construct limits of 4-8 sub-edits (`litchi-docx/src/document/transaction.rs:7716`, `litchi-doc/src/body_text.rs:4875`), so today it is microseconds. CRUD checklist row "Hot paths are indexed … overlap detection … avoid accidental quadratic behavior" (checklist:71-82) is the stated requirement. Users: `litchi-docx/src/document/transaction/durable.rs:151`, `litchi-doc/src/body_text.rs:2468`. Risk low; no ADR. Falsified if: no production composition exceeds ~16 sub-edits (then it stays a hygiene item).

**R6. Per-part `Objects` reservation in OPC batches.** GOAL step 1. `batch.rs:317-330` performs two hierarchical reserves per `PartData` (M: 44-99 ns each). Mo: ≤ 200 ns × parts; a 132-member workbook ≈ 26 µs. Listed only to close it: it is not worth a change unless batches reach thousands of parts. Records: 0498/0499. Falsified already by the micro-measurement unless part counts grow 100×.

**R7. ILP in serial loops — nothing rankable without new evidence.** From `results/change-0584/ranking.txt` the non-memcpy leaders on the flagship one-cell query are `next_chain_sector` 4.06%, `SectorChainScratch::collect_exact` 3.58%, `from_shared_ole_file_with_limits` 3.33%, BIFF `Records::next` 1.61%. The chain walk is a true pointer chase (each link's address is the previous FAT entry); 0579 measured that adding per-sector state-machine layers cut instructions 7.7% but raised cycles 3.7% (IPC 3.629 → 3.230), and 0570 already batches contiguous FAT runs, so the remaining lever is fewer links (0585's second hint), not ILP restructuring. `Records::next` is length-chained framing (next header depends on current length); a speculative two-record decode would need the whole globals buffer resident, which `GlobalsBuffer::ensure` (1.14%) already provides — Size U, and the memcpy/memset 50% (0574 opp 4 / 0584 cand 5) dwarfs it. Recommendation: price any ILP candidate in cycles via `perf stat` (0579 method) before writing code; do not rank one now.

## 3. Looks like an opportunity but is not

- **Swap SipHash for FxHash/ahash.** No hashing symbol is in any retained top-25 (0584 ranking); ADR 0006 favours DoS-safe defaults; no record rejected it because nobody measured it as hot. Not an opportunity without a profile showing a hot map.
- **mmap the file.** `ReadAt` copies by contract (`source.rs:84`), so an mmap-backed source would still memcpy into every consumer (the OwnedSource copy is 16.8 ns / 4 KiB, M); the XLS open reads 317 KB in 42 preads (M) ≈ 7 µs of syscalls. ADR 0001:48 / GOAL.md:381 restrict mmap to an audited low-level owner after proof; no borrowing consumer exists to benefit.
- **`read_vectored`/`preadv`.** No scatter/gather pattern exists (one range per record); the only multi-range read pattern (mandatory rels at OOXML open) is designed as run coalescing in 0577, blocked on a soapberry-zip accessor, not on vectoring.
- **Remove the `FileSource::version` mutex.** The mutex is ≤ 10 ns of the 167 ns observation (M: `len()` without the mutex is 157 ns); the cost is the `statx`.
- **Charge/skip `Budget` on hot paths.** Consume is 6-16 ns (M); it is not on OLE2 per-read paths at all.
- **Parallelize the open (rels/parts) with the existing session.** 0009: many-small tasks regress (0.73x OPC, 0.52x CFB); 0577: the rels reads are mandatory and small; 0498/0499: per-wave thread creation makes many-small regressions "material". The correct lever is 0577's coalesced prefetch (I/O), not workers.
- **Lazy rels / skip validation at open.** Refused on ADR 0005/0006 grounds in 0577; early exit from `query_cell` refused in 0574 opp 6.
- **Make `OpcPackage::open` lazy or route it to the source-backed package.** 0581 C2/C3 are frozen with admission gates and each needs a proposed ADR; the facade already uses the source-backed package (path map).
- **Widen read-ahead.** 0572: 4 KiB → 64 KiB indistinguishable on the simulated range source.
- **Cache `FileSource::len()`.** Its `statx` is the freshness observation ADR 0005 asks for; caching it would silently miss truncation.

## 4. Measurement blockers

- **B1.** No harness selector opens `.doc` or `.ppt` through the facade (`litchi-perf-baseline --case` lists `cfb_*`/`opc_*`; only `filesystem.rs:2525` uses `litchi::Presentation::open`). R1 cannot be A/B-measured without a new selector; `xls_source_attribution` covers XLS only (modes `owned-readat|atomic-file|tracked-file|file-source|eager-file|facade-file`).
- **B2.** `SourceSnapshot::open` refuses 49 of 57 `.doc` fixtures (HOTSPOTS.md:15-16, 0586:79), so a source-backed DOC route is measurable on eight fixtures only.
- **B3.** Lock wait and process thread counts are unavailable by design in the harness envelope (0240); 0405's seam adds timer overhead, so contention can only be counted, not timed, without a new uninstrumented ABBA design.
- **B4.** `folded-docppt.json` retains whole-operation totals only; per-symbol DOC/PPT attribution must be re-derived from `results/change-0584/callgrind-docppt/`.
- **B5.** My one-cell strace run produced zero deltas — the tool needs worksheet/row/column arguments I did not pass; per-query `statx` counts remain U here (0560 holds the last measured value).
- **B6.** No real range source (simulated transport only); the R2 count claim's latency relevance on network filesystems is therefore Mo.
- **Correctness notes (report only).** `refine_workbook_format` (`workbook_types.rs:133-160`) is a public, dead, whole-input slurp of any `Read` — a latent GOAL-hypothesis-1 ingress if it is ever wired. Three rayon/scoped pools can coexist in one process (R3) with no shared cap. `FileSource::from_file` performs two `metadata()` calls where one suffices (`file.rs:93`, `:102`) — 160 ns, cosmetic.
