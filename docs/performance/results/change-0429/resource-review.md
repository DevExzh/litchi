# Provider and native resource review

All 960 retained rows end with zero releasable managed Memory, Objects and
Depth. Native rows additionally compare the returned descriptor, revalidate
the payload after dropping both view and slide, and verify caller-source
release. These checks concern the explicit owners and budgets, not total
process memory or a general leak claim.

Every non-RSS numeric phase observation has identical min/max within its
process and identical distributions across corresponding R1/R2 processes.
This includes cumulative source-read counters, checked interval histograms,
cache events and gauges, and caller budget gauges/charges. Cumulative charges
are not expected to return to zero. Unavailable observers remain null.

All 27 review triggers are the nine RSS phases in each media-rich bytes, file
and short-range lane. Each affected lane already differs at its baseline
phase. RSS includes corpus setup, input and output backing storage, executable
hashing, allocator state and observers. Entry differences cannot be assigned
to the timed APIs. The bundle therefore retains every flag and withholds
comparative RSS conclusions. No API-duration/rate median exceeds the 5%
repeat threshold; two repeats on this host are not proof of population stability.

The range histogram describes requested buffers, while caps constrain returned
chunks. Provider delta min/max fields retain the cumulative snapshot bounds;
interval request-size distributions come from the subtracted histogram bins.
File inputs are warm after staging/hash reads, and the configured delay includes
scheduler overhead. No physical-device, transport, WAN or bandwidth attribution
is established. API-only clocks also exclude source construction, copies,
reservations, checks, observers and drops; their sum is not full lifecycle time.
