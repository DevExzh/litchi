## 0653 — the MCE writer stops re-declaring every namespace on every element: 16.86× expansion becomes 0.93×, the 133.61 ms real-deck edit becomes 22.96 ms, and the marker/control ratio falls from 20.79× to 2.94×

Change [0588](0588-mce-codec-namespace-emission.md) designed, implemented, measured and then **withdrew** this rewrite, because the writer's redundancy was load-bearing — any element span of the processed buffer happened to be namespace self-contained, `litchi-docx` sliced such spans and parsed them standalone, and two writers publish the processed bytes. Change [0649](0649-pptx-opened-transaction-real-deck-edit.md) then priced the redundancy on a real deck: **93.9%** of a 133.61 ms `set_shape_text` plus commit, six whole-slide rewrites per edit each amplified **16.25×**, **28,064,911 bytes of markup produced and thrown away per edit, 259× the source archive**. Decision 1 of change [0652](0652-owner-decisions-for-the-third-wave.md) authorized both halves, and this lands them. `write_start` now emits an element's **own** `xmlns`/`xmlns:*` attributes in source order, plus — only when the output drops an `mc:AlternateContent` wrapper, a `Choice`/`Fallback` branch or a `ProcessContent` element between this element and its nearest emitted ancestor — the declarations those dropped ancestors made, innermost binding winning; `Frame` carries `emitted_ns` and "is there anything to hoist" is one `Arc::ptr_eq`, so the common element pays nothing. A start tag that drops no attribute, hoists nothing, holds no unescaped value and contains no `&` or `<` is **copied verbatim** from the source. The property the consumers relied on is restored **at the slice boundary** instead, by a new shared `mce::self_contained_fragment` that re-declares on one element exactly what it inherits — the shape `litchi-xlsb`'s drawing transfer and `litchi-docx`'s section inventory already used, generalized. **Measured**: the 209,931-byte real worksheet goes from **3,540,261 to 194,508 output bytes**, exactly 0588's predicted figure; over the whole corpus, 6,964 parts, **197,811,418 → 36,761,542 bytes, −81.42%, with 0 parts growing**; the codec's per-call cost falls **305,273,402 → 61,464,892 Ir (−79.87%)**, a public eager open plus one cell **496,700,777 → 154,479,583 (−68.90%)** and a source-backed read **651,068,133 → 304,172,603 (−53.28%)**. In the before profile the codec's self cost is `BoundedOutput::extend_from_slice` 21.81%, `__memcpy_avx_unaligned_erms` 16.45% and `esc` 9.10%; **none of the three appears in the after profile at all**. On 0649's real deck the edit total falls **127.44 ms → 24.19 ms (−81.02%, A/A 3.72%)** and through 0638's harness `pptx_real_file_ordinary_save_edit` falls **133,438,301 → 22,960,854 ns (−82.79%, floor 4.77%)** — two independent instruments, and the before leg reproduces 0638's 133.61 ms to 0.13%. The marker-free control deck is unchanged (8.32–8.46 ms both legs), so the remaining 24.19 ms is the six parse passes 0649 found, which this change does not remove: **2.9× the control rather than 15.4×**. Two accidental refusals disappear with the expansion that manufactured them: `LimitExceeded("output bytes")` on parts that fit their own bound, and `litchi-xlsx`'s `unknown printOptions attribute 'xmlns'`, which meant **every worksheet whose `printOptions` sat inside an `mc:AlternateContent` was unreadable** because the parser refused its own preprocessor's output. Change [0664](0664-perf-harness-marker-bearing-corpora-and-save-allocations.md)'s marker-bearing selectors, which landed after this change's own measurement window and price the codec branch against a **byte-identical** marker-stripped control, agree from an independent corpus: `pptx_marker_ordinary_save_edit` **155,537,122 → 21,340,230 ns (−86.28%, A/A 2.96%)**, `docx_marker_eager_full_text` **−92.25%**, `docx_marker_source_full_text` **−92.56%**, and the **marker/control ratio collapses from 20.79× to 2.94×** on the PPTX edit and from 30.06× to 2.24× on the DOCX source-backed full text — while **every one of the seven byte-identical control selectors moves less than its own floor**, which is what makes those rows a measurement of the branch and not of the corpus. 0664 also found that `Document::write_text_to` refuses a marker-bearing DOCX with `semantic DOCX XML exceeds 4096 namespace bindings` while its byte-identical control is admitted, because that limit counts `xmlns:` attributes cumulatively and a 33-declaration root exhausted it after about 124 elements; a retained witness shows that refusal **gone with the limit untouched** — the marker package now projects the control's exact 2,689 bytes over 200 objects. One regression is reported and chased: `pptx_real_file_ordinary_save_counting_publish` is +20.81% (+13.2% isolated) against A/A block spreads of 20% and 36%, on identical published bytes, +56 µs on a route whose edit falls by 110 ms. `performance_claim: none`. OLE2/OOXML remain active; ODF stays deferred; iWork is excluded. [Record and limitations](0653-mce-namespace-emission-rewrite.md); [retained evidence](results/change-0653/README.md).

## 0653 — clause (b)'s "no unnecessary intermediate" is enforced on the OOXML read path for the first time: 197.8 MB of intermediate markup over the corpus becomes 36.8 MB

Record: [0653](0653-mce-namespace-emission-rewrite.md).

`docs/GOAL.md` asks for no unnecessary work and no unnecessary intermediate representation. The markup-compatibility codec violated both by a large, measured margin on every part a real producer writes: it re-declared every in-scope namespace on every emitted start tag, so a 209,931-byte worksheet produced 3,540,261 bytes of intermediate (16.86×) and the corpus's 6,964 parts produced 197,811,418 bytes where 36,761,542 suffice. The redundancy bought exactly one thing — accidental self-containment of arbitrary inner spans — and this record shows it can be bought for a few hundred bytes on one element instead, at the slice boundary, by the consumer that actually needs it. Three tiers as the audit requires. **Measured**: every byte count above, from a corpus differential over 6,964 parts on both legs; the callgrind isolation pairs; the paired medians on the 0649 deck (−81.02%, A/A 3.72%) and through 0638's harness (−82.79%, floor 4.77%); the twelve marker-free XLSX selector rows, every one moving less than or within a factor of two of its own floor; the publication census over 20,421 published members per leg; and the 179,205-line public-read digest per leg. **Modelled**: nothing. **Unknown**: nothing about the eager XLSX read's wall clock any more — it needed three windows, two of which were destroyed by unpinned neighbours and are retained as failures, and the third gives −64.98% against a 2.17% floor; whether the +20.81% on `counting_publish` is allocator heap state, which is argued from an 83% drop in per-sample work on identical published bytes and not demonstrated; and the behaviour of six migrated `litchi-xlsx` accessors and the PPTX source-backed picture path, for which this corpus supplies **zero** observations. The audit's most useful output is a correction to two clause-(a) claims the program had been making. First, `litchi-xlsx`'s `print_options` parser **refused its own preprocessor's output** for any worksheet whose `printOptions` sat inside an `mc:AlternateContent`; a workspace test asserted that refusal as correct. Second, `litchi-docx`'s `Paragraph::extensions()` refused every paragraph of a `word/document.xml` that declares `xmlns:w` only on its root and carries no MCE markup — 0588 reported that defect and declined to fix it, and the migration fixes it: corpus refusals fall from 122 to 118 and the four are exactly that fixture. Both were invisible because neither corpus differential existed before this record. A third, which change 0664 found and asked this record to witness: `Document::write_text_to` refused a marker-bearing DOCX with `semantic DOCX XML exceeds 4096 namespace bindings` while its byte-identical control was admitted, because the limit is a **cumulative** count of `xmlns:` attributes and the writer re-declared every binding on every element, so a 33-declaration root exhausted a 4,096 budget after about 124 elements — a documented public entry point made unusable on producer-shaped input by an artifact of the writer, with the limit itself perfectly reasonable. It is gone, the limit untouched, and a retained witness carries both legs. A fourth is reported and not fixed: `litchi-xlsx`'s `raw/worksheet/mod.rs` states the old writer's invariant in its prose and its byte budget; the predicate stays sound because it is conservative, but it now admits far less than it could, and that file belongs to change 0657 in this wave. `performance_claim: none`. OLE2/OOXML remain the active priority; ODF stays deferred until completion; iWork is excluded.

## 0653 — a byte-visible writer change with no contract movement: no signature, no error, no limit, and two refusals removed only where the writer itself manufactured them

Record: [0653](0653-mce-namespace-emission-rewrite.md). Authority: decision 1 of change [0652](0652-owner-decisions-for-the-third-wave.md), which assigns this change **no ADR amendment**; none is made.

**ADR 0003.** No public type, signature, error or crate dependency is removed or changed. Six items are added — `mce::InScopeNamespaces`, `mce::self_contained_fragment`, `self_contained_xml()` on five `litchi-docx` types and on `litchi_pptx::shape::{Common, Shape}` — and two more inside the existing `#[doc(hidden)] pub mod private`, whose documented contract already says it carries no compatibility promise. Decision 1 authorized breaking changes; the migration did not need one, and the record says so rather than taking the licence. **The one behavioural break is stated plainly**: the bytes returned by every retained-markup accessor change, and the record measures the change (13,250,784 → 1,615,294 bytes over 2,209 observations) and proves the namespace-resolving meaning identical on all of them (0 canonical differences over 179,205 observations per leg).

**ADR 0005.** No archive type, raw lock or executor is exposed; the new public type carries owned byte pairs. No read, no positional source and no validation is relocated: the codec performs the same mandatory pass over the same parts in the same order with the same bounds, and every attribute name is still expanded — and so still refused for an invalid QName or an unbound prefix — *before* the writer decides whether a tag can be copied verbatim. `litchi-docx`'s migration deliberately reuses the crate's existing `XmlRef::namespace_resolver` lease rather than bypassing it, so a managed or source-backed paragraph keeps its namespace-scan admission accounting; retained state is unchanged. The new helper **adds** validation rather than removing any: a range outside its document, a range not beginning with an element, a malformed document, and a scope exceeding `max_depth` or `max_namespace_bindings` are each refused with a typed error.

**ADR 0006.** The substance. Preservation by default is unaffected — the corpus publication census shows **19,896 pristine published members, 0 of which changed**, so the codec's output still never reaches a part the caller did not edit. The four members that do change are `ppt/presentation.xml` on `litchi-pptx`'s guides writer, the one writer in this corpus that publishes processed bytes; its output moves **towards** its source (309, 58, 76 and 106 redundant declarations become 10) and is canonically equal with identical node counts. Its documented no-op path still returns an untouched source byte for byte, unchanged and re-verified. Determinism is untouched: both legs publish a stable digest per fixture and the census compares them member for member.

**Two refusals disappear, and the record argues why neither is a weakened defence.** `Limits::max_output_bytes` is unchanged to the byte and still checked before every write; what changed is that the codec no longer manufactures output that exceeds it, which change 0587 named a defect and 0588 recorded as still open. `litchi-xlsx`'s `parse_options` reported a bare `xmlns` as `unknown printOptions attribute 'xmlns'`, and the old writer put one on the `printOptions` it selected out of an `mc:AlternateContent`, so the parser refused its own preprocessor's output and every such worksheet was unreadable; no production line of `print_options.rs` changed and the defect is now pinned by a test that carries both byte shapes. In the other direction **no input that used to succeed can now fail**: over the corpus, 6,964 parts keep an identical refusal identity, 30,000 mutants keep an identical error variant, payload and message, 1,276 save outcomes per leg keep an identical OK/ERR status and `Debug` variant, and the public-read digest's only outcome movement is four refusals becoming correct reads.

**Correctness over performance, recorded twice.** The self-containment helper re-declares every inherited binding the fragment root does not declare rather than only the prefixes a scan believes the fragment uses, because an unfamiliar subtree would be mis-served by such a use-set; and `litchi-pptx`'s picture-descriptor read now takes one owned copy per descriptor where it borrowed, because the borrowed alternative needs the re-parse seeded from the owner, which is a larger change than this migration is scoped to. No new `unsafe`, no new dependency, no hidden global pool, every reservation still fallible. **One stale ADR-adjacent artifact is reported and deliberately not edited**: `litchi-xlsx`'s `MceRewriteEquivalence` documents and budgets for "the preprocessor re-declares every in-scope binding on every start tag it writes". The predicate remains sound because it charges every declaration seen so far against every start tag, which is an upper bound on what the new writer emits, and an over-conservative admission only costs a fallback to the authoritative two-pass path; but its prose is now wrong and its bound much looser than needed. That file is change 0657's in this wave. `performance_claim: none`. OLE2/OOXML remain active; ODF stays deferred until completion; iWork is excluded.
