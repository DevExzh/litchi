# OPC decoded-member splice contract

Status: design and implementation review for change-0482. This note records
the boundary required by the DOCX explicit-window append. It is not evidence
of a completed implementation or of a whole-process constant-memory result.

## Decision

The OPC owner should expose one source-backed decoded-member splice operation.
The operation replaces one existing Part's logical payload with a stream
produced from the verified source payload and a bounded insertion fragment. It
owns physical ZIP preservation and publication. A format crate owns the XML
grammar when the target is an XML Part, the insertion offset, and the
source/candidate proof; those responsibilities must not cross the crate
boundary. Non-XML Parts use the same bounded decoded splice and hash/length
proofs without the XML audit.

The public shape should be a narrow `SourcePartSplicePlan` (the final names
may change) issued by `SourceBackedPackage` after metadata and source-proof
checks. It may retain private package/part handles, a compact proof, and an
immutable bounded fragment. It must not expose `soapberry_zip` types,
`PreservationIndex`, ZIP entry IDs, archive locks, compression state, or a
physical member name as a format-level API.

The first milestone accepts a caller-owned `Arc<Vec<u8>>` fragment. The
fragment is charged against an explicit finite fragment limit before the plan
is issued, including the vector's retained capacity. The follow-up full goal needs a replayable authored producer so
64-, 256-, and larger-paragraph appends do not turn the fragment into an
unbounded retained buffer. That producer must be reopened for every source
proof, candidate proof, measurement, and emission pass.

## Existing hooks

The current source-backed OPC implementation already supplies most of the
physical foundation:

* `SourceBackedPackage::main_document_part` and `part` resolve catalog parts
  without reading ordinary payloads. `PartView::declared_uncompressed_size`
  gives a metadata declaration only; it is not a decoded proof.
* `PartView::with_verified_decoded_reader` and its accounting variant invoke a
  callback with a fixed-buffer `BufRead`, avoid the Part cache, drain and
  verify the complete entry, and make source/context failures primary. The
  callback result is retained only after ZIP verification succeeds.
* `SourceBackedPackage::source_artifact` and `SourceArtifact::write_to_stream`
  retain and reproduce the complete physical source. The exact no-op path can
  therefore preserve compressed bytes, ZIP metadata, signatures, opaque
  members, and trailing physical details admitted by the source policy.
* `SourceBackedPackage::write_changed_overlays_with_appended_inner` already
  builds a bounded `PreservationIndex`, copies untouched local spans and
  central records, regenerates selected members using their original Store or
  Deflate method, and wraps the sequential sink with source, context, output
  budget, chunking, and accepted-byte accounting checks.
* `PreservationIndex::write_replacing_with_replay` calls a logical payload
  callback once for measurement and once for emission. It preflights generated
  framing and the whole preservation layout before sink output, supports Store
  and Deflate, preserves every other member, and returns typed progress and
  `NonDeterministic` failures when the two callback passes differ.
* `ReplayLimits` bounds decoded member bytes, compressed generated bytes, and
  complete archive bytes. Replay uses fixed 64 KiB input and compression
  windows plus preservation's fixed source-copy buffer; compressor state and
  preservation metadata remain separate costs.
* `OpcOperationAccounting` already distinguishes decoded ZIP work, generated
  Store/Deflate payload bytes, raw unchanged source bytes, and accepted output.
  The splice path should merge both fresh source-reader passes and the replay
  publisher's low-level report before making the final source/progress decision.

These hooks are usable without the materialized `PartData` path. In
particular, `source_xml_part` and `xml_splice.rs` are not suitable for the
window operation: they load the complete member, retain an `Arc<Vec<u8>>`,
and assemble a complete candidate.

## Proposed plan and proof

The minimum plan should contain private fields equivalent to:

```text
source lineage and SourceVersion
source artifact identity (for exact inverse/no-op authorization)
target part identity and content-type classification
source decoded length and SHA-256
decoded insertion offset
fragment length and SHA-256
candidate decoded length and SHA-256
selected finite splice/replay/output limits
```

The plan must also record the source's compression method indirectly through
the OPC owner. A public format caller receives proof accessors only for
content-free scalars; it never receives a ZIP entry token.

The offset is a decoded-member byte offset. It is not a compressed payload
offset, a `quick_xml` normalized position, or an offset in a reserialized
candidate. The format scanner must prove that the offset is at the exact
start of the final direct `w:sectPr`, or at direct `</w:body>` when no section
properties exist. OPC should treat the offset as opaque and only enforce
`0 <= offset <= source_len` plus checked `source_len - removed + fragment_len`
arithmetic.

The plan is issued only after all of the following are true:

1. The source version and lineage are current, the target member exists once,
   and its declared size and physical topology fit the package limits. A
   changed publication refuses encrypted entries and signature infrastructure
   during preparation; exact no-op publication remains eligible for malformed
   or signed source reproduction.
2. A complete source pass has decoded and verified the member, computed source
   length/hash, and supplied the insertion proof. The format owner performs
   its source-compatible grammar checks in that pass.
3. The bounded fragment has a fixed length/hash and is produced under the
   format owner's grammar contract. It need not be a standalone XML document:
   a fragment may be a sequence of paragraphs or may depend on namespace
   bindings supplied by the retained source prefix. A fragment length of zero
   is a valid insertion only when the format operation explicitly defines it;
   for insertion-only plans, zero bytes plus a valid offset is mathematically
   the exact source no-op.
4. A fresh verified source reader has streamed prefix + fragment + suffix
   through the complete candidate validator. XML Parts receive the generic
   authored XML audit under the complete source context; non-XML Parts receive
   the same complete bounded byte stream and hash/length checks without XML
   parsing. The candidate validator has checked source length/hash, candidate
   length/hash, all format limits, and final structure where applicable before
   any publication sink is touched.
5. Candidate output length, selected-part limits, archive limits, and the
   preservation layout fit their explicit finite ceilings. Any arithmetic
   overflow is a typed refusal before output.

The candidate proof is content identity, not just a length check. The source
pass and candidate pass must each hash bytes as they are consumed. Publication
reopens the source reader and checks the same source proof again while writing
the prefix, fragment, and suffix. A non-deterministic fragment producer is a
typed failure; it must never be silently retried or replaced with a stored
copy.

## Publication sequence

`prepare` is a no-output operation. It should perform the following checks in
this order:

1. Check source version and execution context, then resolve the target member
   and its declared limits. For a changed publication, refuse encrypted
   entries and changed-signature infrastructure before touching the output
   sink; exact no-op plans take the source-artifact path.
2. Run a source pass through `PartView::with_verified_decoded_reader` (with
   accounting when requested). XML targets use the authored XML audit; binary
   targets use a bounded hash/length pass. The callback must be bounded and
   must not call `PartView::data`, `source_xml_part`, or any cache-populating
   operation.
3. Run the candidate pass through a second fresh verified reader. The
   `SplicedReader` or equivalent must expose only fixed-size reads and must
   not buffer the complete prefix or suffix. XML candidates are audited as a
   complete stream; binary candidates are drained and hashed as a complete
   stream.
4. Check source state, context/cancellation, all proofs, and output limits
   again. Retain only compact proof values and the bounded fragment.

`write_to` consumes or borrows the plan according to the final API and then
uses `PreservationIndex::write_replacing_with_replay`. The replay callback is
called exactly twice by the current low-level implementation. Each invocation
must open a fresh verified source reader and stream the same prefix, fragment,
and suffix; it must not reuse a consumed reader. The measurement callback
must be sink-free from the caller's publication point of view. The emission
callback must verify the expected logical measurement, source proof, candidate
proof, cancellation, and source freshness while writing.

The existing source-backed sink wrappers can be reused with small factoring:

```text
Counted -> SourceCheckedSink -> ContextCheckedSink
        -> OutputBudgetedSink -> Chunked -> PreservationIndex writer
```

The splice callback's logical writer is the replay writer, so its generated
Store/Deflate bytes are charged by `ZipOperationAccounting`; the outer sink
charges raw copied spans, central records, framing, and accepted output. The
final source decision must run after low-level ZIP accounting is merged:
`SourceChanged`, cancellation, and `IncompleteOutput` remain authoritative
over an accounting overflow or secondary callback failure.

An exact no-op must be decided before XML audit and before replay. If the
requested candidate bytes are proven byte-identical to the decoded source, the
plan uses `SourceArtifact::write_to_stream` and preserves malformed-but-
identical payloads and signed physical packages exactly. A no-op cannot be
inferred merely from an empty fragment or equal semantic paragraph count.
For a changed payload, the existing signature policy applies: observed
signature infrastructure requires an explicit strip/resign operation, which
this low-level plan does not provide.

## Error and source-freshness rules

The operation is a sequential, non-atomic sink API. Before the first accepted
byte, source, XML, limit, topology, cancellation, allocation, and callback
errors must leave the sink untouched. After accepted bytes, the result must
carry the accepted count through `OpcError::IncompleteOutput` or the replay
progress equivalent. The sink is never flushed or rolled back by a decoded
reader callback; the final preservation sink is flushed only after all local,
central, tail, and comment bytes have been emitted.

The source version is checked before each pass, periodically during scanning
and copying, after each verified reader returns, before preservation layout,
and after the final flush. A source change wins over a callback's parse error
or a low-level accounting error when both occur. Cancellation/context failure
has the same precedence as the existing `with_verified_decoded_reader` and
preservation wrappers. A callback error remains available as secondary
diagnostic data when ZIP verification reports a primary source/archive error.

The inverse path chooses the current candidate package's execution context
when it is managed, and otherwise falls back to the retained source context.
That selected context owns the one 64 KiB fingerprint/copy workspace
reservation and all inverse `InputBytes` and `OutputBytes` reservations. The
candidate and retained source versions are still checked independently, and
both retained and current contexts are checked for cancellation. This avoids
charging the retained source's output budget a second time when the current
candidate supplies the operation context.

The caller's execution context reserves the fixed verified-reader buffer and
output chunks, and consumes declared decoded work. The splice plan now keeps
separate reservations for retained fragment capacity and decoded-audit
workspace; changed publication reserves preservation metadata and
replay/compressor workspace before constructing the preservation index. XML
workspace is derived from `Limits::streaming_memory_upper_bound` plus the
adapter buffer; non-XML targets reserve the adapter buffer itself.
The preservation envelope uses the archive's exact central-directory/EOCD
metadata bytes and a conservative four-copy metadata envelope for retained
central records, generated target framing, ZIP64 promotion copies, and the
prepared tail. It also includes private layout sizes for each retained entry,
the twelve ZIP64 promotion ranges, and preservation's fixed copy buffer; the
standard index scratch buffer is reserved separately. The replay envelope is
provided by soapberry-zip from the private `ReplayPayloadWriter` layout, the
fixed 64 KiB compression output window, preservation's copy buffer, and a
locked-backend compressor allocation bound. These are caller-controlled finite
reservations, while allocator headers, caller sink storage, and private sink
buffering remain outside OPC's accounting.

## Physical preservation and security

`PreservationIndex` is the only physical rewrite authority. The splice path
must raw-copy every untouched local member, including non-part members, and
retain central record bytes, ordering, ZIP64 framing, data descriptors, extra
fields, archive comments, and source member names subject to the existing
validated layout policy. Only the selected member's logical payload and the
necessary generated local/central framing may differ. Store and Deflate must
be selected from the source entry and no other compression method may be
silently normalized.

The plan must reject encrypted archives/entries, trailing bytes outside the
located archive, ambiguous or mismatched local/central target names,
unsupported multi-disk or malformed preservation layouts, duplicate target
members, and any signature state that makes a changed source publication
unsafe. The exact no-op exception is deliberate and must bypass
changed-publication signature/XML rules while retaining the source artifact.

The format crate must not acquire `soapberry_zip` or physical ZIP types. OPC
should expose only content-free proof and publication errors, and should map
low-level ZIP errors to `OpcError` while retaining typed cancellation,
source-change, limit, allocation, and incomplete-output distinctions. A
changed signed or encrypted source is refused during preparation, before any
publication sink is touched; exact no-op preparation retains its source-copy
exception.

## Accounting and memory budget findings

The current replay implementation gives a bounded payload-window claim but not
a complete RSS claim:

* `ReplayPayloadWriter` owns a 64 KiB decoded input window, a 64 KiB Deflate
  output array, and a compressor object. The replay owner measures its private
  writer layout with `size_of`, adds preservation's 64 KiB raw-copy buffer, and
  reserves a conservative 512 KiB zlib-rs backend envelope. The envelope is
  derived from the locked backend allocation layout rather than a one-machine
  measured size and must be revised with a backend lock change.
* `PreservationIndex` owns one record object per central entry, each retained
  central record's bytes, local-order/index vectors, archive comment, and
  optional ZIP64 tail. `PreservationPlan`, prepared entries, local offsets,
  central patches, and generated framing add more O(entry-count + metadata)
  allocations during preflight. None is proportional to the decoded splice
  window and none is currently caller-supplied scratch.
* `write_changed_overlays_with_appended_inner` allocates an owned
  `RECOMMENDED_BUFFER_SIZE` scratch buffer plus replacement/omission lookup,
  count, action, and plan vectors. The replay path can avoid the replacement
  byte vector, but it still pays preservation metadata and layout vectors.
* `with_verified_decoded_reader` charges `Resource::Work` by declared decoded
  size and reserves the low-level reader's private fixed verification state.
  Deflate additionally reserves its 32 KiB compressed-input window, public
  decoder value, and conservative 64 KiB inflater envelope. The XML parser's
  input buffer, open-element/namespace state, token scratch, and fragment
  capacity remain separate reservations. These scalar owner bounds exclude
  allocator headers, caller reader/sink storage, and whole-process RSS.
* `OutputBudgetedSink` reserves accepted output chunks and commits only bytes
  accepted by the destination. This bounds output accounting but does not
  bound a sink's own buffering or a ZIP compressor's internal allocations.
* `OpcOperationAccounting` separates compressed/decoded read work, generated
  payload classes, raw unchanged source bytes, and total accepted output. It
  does not currently expose scanner scratch, preservation-index bytes, or
  compressor-state bytes; add counters only if the measurement contract needs
  those values, and keep them distinct from payload bytes.

Therefore the first implementation may honestly claim: no complete source or
candidate XML materialization, a bounded decoded reader/token window, finite
decoded/compressed/archive/output limits, and O(package metadata) preservation
state. The implementation now reserves the fragment's `Vec` capacity, XML or
binary audit adapter workspace, preservation owner bound, replay owner bound,
and selected inverse copy buffer before the corresponding operation. It still
must not claim O(1) total RSS or memory proportional only to the inserted
paragraph: package metadata and backend allocations are explicit finite costs,
while allocator overhead and caller-owned sink storage remain outside this
contract.

## XML audit seam

The current `xml_minifier::audit::verify` and `verify_authored` APIs accept
`&[u8]` and use a `quick_xml::Reader` over that slice. The splice operation
cannot call them on the source, prefix, or candidate without defeating the
window contract. The upcoming bounded reader audit API must preserve the
ordinary audit distinctions:

* source XML receives a complete well-formedness/structure audit under the
  source-compatible rules;
* a format-owned fragment may be a non-document sequence and therefore is not
  required to pass a standalone generic document audit; the format owner
  validates its generated fragment and namespace binding rules;
* the complete candidate receives the generic XML audit under the source
  context, after prefix + fragment + suffix have been presented as one stream;
* a compactness violation does not authorize skipping the remainder of source
  or candidate validation;
* malformed XML, token/depth/event/attribute/text limits, and I/O errors stay
  typed and fail before publication output;
* token bytes must be bounded before any parser call can allocate a hostile
  text or attribute token;
* hashes and decoded byte offsets count raw bytes consumed, not normalized
  event text.

OPC should depend on this seam only through a callback/error adapter. It must
not duplicate XML grammar policy or treat a format scanner's successful result
as permission to bypass generic XML audit. The source and candidate validators
may share one reader/scratch implementation, but source and candidate proof
must remain separate passes.

`SourcePartSpliceLimits` carries the XML audit profile explicitly. Its default
profile narrows the token window to 64 KiB; callers that need a larger OOXML
token can supply another finite profile with `with_xml_audit_limits` (for
example, a 4 MiB token window).

## API staging

The minimal practical implementation can be staged as follows:

1. Add an internal `SourcePartSplicePlan` record with target part index,
   offset, source/candidate proof, fragment handle, and finite `SpliceLimits`.
   Keep the constructor private to `SourceBackedPackage`; expose only
   content-free proof accessors and a `write_to_stream` method.
2. Add a package method that accepts the already-proved source/candidate
   scalar proof and a bounded shared fragment. It performs target/topology/
   signature/no-op checks and rechecks source freshness before returning the
   plan. Do not accept a raw ZIP entry ID or an unchecked compressed span.
3. Implement a private replay callback that calls the existing verified-reader
   hook twice, copies exactly `0..offset`, writes the fragment, then copies
   `offset..source_len`, and verifies all expected hashes/lengths. Refactor
   the existing sink wrapper stack only enough to reuse source/context/output
   error precedence.
4. Route changed publication through the replay preservation method and merge
   both decoded-reader and ZIP accounting. Keep exact no-op on the source
   artifact path.
5. Add tests for Store/Deflate, exact no-op on malformed and signed sources,
   invalid XML before output, source mutation/cancellation at every pass,
   decoded/fragment/output/archive limit boundaries, partial sink writes,
   untouched raw members, ZIP64/data descriptors, and fresh-reader callback
   invocation count. A separate allocation test must report preservation
   metadata and compressor state instead of calling it payload scratch.

This API is feasible with the current replay and sink framework for a
one-fragment milestone, provided the XML reader audit seam lands first and
the public contract says “bounded payload window plus package metadata.” A
full complete-window claim still requires caller-owned scratch or an explicit
bounded preservation index, and a replayable authored stream is required for
the larger append goal.

## Acceptance evidence

The current root-owned OPC focused run (`opc-dev-tests-04`) passed all 20
cases. It covers Store and Deflate publication, binary targets, signed and
encrypted changed-source refusal, malformed and signed exact no-op copying,
workspace quotas, accounting, cancellation, fragment work charging, and
inverse current-candidate output budgeting. The lower ZIP owner also carries
tests that exercise the private replay writer state and a long-name ZIP64
replacement layout; those tests are intended to run in the soapberry-zip
validation pass.

The implementation is ready for a performance result only when all of these
are directly demonstrated:

* source and candidate are validated from fresh decoded readers without a
  complete main XML, binary member, or candidate allocation;
* the final opaque `w:sectPr` span remains byte-identical and the generated
  paragraph is inserted at its exact decoded offset;
* exact no-op output equals the complete source artifact byte-for-byte,
  including malformed-but-identical XML and signed physical members;
* changed output regenerates only the selected member and raw-compares every
  untouched physical record and archive tail;
* source hash/length, candidate hash/length, insertion offset, cancellation,
  and finite limits are checked before output and during replay;
* XML and non-XML Store and Deflate outputs reopen successfully and report separate payload,
  raw-source, archive-output, package-metadata, and scratch measurements; and
* immediate inverse restores the retained source artifact, while a durable
  inverse without an explicit original replay source is refused.
