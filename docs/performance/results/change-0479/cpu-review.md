# CPU and syscall review

This review covers the retained normal-build diagnostic profile at 131,072
paragraphs (`total` mode, 30 samples after three warmups, CPU 2). It is a
whole-process profile and is excluded from the formal 24-report timing matrix.
The process includes corpus construction, independent XML/member/semantic
oracles, warmups, measured lifecycles, JSON report serialization, and teardown.
It does not isolate operation timing or authorize a performance claim.

The replayable arithmetic is in [`profile-summary.json`](profile-summary.json),
generated by [`profile-analysis.py`](profile-analysis.py). The parser weights
each `perf script` stack by the period printed on its sample header.

## Capture reconciliation

`perf script` retained 1,017 sample blocks: 1,012 for the benchmark process
(`docx_plain_para`) and five for the `perf` helper. Their period totals were:

| Population | Blocks | Weighted cycles | Share of all periods |
| --- | ---: | ---: | ---: |
| Benchmark process | 1,012 | 45,568,703,592 | 99.9999869274% |
| `perf` helper | 5 | 5,957 | 0.0000130726% |
| All retained blocks | 1,017 | 45,568,709,549 | 100% |

The all-process period total exactly equals `perf report --no-children`'s
`Event count (approx.)` of 45,568,709,549. `perf report` recorded zero lost
samples. The helper blocks are retained in the reconciliation but excluded
from target ancestry percentages.

The `perf stat` counters came from a separate normal process invocation, so
their cycle count is not expected to equal the sampling run's event count and
must not be subtracted from it. That invocation measured 45,360,449,734 cycles,
190,361,776,641 instructions, 38,029,370,097 branches, 142,458,513 branch
misses, 10,174,103 cache misses, and 37,201 page faults. The direct derived
ratios are 4.1966465888 instructions per cycle and 0.3746012954% branch misses
per branch. No cache reference event was captured, so the cache count is
reported as a raw event only.

The source-backed scanner is not wholly operation time. Of its weighted
30,143,230,391 cycles, 27,485,495,690 cycles (611 blocks, 60.3166066257% of
the target and 68.0373951135% of lifecycle ancestry) intersected
`run_total_iteration`; 2,657,734,701 cycles (59 blocks, 5.8323684711% of the
target) occurred outside that lifecycle, principally while constructing and
checking the corpus. The parser also reports a broad `scan_document` diagnostic
of 30,593,376,543 cycles (67.1368156903%); the difference is ten semantic
transaction-scanner blocks. The narrow source-backed marker is the value used
for the review.

The target ancestry outside `run_total_iteration` is 5,171,072,783 cycles
(11.3478602097%). This is why a whole-process stack share cannot be presented
as an operation-only timing fraction.

## Syscalls

The retained `strace -c` run observed 21,238 calls in 0.049722 seconds with one
error. The largest rows were:

| Syscall | Calls | Seconds | Share |
| --- | ---: | ---: | ---: |
| `brk` | 306 | 0.025210 | 50.70% |
| `write` | 19,025 | 0.021848 | 43.94% |
| `read` | 1,193 | 0.001268 | 2.55% |
| `openat` | 203 | 0.000640 | 1.29% |

This is whole-process syscall time. In particular, `write` includes JSON report
serialization and does not measure the in-memory hashing sink's logical writes;
the table cannot establish a sink syscall bottleneck.

## Next measured work

The next controlled implementation experiment should be the lowest-risk
same-contract ownership candidate: pass the already-owned target XML `Arc`
through the existing shared OPC publication method. Publication ancestry is
55.0894025465% of the target profile and publication is the largest large-case
phase in the formal phase measurements. The experiment must retain whole-source
recapture, artifact fingerprinting, XML validation, unchanged-member
preservation, inverse retention, and the existing failure matrix, then rerun
the same pilot and formal protocol so any change is attributable to the handoff
itself.

The profile also identifies the next parser/layout question if that experiment
does not account for the measured phase cost: evaluate a derived projected
range index or validated layout cache while keeping `scan_document` as the
parser authority. The 60.3166066257% lifecycle intersection is sufficient to
justify measuring that candidate, while the 5.8323684711% scanner ancestry
outside the lifecycle shows why the candidate must be evaluated with phase
attribution rather than by this whole-process percentage. Exact range-growth
and name-allocation accounting is a separate follow-up; the allocator's
requested-byte total is not evidence of physical copy bandwidth.

No candidate is approved by this review, and no speedup or bounded-memory
claim follows from these profiles.
