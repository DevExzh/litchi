# Remaining native and existing-append work

The six actual distinct native PPTX probes in `pair-probe.json` all refuse
`SharedOwner`: the selected layout/master/theme graphs differ. Their source
archives independently published in the earlier self-pair inventory. This is
concrete evidence that self-pair success does not establish cross-producer
compatibility. No source fixture was rewritten and no refusal was bypassed.
A broader static audit identified potential matching-layout fixture groups but
no verified successful distinct pair; those leads do not prove all local pairs
refuse. The next native harness must accept separate source and destination
identities, selected positions, complete image/chart closure and destination
preservation oracles. Native application execution remains absent.

The strongest bounded-append gap remains existing ODP logical tail append.
The 0439 control opens a complete owned snapshot, creates a transaction, appends
one plain title/body slide, commits and writes the materialized archive. At
8,192 slides it requests 236,704,188 allocation bytes and peaks 39,890,548 bytes
above entry, retaining 8,074,341 bytes with source and candidate alive. The
current source-backed ODP presentation is read-only and retains complete
`content.xml`. The common source publisher also accepts and clones a complete
replacement, reading the original content for comparison; its memory model
contains `replacement_len * 3 + maximum_member` plus metadata and fixed buffers.
Those APIs cannot prove a document-size-independent append window.

A complete next implementation needs a common source-member streaming XML
transform and a format-owned tail-append plan. It must copy source XML through
bounded parser/compressor windows, insert an audited plain slide, preserve
source lexical bytes and untouched package members, and retain source-version,
cancellation, finite resource and partial-output checks. Its owner must avoid
retaining complete source/output XML. Measure a separate append lifecycle
against the 64/4,096/8,192-slide owned control, including open, planning and
sequential publication, with a flat peak-memory slope and complete semantic,
member and source-identity checks. Fresh creation, adding a Part and arbitrary
repackaging remain separate scenarios.

The current direct shared-payload experiment removes a duplicate publication
buffer for already materialized and verified data. It does not implement the
streaming transform, logical append, or a bounded complete document lifecycle.
ODS row append and ODT paragraph append require the same common streaming
foundation plus their own semantic owners. The full non-iWork goal remains open.
