# 0720 qualification boundary

This is an untimed diagnostic of the current two structural walks, not a
candidate or native performance pilot. The actual owner is
`DocumentBody::from_xml`, returning `ParsedDocumentBody`; the 0719 next-step
note used the return type as the owner name incorrectly.

Build the standalone diagnostic against unchanged production source, record
public outputs, apply reversible exact-source tracing, rebuild and run twice.
Require byte-identical public JSON reports and repeated trace records. Restore
production bytes before final validation and cleanup. Keep source censuses,
binary identities, command receipts, instrumented source identity and trace
recipe. Never infer latency, allocation, RSS or throughput from this build.

The tracer activates only at the BOM-adjusted body boundary and records:

- each structural scanner invocation and event/consumed-byte count (range events
  are counted after initial node/depth/classification checks; alt events after read);
- exact per-call MCE offset inputs and selected outputs or error;
- raw/selected chunk metadata and raw/selected block ranges;
- exact boundary source digest, with source-order event-stage records.

Run the inherited 0712 public matrix and new depth, BOM, marker-text, foreign,
fragment and malformed controls. Also run real NumberedList and the same 200
paragraph generator used by the ordinary-save generated-medium selector through
the actual package facade. Public standalone probes are outside the body trace.
Setup calls have a separate label and are excluded from representative totals.

An optimization is not retained by this batch. A later candidate must retain
both independent MCE calls and their order, all offset vectors, each scanner's
namespace rules, capture suppression and limits, and earlier alt/MCE error
precedence over a deferred range error. Its acceptance requires new differential
and native edit/lifecycle/allocator evidence. A trace does not demonstrate that
one reader can preserve every resource or failure behavior.
