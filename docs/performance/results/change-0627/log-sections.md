## 0627 — the OLE2 readers get a range source, and the first price list for one

Evidence gap 4 of change [0587](0587-remaining-opportunity-survey.md) — three independent OOXML range-source mechanisms and **no** OLE2 one — is closed for XLS and PPT by fourteen opt-in selectors, none in `Case::DEFAULT`, over a caller-named real fixture supplied with `--ole2-file PATH`. Seven run the source-backed open, list, one-cell, all-cells (change 0605's walk) and full-text XLS scenarios and the PPT `SourceSnapshot::open` and `read_text` scenarios over `SimulatedRangeSource`; seven are owned-source controls for the same phases over the same bytes. The transport is change 0572's delayed arm in this harness's four parameters: **1 ms fixed service per request, no overhead term, 100 MiB/s, 64 KiB maximum range**. What the first baseline says, over 20 warm-ups and 50 retained samples per case on CPU 20, every count identical on all 50 samples of both transports: **an XLS open is not a small read** — 16 requests / 110,242 B on `WithCustomViews.xls` (66.5% of the file), 53 / 565,201 on `ConditionalFormattingSamples.xls` (40.3%), 40 / 317,171 on `54016.xls` (32.2%) — and **listing the worksheets after it is free**, the list scenario's counts being identical to the open's on all three. **The PPT open reads the file about twice**: 8 logical reads returning 779,264 B from a 385,024-byte file, 2.02×, split into 18 physical requests by the 64 KiB cap, because `SourceSnapshot::open` validates the complete CFB index and then takes a complete-artifact fingerprint. **Change 0605's whole-sheet walk is the most expensive thing a range-source caller can ask an XLS reader for**: `54016.xls` all-cells is 16,145 requests / 1,256,139 B (1.28× the file) against 66 for one cell — 16.2 s of modelled service for one worksheet — though the API it replaced would have been roughly 38,950 × 26 requests. Full text and all cells are the *same* read on that single-sheet workbook, 16,145 / 1,256,139 for both. Two typed refusals are frozen as scenario oracles and measured rather than dropped: `ConditionalFormattingSamples.xls` full text refuses (`Invalid record`) after 394 requests / 790,147 B, and `45543.ppt` one-shape text refuses (`unsupported dependency record`) after 73 logical reads / 792,661 B on a shape the eager reader reports with text. The point of the record is the denominator it hands the queue: **XLS-6**'s "+46 requests, a range-source regression" is now +46 ms of fixed service against a measured 53-request, 58.39 ms flagship open — a **1.87× open** — for a change whose retained upside is at most 30% of that open's instructions. Elapsed on the range leg is **modelled**: the configured service floor is 86.7–94.8% of every range median. A/A floor on the owned controls, same window: worst |p50| **1.71%**, all 17 rows inside it. `performance_claim: none`; no file under `crates/` changed; registry 457 → 471 names and the checked default catalog SHA-256 does not move. OLE2/OOXML remain active; ODF is deferred until completion and iWork excluded. [Record and limitations](0627-ole2-range-source-selectors.md); [retained evidence](results/change-0627/README.md).

## 0627 — a benchmarked dimension `docs/GOAL.md` names for both priority formats had no OLE2 measurement at all

Record: [0627](0627-ole2-range-source-selectors.md).

`docs/GOAL.md` names caller-supplied remote and range sources as a benchmarked dimension for OLE2 *and* OOXML. Change 0587's evidence gap table recorded that only one half of that had ever been measured: `SimulatedRangeSource` over OPC and XLSX, a dedicated `pptx_range_source` module and provider pacing on the OOXML side, and not one CFB, XLS, DOC or PPT case on the other. **The row closes for XLS and PPT and stays open for DOC and for CFB itself**, which is the honest reading of a gap that names four formats. The audit's own standard — that a claim be scoped to scenario, corpus, machine, build and metric — is what shapes the result: request counts, request bytes and request-size distributions are **measured** and identical across 50 retained samples of both transports; the request *sequence* is proved a pure function of fixture and scenario by a per-sample digest, which is change 0572's determinism property applied per selector; elapsed time on the range leg is **modelled** and labelled so, because the configured service floor is 86.7–94.8% of the median and, per changes 0447 and 0448, the delay counters are requested targets and not observed sleeping time; the corpus-wide rate of the two typed refusals met here is **unknown**, and deliberately left to change 0587's evidence gap 3 rather than guessed at. Two audit-relevant facts the record produces without proposing anything. First, the readers' admitted populations differ by scenario on real files: `ConditionalFormattingSamples.xls` opens, lists, answers a cell query and walks a worksheet but refuses full text, and `45543.ppt` opens but refuses the text of a shape its own eager reader reports with text — with four further real decks spot-checked refusing the same way, while `litchi-ppt`'s test for that API uses a generated fixture. Second, the audit's standing worry that "the measured path is not the path real files take" now has a measured instance in the opposite direction: a `SourceSnapshot::open` reads 2.02× its file before answering anything, which no in-memory selector had made visible. What this batch does not discharge: no DOC or CFB selector; one transport point; in-memory sources only, so the `fstat` per source observation on the `from_path` route that change 0587 identified is still unmeasured; and no save, edit or publication scenario runs over a range source. `performance_claim: none`; no file under `crates/` changed. OLE2/OOXML remain the active priority; ODF stays deferred; iWork is excluded.

## 0627 — what an OLE2 read costs a caller who pays per request

Change 0627 adds fourteen opt-in harness selectors and takes the first descriptive baseline of any OLE2 reader over a range source. Four real fixtures — `WithCustomViews.xls` (165,888 B), `ConditionalFormattingSamples.xls` (1,402,368), `54016.xls` (984,576), `45543.ppt` (385,024) — supplied with `--ole2-file PATH`, one release binary (SHA-256 `d40979be…8728fd1`), CPU 20 via `taskset`, 20 warm-ups and 50 retained samples per case, one continuous window. The transport is change 0572's delayed arm expressed in this harness's four parameters: 1 ms fixed service per request, no overhead term, 100 MiB/s, 64 KiB maximum physical range. Deterministic counts, identical on all 50 samples of both the range-source and the owned-source leg: XLS opens cost 16 / 53 / 40 requests and 110,242 / 565,201 / 317,171 bytes, and listing worksheets after an open adds **nothing**; one cell costs 24 / 62 / 66 requests; the whole-sheet walk change 0605 added costs 896 requests on `WithCustomViews.xls` and **16,145 on `54016.xls`**, where full text costs exactly the same 16,145 because the workbook has one sheet; the PPT open costs 8 logical reads returning 779,264 bytes — **2.02× a 385,024-byte file** — which the 64 KiB cap splits into 18 physical requests. Two typed refusals were measured rather than dropped, since a caller pays for the bytes read before the refusal: `ConditionalFormattingSamples.xls` full text refuses after 394 requests and 790,147 bytes (56.4% of the file), `45543.ppt` one-shape text after 73 logical reads and 792,661 bytes. Both of this record's per-case gates held on all 51 legs: every retained sample reproduced its frozen oracle, and every range-source leg produced exactly one `(offset, requested, returned)` sequence digest across its 50 samples. The paired medians are reported with the caveat that dominates them — the modelled service floor is 86.7% to 94.8% of each range median, so those rows price the configured model and not a network — against an owned-source A/A floor, measured in the same window, whose worst |p50| is **1.71%** over 17 rows. The use is immediate: change 0587 ranked **XLS-6** partly on "+46 requests, a range-source regression" and had to call that cost modelled; against a measured 53-request, 58.39 ms flagship open it is **+78.8%, a 1.87× open**, for at most a 30% instruction saving on the same operation. Gates on `tools/perf-baseline`, the only package touched: `cargo fmt --all -- --check` clean, `cargo clippy --release --locked --all-targets` clean with 0 warnings, `cargo test --release --locked` **513 passed, 0 failed, 1 ignored** in the library plus 12 + 2 + 4 across the binary targets, `cargo doc --release --locked --no-deps` clean, and 23 of 26 `tools/test_*.py` modules OK with three pre-existing failures reproduced at the base commit with this change's edits stashed. Selectable registry 457 → 471; `Case::DEFAULT` stays 41 and the checked default catalog SHA-256 does not move. No file under `crates/` changed; `performance_claim: none`. [Change and limitations](0627-ole2-range-source-selectors.md); [retained evidence](results/change-0627/README.md).

## 0627 — a new observation axis, and no boundary on it

Record: [0627](0627-ole2-range-source-selectors.md).

No production code changed, so no ADR boundary moved and no accepted hash changed. The new module reads exclusively through public APIs — `litchi_xls::SourceBackedWorkbook`, `litchi_ppt::text_edit::SourceSnapshot`, `litchi_cfb::OleFile` — over `litchi_core::ReadAt`, which the harness's existing `SimulatedRangeSource` already implements; no typed error, limit, refusal point, validation order, output byte or public API is reachable from it. ADR 0005's mandatory-validation clause is **observed and quantified rather than altered**: the CFB index validation, protected-container policy, source-version check and complete-artifact fingerprint that `SourceBackedWorkbook::from_read_at` and `SourceSnapshot::open` perform are inside the measured region, which is precisely why the PPT open reads 2.02× its file, and the two typed refusals the fixtures produce are reported verbatim with the byte and request cost of reaching them. Nothing was relaxed to make a fixture measurable; a refusal is frozen as the scenario's oracle and the phase is still measured, which is the same treatment `tools/perf-baseline/src/bin/xls_source_attribution.rs` already gives a refused full text. ADR 0003's bounded-resource rule is satisfied additively: `--ole2-file` introduces a **new** 32 MiB ceiling checked from `fs::metadata` before the module's single `fs::read`, and the retained request-sequence evidence is a per-sample digest plus a 32-triple preview rather than tens of thousands of triples. ADR 0006's preservation default is untouched because nothing here reaches a writer. ADR 0002's dependency direction is unaffected: the module lives in a separate Cargo project that already depends on every crate it names. No new `unsafe`, no `#[global_allocator]`, no `std::env`, no `Command`, no hidden global Rayon pool — the simulator sleeps on the calling thread — and no ambient I/O beyond the one bounded read of the file the caller names; three source-policy tests in `tools/test_perf_baseline_source_policy.py` assert all of that, mirroring the three change 0601 added for `producer_shape`. The default matrix is frozen: all fourteen variants are absent from `Case::DEFAULT`, a fourth policy test asserts it by name, and `test_corpus_manifest_v2` and `test_crud_coverage_index` both pass, which is the mechanical statement that the checked `catalog_sha256` and `content_set_sha256` did not move. Two generator identities, `litchi-xls-real-file-v1` and `litchi-ppt-real-file-v1`, are documented in `docs/performance/CORPUS_MANIFEST_V2.md` and deliberately **not** added to the family map, for the reason `litchi-xlsx-real-file-v1` is not: a caller-named file's licensing and provenance cannot be asserted by a static map. `performance_claim: none`. OLE2/OOXML remain active; ODF is deferred until completion and iWork excluded.
