# 0830 — XLSX public-edit allocation attribution

This isolated diagnostic packet profiles `Munka1!A1` replacement in the real
LibreOffice `dateAutofilter.xlsx` fixture. Production source is unchanged.
The frozen [plan](plan.json) separates qualification, native instrumentation
controls and Heaptrack captures. No profiler-observed timing is a native
latency result. Requested allocation bytes are not retained bytes or a peak.

The probe opens a fresh workbook before each timer. The public edit, commit,
nonempty-patch check and replacement of the old workbook are inside the timer.
Serialization, final owner drop, hashing and complete stored-cell readback
follow it. Every output must equal the pinned 0821 reference bytes.

The root coordinator executes all Cargo, probe, profiler and reader commands.
Agents prepare and review source only. `commands/` retains the start and terminal
receipt for each child plus its combined stdout/stderr. `inputs.json` freezes
production, normative, harness, corpus, driver and probe inputs. Offline reader
sources and every reader attempt are retained separately under `reader-attempts/`.
Failed attempts are evidence and are not overwritten by successful retries.

The isolated Cargo lock is seeded from the workspace lock, with every external
package identity checked in `lock-parity.json`. Rebuilds use two Cargo jobs,
release opt-level 3, thin LTO, one codegen unit, debug level 1 and unwind panics.
The second build adds forced frame pointers. Captures run serially on CPU 12.

These commands intentionally refuse to replace evidence. A new measurement
requires a fresh packet and target directory, updated base/paths and a new
input freeze. The Cargo manifest and recorded identities use the absolute
`/home/zhuhe/code/litchi` checkout; relocation requires an explicit new freeze.
Existing numerical evidence can be replayed after target cleanup:

```sh

```

The complete `analysis.json.gz` is deterministic gzip of the expanded JSON.
`summary.json` is a small projection generated by `summarize.py`. The initial
uncompressed analysis is preserved losslessly as `analysis-attempt03.json.gz`;
`analysis-storage.json` binds both compressed and expanded byte identities.

`heaptrack_reader.py` documents the pinned KDE 1.5.0 interpreted format.
Attribution requires exactly one matching edit-owner frame in the exact
executable module. Duplicate-owner, wrong-module and unresolved-frame
diagnostics remain visible. Inclusive caller rows overlap and must not be
summed. Native Rust allocator counters and Heaptrack's malloc interposition
are different measurement mechanisms; equality is not assumed.
