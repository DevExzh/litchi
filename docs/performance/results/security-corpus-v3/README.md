# Security corpus V3

This opt-in corpus binds 22 checked-in security fixtures to executable Rust
rows. Each fixture has bounded `bounded_read`, `validate`, and `preserve`
selectors, for 66 runnable rows in total. The rows cover signed, protected,
encrypted, macro-bearing, external-link, malformed OPC, CFB-boundary, XLSX
adversarial, and OOXML encryption vectors.

The ordinary performance baseline keeps its 201 default bindings. The security
rows are exposed by the separate binary and are never selected implicitly:

```text
cargo run --manifest-path tools/perf-baseline/Cargo.toml --bin security_corpus -- \
  --operation read,validate,preserve --json /tmp/security-corpus-v3.json
```

The command above runs one correctness iteration for every selected row. It
does not record elapsed time. Timing requires both `--measure` and the explicit
capture gate `LITCHI_SECURITY_CORPUS_CAPTURE=approved`; no timed capture is
part of this candidate.

The admission path obtains the filesystem length before reserving the source
vector, reads in bounded chunks, and rejects a growth race. ZIP rows use
`soapberry_zip::office::ArchiveReader` and `PreservationIndex` with limits on
members, metadata, compressed bytes, declared uncompressed bytes, and aggregate
bytes. Because `ArchiveLimits::max_files` counts non-directory members, every
central-directory entry is admitted in a separate bounded preflight before the
high-level index or preservation index is built. OPC rows pass the same 64 MiB
and 4,096/8,192 ceilings through `ReadLimits`, including an explicit total
central-directory entry admission before the OPC lazy index. CFB and OOXML
crypto rows use
`OleFile::open_with_limits` with a 512 KiB directory ceiling (4,096 128-byte
entries) and a 64 MiB allocation-table ceiling before index allocation. No
Python ZIP index is used for validation or row execution.

The catalog records the actual archive or CFB-stream hashes produced by those
bounded readers. ZIP relationship counts are `complete` or `refused`; CFB
containers report `not-applicable`. Every fixture has an explicit
`document_producer` value of `null` and a provenance classification that says
whether it is a third-party test fixture, a synthetic interoperability vector,
or a repository fixture whose author is unknown. No row executes code, fetches
an external relationship, or resolves a macro.

The shared ignored corpus harness uses the same explicit OPC, CFB, DOC, and XLS
profiles. Its XLS source snapshot path applies both object-capture limits and
the bounded CFB parser before publishing an editable snapshot.

`catalog.json` and `oracles.json` are generated by the executable with
`--catalog-dir`. `source-manifest.json` records the implementation and the
library oracle sources used for the bindings. The special msoffcrypto Agile
zero-DataSpaces-block fixture has a two-sided oracle: strict
`spaces::inspect` refuses the advisory zero block size, while the OOXML
compatibility reader accepts and decrypts the same bytes, with mode, clear
package digest, and Agile authentication checked. Producers remain unknown
unless the source provides evidence; synthetic interoperability vectors are
labelled synthetic. The `prior-v2/` directory retains the complete V2 artifact
for audit comparison without changing its contents; the sibling
`security-corpus-v2/` tree remains available as well.
