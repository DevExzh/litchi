# Change 0463 proof design review

This is a bounded design review for the ordinary ODP commit candidate at
baseline revision `c079b1c59`. It records the proof argument before any Rust
candidate implementation. No production source, build, or profiler was
changed by this review.

The review follows the accepted snapshot, validation, and measurement policy
in [ADR 0003](../../../../docs/adr/0003-snapshots-edits-and-patches.md),
[ADR 0005](../../../../docs/adr/0005-io-memory-and-performance.md), and
[ADR 0006](../../../../docs/adr/0006-validation-security-and-compatibility.md),
and the ODP ownership decisions in
[changes 0060](../../../../docs/performance/changes/0060-odp-snapshot-slide-projection-reuse.md),
[0065](../../../../docs/performance/changes/0065-odp-final-snapshot-handoff.md),
[0441](../../../../docs/performance/changes/0441-odp-shared-preservation-projection.md),
[0442](../../../../docs/performance/changes/0442-odp-shared-staging-traversal.md),
and [0443](../../../../docs/performance/changes/0443-odp-compact-fragment-frames.md).

## Design result

A private writer-origin proof is a plausible bounded optimization. The proof
can establish that every candidate XML member is either:

1. a member emitted through the ODF writer's authored XML path and accepted by
   its strict default audit, or
2. an untouched source member copied byte-for-byte from the exact immutable
   source package.

The proof must be minted only after the complete bounded writer succeeds and
the resulting bytes have been opened as an `OwnedPackage`. It may then let
`Transaction::commit` skip the final
`validate_compact_xml_parts_against` pass for that exact package, while
retaining candidate reopen, semantic readback, media checks, domain readback,
and patch construction. A missing, stale, ineligible, or conservatively
unprovable proof falls through to the current validator.

This is narrower and safer than trying to reuse `ContentSource` spans or a
generic XML splice token. `MutablePresentation::generate_content_xml` returns
only a `String`; its retained source skeleton is not an authored-audit or
whole-package provenance proof. The relevant implementation is in
[mutable.rs](../../../../crates/litchi-odp/src/authoring/mutable.rs), in
`MutablePresentation::generate_content_xml` and
`MutablePresentation::to_bytes_bounded`.

## Output origin coverage

The writer boundary gives complete origin coverage for a successful ordinary
serialization:

| Candidate member class | Existing production origin | Proof fact | Final-validator consequence |
| --- | --- | --- | --- |
| `content.xml` | `PackageWriter::add_file_with_media_type` from `to_bytes_bounded` | Whole candidate payload passed `verify_authored` with the common default profile | Candidate compactness is already proven under a stricter per-document profile |
| `styles.xml` and `meta.xml` | The same authored writer path | Same strict authored proof, even when their bytes happen to equal the source | Safe to include their actual lengths in the conservative bound |
| Staged XML-classified media | `add_file_with_media_type` before auxiliary copying | The writer audits every XML member it classifies as authored/changed | Include their count and bytes; broader classification is a safe overestimate |
| `META-INF/manifest.xml` | Generated by `PackageWriter::finish` unless source-manifest preservation is equivalent | Generated manifest is authored-audited; a preserved manifest is exact source bytes | Include a conservative generated allowance; preserved source bytes receive the existing source-equality treatment |
| Other source files | `copy_auxiliary_files_from_except` and exact-source writer publication | Payload originates from the source package bound to the proof | Candidate/source byte equality continues to authorize the existing skip |
| `mimetype`, directories, omitted signatures | Package transport or manifest bookkeeping | No candidate XML payload requiring this proof | No compact XML member is omitted from the relevant classes |

The origin split is visible in
`MutablePresentation::to_bytes_bounded`,
`PackageWriter::write_file`,
`PackageWriter::copy_auxiliary_files_from_except`,
`PackageWriter::preserve_source_manifest`, and
`PackageWriter::finish_into_writer_with_progress` in
[writer.rs](../../../../crates/litchi-odf-common/src/core/writer.rs).
The exact-source path is not treated as authored XML; it remains covered by
the final validator's source payload equality rule.

## Per-document limit implication

The writer's successful authored audit is sufficient for the final ODP
per-document audit because the default profile is equal to or tighter than the
ODP profile on every resource. `verify_authored` also rejects the additional
ambiguous-authored-whitespace case, so its acceptance is stronger than the
ordinary `verify` policy for the same limits.

| Resource | Writer `xml_minifier::audit::Limits::default()` | ODP final `audit::Limits` | Implication |
| --- | ---: | ---: | --- |
| Input bytes | 32 MiB | 128 MiB | Writer is tighter |
| Element depth | 256 | 512 | Writer is tighter |
| Parser events | 1,000,000 | 1,000,000 | Equal |
| Aggregate attributes | 250,000 | 250,000 | Equal |
| One lexical token | 4 MiB | 16 MiB | Writer is tighter |
| Character-data bytes | 16 MiB | 128 MiB | Writer is tighter |

The profiles are defined by
[xml-minifier audit](../../../../crates/xml-minifier/src/audit.rs) and
constructed for ODP in
[edit.rs](../../../../crates/litchi-odp/src/authoring/edit.rs), in
`validate_compact_xml_parts_against`. This implication applies only after the
writer has actually returned success; it is not a reason to bypass the writer
audit or candidate package reopen.

## Conservative aggregate eligibility

The final ODP validator charges `part_count` and `aggregate_bytes` only when
source equality fails, XML splice publication fails, and the fallback compact
audit is reached. A proof fast path must not assume that every authored member
would be charged. Instead, it uses an upper bound on every possible charged
authored member:

```text
authored XML bytes upper bound =
    actual content.xml bytes
  + actual styles.xml bytes
  + actual meta.xml bytes
  + actual XML-classified staged-media bytes
  + 32 MiB manifest allowance
```

The corresponding part-count bound includes the three core members, one
manifest member, and every XML-classified staged-media member. Require checked
arithmetic and eligibility only when the bounds are at most the existing
`MAX_PACKAGE_BYTES` and `MAX_XML_PARTS`. A bound overflow or an unrecognized
origin is a proof miss and must fall back to the current validator.

The 32 MiB manifest allowance is conservative for the *charged* case. A
generated manifest must pass the writer's default authored byte limit. When
`preserve_source_manifest` emits a raw source manifest instead, the source and
candidate manifest payloads are equal and the current validator charges zero
for that member; adding 32 MiB to the bound remains safe. The same reasoning
allows conservative overcounting of source-equal core members and splice
successes.

This is an optimization eligibility guard, not a new admission gate. It must
never reject a package merely because the proof is too large or uncertain:
the existing writer/package limits and the existing final validator remain the
only admission decisions. The proof branch must be selected only when the
bound proves that skipping the final scan cannot change aggregate-limit
acceptance. This preserves the old distinction that splice success avoids a
charge while fallback audit is chargeable, without paying the splice attempt
on an eligible writer-authored package.

## Ownership and provenance shape

A minimal private result can carry a proof beside the exact serialization
bytes, for example:

```text
SerializationProof {
    source_archive: Arc<Vec<u8>>,
    candidate_archive: Arc<Vec<u8>>,
    authored_xml_bytes_upper_bound: usize,
    authored_xml_parts_upper_bound: usize,
}
```

The exact field names are implementation details. The important ownership
rules are:

- `source_archive` is the immutable package used by the writer's exact-source
  copy path. It should be compared with the commit's source package by
  `Arc::ptr_eq`, which is stronger than a content hash and requires no new
  allocation.
- `candidate_archive` is minted from the `OwnedPackage` opened from the exact
  successful writer bytes. The final package must still have the same archive
  `Arc`; any later design, annotation, RDF, chart, or semantic-content package
  replacement therefore falls back automatically.
- The proof is returned with one serialization result and consumed by the
  commit that owns that result. It must not be cached as mutable presentation
  state: chart/content staging helpers may serialize an intermediate package
  before later edits.
- Checked counters contain no source content, retained span list, or unbounded
  allocation. A counter overflow is a proof miss, never a new commit error.

`Transaction::commit` already has the required lifecycle boundaries in
[edit.rs](../../../../crates/litchi-odp/src/authoring/edit.rs): the exact no-op
return precedes serialization; the initial candidate is reopened and compared
with the staged slides; subsequent domain operations reopen replacement
packages; and the final snapshot/patch is built only after validation. The
proof may not move any of those boundaries.

## Required fallback and behavior obligations

The fast path is valid only for the initial writer package whose source and
candidate identities still match. It must retain these behaviors:

- An exact no-op still returns the source snapshot and empty-domain patch
  without serialization.
- A multi-domain commit, intermediate package replacement, source-identity
  mismatch, missing origin record, counter overflow, or failed eligibility
  check executes the existing equality, splice, and compact-audit path.
- Candidate ZIP reopen, semantic slide readback, malformed-input refusal, and
  package bounds remain unchanged. The proof is not a replacement for
  `Snapshot::from_owned_package`.
- Media survival/removal checks, RDF/chart/design/annotation readback, atomic
  failure, and exact reversible `Patch` source behavior remain unchanged.
- Exact copied source XML may remain noncompact because the existing validator
  already skips it after source-payload equality. A generated member can enter
  the proof only after the writer's whole authored audit succeeds.
- XML classification should be conservative. Counting the writer's broader
  XML classification, including media-type and `.rels` cases, is safe even
  though the ODP final loop names `.xml` and `.rdf` parts.
- Proof eligibility must not change error precedence. Since the proof is
  minted only after successful serialization and consumed only after candidate
  readback, a hit introduces no new failure. Every uncertainty must fall
  through before the old final validator could have produced an error.

The common XML splice implementation remains the fallback authority for
source-bound edits. `XmlSourcePart::load`,
`xml_splice_publication`, and `XmlSplicePublication::assemble` in
[xml_splice.rs](../../../../crates/litchi-odf-common/src/core/xml_splice.rs)
still enforce source loading, well-formedness, source-range provenance, and
assembled-output checks whenever the proof is absent or inapplicable.

## Evidence and limits of the claim

The frozen 0463 protocol states the same hypothesis and binds the current
source epoch in [protocol.json](protocol.json) and
[baseline-binding.json](baseline-binding.json). The R1 baseline lifecycle
reports are retained under [runs/baseline](runs/baseline/); the report scope
includes `Snapshot::from_bytes`, transaction setup, add, commit, and sink
publication, with report assembly and drops outside the timed lifecycle.

The prior symbol-resolved diagnostic attribution is bound in
[prior-profile-binding.json](prior-profile-binding.json). Its inclusive shares
for the two diagnostic samplers were:

| Inclusive symbol | DWARF share | Frame-pointer share |
| --- | ---: | ---: |
| `MutablePresentation::to_bytes_bounded` | 29.98% | 27.41% |
| `xml_minifier::audit::verify_authored` | 14.63% | 13.94% |
| `validate_compact_xml_parts_against` | 9.87% | 11.95% |
| `xml_splice_publication` | 9.57% | 9.39% |
| `XmlSourcePart::load` | 6.88% | 7.54% |

These are overlapping sampled inclusive shares from the earlier diagnostic,
not independent ordinary-build timings or causal savings. They justify
measuring proof hit/miss and phase attribution; they do not establish a
speedup. The 0458/0462 phase evidence likewise identifies commit as the large
ordinary lifecycle phase but does not prove that final XML validation is the
best removable work. A candidate implementation therefore still needs the
frozen normal/allocator correctness and performance comparisons before any
production decision.

This design introduces no public API, dependency, ambient state, lazy
source-backed snapshot, or new ADR. It is a private proof-reuse candidate
under the existing atomic validation contract.
