# 0546 integrated candidate protocol

This campaign follows the passing frozen isolated scanner screen. It does not
reuse 0544 timing data. Main native, allocator, refusal, cap, conditional
instruction, hardware and eager lanes use fresh source-bound baseline/candidate
binaries. The runner records every command, raw output, start/end, source and
working-source manifests, binary custody and artifact hashes. Builds, quality
commands and captures are serial; source changes occur only between terminal
stages. CPU 2 and ABBA ordering are retained.

The baseline includes the expanded perf_cap_boundary benchmark. Candidate and
baseline compile that identical enabler. Numeric sizes 160/164/256 retain exact
old archive bytes; sizes 1/2 append a one-MiB comment to a valid worksheet and
span the sixteen-marker probe boundary. They add one XML event and preserve
numeric cell expectations. Planning alone is timed; source/editor/selector setup,
cell inspection, empty commit and exact source/publication assertions are outside
the clock. Every size/repeat must keep p50 AND mean within 1.05x baseline.

Original primary gates are unchanged: every shape/repeat must reduce workflow
p50 and mean by at least 3% and planning p50 by at least 10%. Ordinary planning
allocated bytes and peak live bytes may increase at most 1%. Refusal invalid
planning p50 must stay within 2x matched baseline valid p50 and invalid peak
within 1.10x matched baseline valid peak. Same-invalid adverse results remain
visible; an envelope pass does not erase those regressions. Calls/reallocations
are diagnostic. Region peak is not process RSS or an OOM guarantee.

All >5% individual latency/RSS/metric adverse and repeat-drift rows receive
explicit review without filtering or reruns. Only a passing native/allocation/
refusal/cap pilot admits conditional planning instruction, hardware and eager
captures; required instruction reduction is 5%, with existing eager/no-op and
quality requirements before retention. Failed pilot data remains authoritative;
restore production if a required gate fails. Retain the sparse benchmark enabler
and all evidence regardless of runtime admission. Source correctness and safety
are prerequisites, never traded for measured speed.

OLE2/OOXML performance remains the active priority. ODF is deferred until that
goal completes, and iWork implementation is outside this workstream.
