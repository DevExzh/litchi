# 0728 current DOC/PPT length-changing-save baseline

The 0617 fractions predate the implemented 0663 Reuse policy. Re-measure current
public DOC paragraph replacements and PPT slide removal, plus the common OLE
editor using exactly the replacement bytes produced by those format edits.
The common-editor path has separate open, staging and finish windows to price
its current validation/render/recapture lifecycle. Reuse and Rewrite are
existing policy controls, not baseline/candidate source variants.

Production remains unchanged. Source and oracle qualification precede a fixed
native process matrix. Preserve every raw process/sample, stdout/stderr and
source/probe/input/binary identity. Native timing uses the system allocator;
allocation instrumentation runs in separate processes with explicit lifetime
boundaries. Expected edited semantics, complete stream membership/content,
metadata and changed-length proof are checked outside timers. A stable hash
alone is not an output oracle.

Do not reinterpret a reduced-source container as a causal unchanged-byte cost:
its different directory and sector geometry changes more than the copied bytes.
Do not subtract medians of independent public-format and common-editor runs as
if they were nested phase measurements. Only measured phases within one
common-editor lifecycle support direct phase fractions. Any new caching or
copy-through design requires current measured benefit and separate qualification.
The existing 0652 placement decision and 0663 policy remain authoritative.

Current source qualification distinguishes format ownership: PPT finish writes
through its own OleWriter and source-layout adoption. A common-editor replay
of its exact changed streams is an alternative-container control, not a nested
public PPT phase. DOC uses the common batched editor, but its separate process
measurement still must not be subtracted from public-format medians.
