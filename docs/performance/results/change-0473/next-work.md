# Remaining streaming and append work

The public PPTX StreamingPresentationWriter is the next unmeasured OOXML
fresh-creation path. It retains an active slide plus ZIP central-directory
and member-name metadata proportional to part count. Its performance record
must measure and expose that structural term. A constant semantic slide window
alone cannot satisfy a claim of constant total memory as slide count grows.

Add a dedicated scalar-slide selector and operation allocator scaling matrix,
with an untimed complete topology/text oracle and timed zero-retaining sink.
Use the resulting profile to decide whether transport metadata must be spooled
through an explicit caller provider or accounted as a bounded structural term.
Do not redesign transport before measuring its contribution.

Keep fresh streaming creation, logical append to an existing structure,
package Part addition, and arbitrary modification/repackaging distinct. The
DOCX case closes only a missing measurement for its tested fresh plain-text
subset. Other append meanings, native application breadth, source variants,
parallel scaling, and larger measured edit bottlenecks remain open under the
full non-iWork goal.
