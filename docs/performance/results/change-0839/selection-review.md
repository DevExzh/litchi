# Target selection and boundaries

The previous turn was progress: 0838 independently reproduced a physical
inverse limitation using current public writers. It did not make the rejected
fresh OPC compression change adoptable. Current source remains 6b33c24b53.

Two read-only reviewers assessed the next work. Cached ordered-Part scheduling
has stronger measured benefit than the duplicate PPTX catalog seam: 0787's
six-block trial found 96.75–99.03% lower cached p50 in sixteen cases, but rejected
the candidate on the small/primed/zero-floor/width-four raw RSS guard. 0788 did
not reproduce that increase; 0789/0790 exposed accounting and launcher effects.
None proves the cause of 0787 or overturns its rejection. A fresh trial must
retain raw GNU-time RSS, distinguish observed residency from high-water
accounting, and measure operation allocation separately. The frozen plan keeps
the original conjunctive 5% guard and adds separate phase/allocation flags.
Historical timings and memory observations are not pooled with current results.

The duplicate PPTX catalog remains a bounded hypothesis, but current profiles
show only 11/8 capture self leaves for slide_references; that does not establish
practical savings. Cached scheduling already has direct thread-creation,
source-work and instruction evidence and materially larger observed latency
benefits, making fresh qualification the higher-return next action.

A second reviewer found no existing self-contained physical-inverse primitive
for arbitrary compressed bytes. SourceArtifact and splice publication preserve
an in-process source; provider-backed OriginalArtifactReference and exact restore
proofs require the original artifact to remain retrievable. Existing owned
precompressed payloads lack original local/central/tail geometry. A self-contained
capsule would need a new bounded ZIP/OPC owner API and versioned wire with
same-topology, descriptor, offset, ZIP64 and authenticated-splice rules. A
provider-backed envelope could instead reuse authenticated original-artifact
restoration. Neither design is implemented or authorized as an implicit change
in this batch. Existing v1 input fingerprints and exact regression tests stay
unchanged, as do preservation compression policies.

Root owns execution. Candidate and reader agents prepare archive-only code;
production changes, if any, are applied by root only after the baseline is
frozen, with the three exact base files retained for restoration. Unrelated
workspace edits remain outside the batch.
