# Normal 201-row control publication v2

This directory is a portable publication wrapper. The sealed evidence is
`publication-bundle.tar.gz`; extract it and run the inner `verify.py` from the
`normal-201-control-v2-20260910/` directory.

```sh
mkdir extracted
tar -xzf publication-bundle.tar.gz -C extracted
cd extracted/normal-201-control-v2-20260910
PYTHONDONTWRITEBYTECODE=1 LC_ALL=C python3 verify.py --root .
PYTHONDONTWRITEBYTECODE=1 LC_ALL=C python3 verify.py --root . --binary /path/to/litchi-perf-baseline
```

The timed workload is a normal, uninstrumented control capture from clean
source commit `995bdaf09352297bde17e6ed7d986360f8c10134`, tree
`7f02507971d036c174273bff0ad643c8338d6227`. That source is historical and is
not the latest publication HEAD. The publication documentation base is
`fdd2b80dfa9efc246a5983a3fec64de25e5c4f63`; no timed workload ran at that
revision.

The capture contains three fresh process repeats of 201 rows over 31 corpora,
with 15 samples and three warmups per row, on CPUs `0-7`. It is one control
baseline, without ABBA ordering or a paired optimization comparison. The raw
canonical result-key digest is
`f0fd76293959e72211e06e51b0a2b41f371423fda34c55144077193d262b1670`.

The publication retains the original analyzer plus two versioned analyzer-only
corrections. Version 1 fixes GNU time elapsed-label parsing. Version 2 changes
the canonical result-key digest final frame from NUL to LF. The exact v1 diff,
v1-to-v2 one-line diff, v1 history receipt, v2 defect receipt, fresh v2
analyzer execution receipt, and normalized derived output are sealed inside the
archive. Raw reports, catalogs, GNU-time envelopes, runner, source identity,
and external binary identity are unchanged.

The inner verifier recomputes all 603 retained row sample sets and their
harness p50/p95/p99 values, executes the v2 analyzer in a temporary directory,
normalizes the expected report paths, and compares the complete derived output.
It never runs a benchmark. The optional binary is external and checked only by
recorded size and SHA-256; no binary or build target is embedded.

The raw matrix emitted zero filesystem rows. `warm` and `cold-requested` are
harness selectors, not proof of physical eviction or cold I/O. Aggregate
payload throughput is unavailable because no row exposes a common
`execution.logical_bytes` denominator. RSS is GNU time whole-process maximum
resident set size, not operation-scoped RSS. The host was shared.

The two `preparer-verifier-*.json` files are fresh checks of the extracted
archive, generated by the packaging agent. `preparer-validation.json` records
those commands and hashes and deliberately makes no root-validation claim.

Root independently extracted the archive and ran its verifier with and without the historical external binary. Both checks passed; root-validation.json and the compressed root logs record these checks separately from preparer evidence.
