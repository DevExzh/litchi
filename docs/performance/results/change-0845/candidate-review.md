# Change 0845 archive-only candidate review

## Scope

This is an archive-only candidate for the source-backed OPC topology scan. It
was derived after reading the accepted physical-package and performance
contracts in ADR 0005 (I/O, memory, preservation, and measured optimization),
ADR 0006 (preservation and validation), ADR 0010 (archive ownership below the
facade), ADR 0011 (physical OPC ownership in `litchi-opc`), ADR 0024 (current
workspace topology), and ADR 0030 (the fallible lazy OPC access seam).

The candidate does not change production files in the worktree, does not add a
cache or hash strategy, does not alter a public archive representation, and
does not change any workload or build artifact. The only archived files are
`candidate.patch` and this review.

## Proposed change

`IndexedArchive::file_entries()` adds a `#[doc(hidden)]` method with the
following shape:

```rust
pub fn file_entries(&self) -> impl ExactSizeIterator<Item = (EntryId, &str)> + '_
```

It maps the immutable `self.order` slice to the corresponding immutable
`self.entries` names. The iterator therefore yields `(EntryId, normalized
name)` in physical local-header order, with the exact non-directory length.
The method performs no allocation, lookup, source read, or mutation.

The candidate uses that pair in two existing paths:

* `validate_topology_limits` keeps the same progress checkpoints, arithmetic,
  relationship classification, and error order, but obtains metadata with
  `metadata_for(entry_id)` instead of normalizing the name and looking the ID
  up again.
* `build_physical_member_lookup` keeps its first name-byte sizing pass and all
  reservation, folding, duplicate-count, and insertion behavior. Its second
  pass receives the already-issued `EntryId` instead of calling
  `entry_id(name)`.

The candidate deliberately leaves other `file_names()` callsites unchanged.

## Invariant proof

During `IndexedArchive` construction, every accepted non-directory central
record creates `EntryId(entries.len())`, inserts the normalized name into the
file index, and pushes the matching `IndexedEntry`. The same ID is then pushed
into `ordered_entries` with that record's local-header offset. After the
offset sort, `collect_order_fallibly` publishes those IDs as `self.order`.
Directory records are kept in the directory metadata map and physical layout,
but never enter `entries` or `order`.

`IndexedArchive` exposes neither `order` nor `entries` mutably, and the
archive's private state cannot be changed after construction. Consequently
every ID in `self.order` is a valid index into `self.entries`, and the name at
that index is the same normalized name returned by `file_names()`. The direct
index in the iterator is therefore backed by a constructor invariant rather
than an unchecked caller-supplied ID. The old
`indexed physical member disappeared during topology lookup` branch was
impossible for this immutable valid index and is removed only from the
second physical-member pass. `metadata_for(id)` returns the same central
metadata as `metadata(name)` for the paired name; no limit, progress, or
publication refusal is moved.

## Focused test

The added ZIP test uses the existing `fixture` and `central_record_len`
helpers. It physically writes `first.bin`, a `folder/` directory, and a
normalized `dir/../second.bin`, then reverses the central records. This makes
central-issued IDs `(second.bin = 0, first.bin = 1)` differ from physical
order `(first.bin, second.bin)` while retaining valid local offsets.

The test checks:

* exact-size behavior before each `next`, after each consumption, and after
  exhaustion;
* the ID/name pairs in physical order;
* `entry_id(name) == id` and `metadata(name) == metadata_for(id)`;
* normalized output for `dir/../second.bin`;
* directory metadata remains available while `folder/` is absent from the
  file-entry iterator; and
* the existing `file_names()` physical-order result remains unchanged.
