## Findings

1. **Semantic authority and fallback are preserved.** The shared traversal keeps the strict validator and ordinary worksheet parser as authorities ([validation.rs](../../../../crates/litchi-xlsx/src/cell_values/validation.rs#L193), [worksheet/mod.rs](../../../../crates/litchi-xlsx/src/raw/worksheet/mod.rs#L188)). Observer refusal, reader failure, parser-transition failure, formula presence, unsupported namespaces, MCE/extensions, and cap refusal disable only the proof and repeat the established validation/parse path. The proof callback cannot return a speculative parser error. The compact wrapper falls back to the complete scanner/writer whenever identity, layout, action eligibility, allocation, or writer checks refuse it ([package.rs](../../../../crates/litchi-xlsx/src/raw/worksheet/edit/package.rs#L173)).

2. **Source and Store pairing is checked before offsets are used.** `CompactLayout` retains the source allocation pointer/length and the parser `Store` entries pointer/length. The production source path retains the immutable `SourcePayload`, `Arc<Store>`, and proof in the same `Snapshot`; commit checks both identities before reading any compact span ([model.rs](../../../../crates/litchi-xlsx/src/raw/worksheet/edit/codec/snapshot/model.rs#L154), [snapshot.rs](../../../../crates/litchi-xlsx/src/cell_values/snapshot.rs#L427)). Rewritten worksheet payloads clear the proof ([snapshot.rs](../../../../crates/litchi-xlsx/src/cell_values/snapshot.rs#L704)). The source/store mismatch differentials therefore exercise the safety boundary rather than merely checking a fallback byte result.

3. **The compact action boundary is conservative and now explicit.** `compact_plan_eligible` requires existing rows and cells in parser order and accepts only `Action::Update` with `None`, `Set`, `Clear`, or `ClearIfPresent`; removals, shared formulas, shared strings, and future payload variants use the complete path ([package.rs](../../../../crates/litchi-xlsx/src/raw/worksheet/edit/package.rs#L258)). Public staging validates values and rejects unsupported cell dependencies before commit. The optimized production route is `MultiSnapshot::load_source_backed` plus `MultiSourceEdit::commit`; the single-snapshot `SourceEdit::commit` still uses the complete provenance writer. The benchmark's source-backed edit/save cases call `edit_sheets`, so this scope matches the stated campaign target. A broader claim about every source-backed edit would be incorrect.

4. **Offsets and lexical preservation have adequate static guards.** The proof receives parser-resolved row and cell addresses after transitions, retains only source spans, checks row/column monotonicity and cardinality, and validates source/layout span ordering before writing ([source_proof.rs](../../../../crates/litchi-xlsx/src/cell_values/source_proof.rs#L656), [package.rs](../../../../crates/litchi-xlsx/src/raw/worksheet/edit/package.rs#L210)). The changed-cell reader materializes a tag only for the changed cell and copies all untouched source spans. Namespace, attribute decoding, inferred addresses, empty forms, typed values, CDATA, dimensions, formulas, and error-preserving refusals are represented in the direct and integration differentials.

5. **The resource controls are bounded and fallible.** Shared traversal eligibility keeps the source below 8 MiB and 131,072 provisional events ([worksheet/mod.rs](../../../../crates/litchi-xlsx/src/raw/worksheet/mod.rs#L31)); the proof has a 2 MiB logical retained-state cap. Fixed metadata is charged up front, row/cell/stack capacity growth is checked before `try_reserve_exact`, and cap refusal drops all retained scratch ([source_proof.rs](../../../../crates/litchi-xlsx/src/cell_values/source_proof.rs#L100), [source_proof.rs](../../../../crates/litchi-xlsx/src/cell_values/source_proof.rs#L159)). Output and omission growth retain fallible reservation/refusal behavior. `MAX_PROOF_BYTES` is a logical proof-cache budget, not a total process/RSS budget; no new unbounded persistent allocation was found.

6. **The strengthened tests close the earlier review gaps for the accepted seam.** The direct tests compare compact and complete output bytes, omission spans, reduced readback, and semantic stores. They cover styled and empty cells, compact-only `Set`/`Clear`/style combinations, prefixed and rebound namespaces, inferred addresses, CDATA, dimensions, formula/shared-string fallback, source and Store identity mismatch, late attribute decode refusal, populated cap refusal, and proof-only refusal without stopping the parser. The 74-test integration receipt adds source revision/lineage, atomicity, inverse/recommit, multisheet, cancellation, dependency refusals, and the public exact-output/refusal cases.

7. **Allocation risk is inherited and remains a measurement item.** The complete scanner already materializes tags and cell primary spans for every cell. The compact path avoids retaining those tags for unchanged cells, but shared validation still copies element names, proof decoding checks every tag/attribute, and the changed-cell writer decodes the changed tag again. These transient allocations are source-size bounded and are not a correctness defect, but large-tag/large-cell latency, allocation count, and peak RSS need to be captured against the same baseline shapes. The proof-cache cap must not be presented as covering those validator/writer temporaries.

## Readiness and remaining gates

From code review, the candidate is ready for the frozen controlled capture now that draft-07 Clippy, no-default, formatting, and boundary checks pass. The capture must keep the draft-07 source manifest and candidate/baseline provenance separate, exercise the documented `MultiSourceEdit` scope, and measure stage, commit, publication, retained-memory, allocation/copy, and refusal paths at the planned p50/p95/p99 points. No performance result or speed/RSS claim is supported by this review.

Keep the status **PROVISIONAL HOLD for adoption** until the final quality plan (including full tests/check/rustdoc/performance-claim checks), candidate and baseline performance evidence, memory/allocation evidence, and final independent verification are complete. If a large-tag or large-cell profile shows an adverse transient peak, revisit the allocation policy then; the source review does not justify a speculative guard or a change to the compact proof boundary.
