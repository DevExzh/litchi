## 0639 — the gate list catches up with what two records already diagnosed

`docs/GOAL.md` makes correctness, bounded resources and safety the things speed may not buy, and the program enforces that through a gate list each change runs before it commits. Two records in the first wave showed the list has holes a per-crate gate cannot see by construction: change [0619](0619-harness-xls-lifecycle-assertion.md) found a test in `tools/perf-baseline` — a Cargo project outside the workspace — red for 54 records, and change [0629](0629-facade-docx-budget-test-bisect.md) found a facade test behind `#[cfg(feature = "docx")]` red for 94 commits, because `litchi`'s `default = []` means `cargo test -p litchi` compiles almost none of the facade's own tests. Neither was a regression; both were suites nothing selected. This record closes the reachability gap at the cheapest place CI already executes: two single-command modes in `tools/non_iwork_gate.py`, `facade-format-tests` and `harness-tests`, wired into the `non-iwork-release-gate` job before its long sweeps, with six unit tests pinning their argv and their invariants, and both green at the base. The audit should note what is *not* closed. First, both workflows in this repository trigger on `push`/`pull_request` against `main` only, and the performance program commits to `feat/office-format-completeness`; a change that never reaches a PR is still gated only by what its author runs, so the modes' value here is that the standing gate list can now name two commands, not that a robot will run them on this branch. Second, neither suite gained a test: this is coverage *of* a suite, not coverage of behaviour. The other two items are bounded-resource hygiene the goal document asks for directly. `refine_workbook_format` read its whole input into a `Vec<u8>` with no cap and had zero callers; change 0587 named it a latent hypothesis-1 ingress, and deleting it leaves `crates/litchi/src` with no production `read_to_end` at all. The `office_crud_demo` PPTX update took a route that refuses every opened deck; it now takes `opened_presentation_transaction`, and the resulting save is measurably a per-part delta — 42 of 43 members byte-identical — which is preservation-by-default demonstrated rather than asserted. Evidence tiers: **measured** for both gate legs' per-target totals and exit statuses on both the base and the branch, the 51 → 57 unit-test count, both demo runs and their exit statuses, every number in the 43-member census, the 0-caller and 66-line counts, the 8,086-page rustdoc comparison, and the two test-suite wall times that justify one gate flag; **modelled**: nothing; **unknown**: whether either newly reachable suite is adequate, and whether `detect_workbook_format_from_signature` — dead but bounded, and deliberately untouched — should exist at all. One gate fails and is pre-existing: `tools/check_example_targets.py` reports four cross-package duplicate example target names among `litchi-keynote`, `litchi-numbers` and `litchi-pages`, reproduced with identical findings and exit status on the untouched before checkout, in crates the brief excludes. `performance_claim: none`; no library operation was timed, so there is no floor to state. OLE2/OOXML remain the active priority; ODF stays deferred; iWork is excluded.

## 0639 — one unbounded ingress removed, one refusal respected instead of provoked, no boundary moved

Record: [0639](0639-gate-list-gaps-and-two-dead-paths.md).

No ADR boundary moved and no accepted hash changed. The only production edit is a deletion, and the item deleted was never reachable from outside its crate. ADR 0003's bounded-source direction is served directly: `refine_workbook_format` took any `R: Read + Seek`, called `read_to_end` into an unbounded `Vec<u8>` and then ran three detectors over the buffer. That is the ingress shape `docs/GOAL.md` hypothesis 1 names and the reason change 0587 flagged it as latent; with it gone, `crates/litchi/src` has no production `read_to_end` site. Nothing that validated stopped validating: the file's remaining classifier `detect_workbook_format_from_signature` is byte-identical and still refuses a truncated OLE2 prefix, still returns `Error::NotOfficeFile` for an unknown signature and still restores the caller's cursor on both the success and the failure path, with its four unit tests untouched. It is dead too, but it is bounded — at most eight bytes read — so it is not the ingress in question and is deliberately left alone, its inaccurate "public" allow-reason included. ADR 0006's preservation default is what the example change demonstrates rather than merely respects: `presentation_mut` still raises `UnsafeEdit` for an opened package, for the same reason, from the same code; the example simply stops asking for it and takes `opened_presentation_transaction`, whose commit publishes one patch that names the parts it touches and leaves every other part's name, content type, relationships and blob `Arc` alone — 42 of 43 members byte-identical on a real save. The gate work touches no ADR surface at all: two new modes are additions to `command_specs` that return before any existing selection is built, every Cargo invocation remains an argv list with no shell, and the new `harness-tests` mode stays inside the non-iWork slice by a unit test that fails if `tools/perf-baseline/Cargo.toml` ever declares an iWork dependency. No new `unsafe`, no weakened limit or malformed-input defence, no hidden global Rayon pool, no ambient I/O, no public leakage of archive types, raw locks or executors. Proposed ADRs 0030 and 0031 are not cited. `performance_claim: none`. OLE2/OOXML remain active; ODF is deferred until completion and iWork excluded.
