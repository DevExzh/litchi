# 0828 profile design

The fresh experiment localizes remaining CPU work after the shipped compaction
optimization. It does not compare old and new production or make an adoption
decision. Its three arms are ordinary/direct, ordinary/wrapped and frame-pointer/
wrapped. Six counterbalanced blocks use three warmups and thirty timed samples.
The wrapped/direct ratio estimates wrapper perturbation; fp/wrapped estimates
frame-pointer perturbation. Two separate perf captures use 2,000 edits each,
997 Hz user cycles, frame-pointer stacks, CPU 12 and no warmup.

Every report validates input, complete output bytes/hash, semantic text, slide
count and selected shape text. Three qualification reports precede native
capture. Expected totals are 23 reports and 4,549 samples. Every process runs
serially; no readers inspect new comparative values before all native and perf
commands are terminal. Root alone owns execution and Git mutations.

Stacks qualify only through the exact whole-edit symbol in the expected binary.
Qualified samples partition into capture, set-text, publish, unclassified and
ambiguous buckets using exact nested phase owners. The partition must be
exhaustive and mutually exclusive. Self-leaf censuses use that partition;
inclusive descendants overlap and cannot be summed as phase costs. Unknown
frames, empty stacks, lost events, maximum depths and possible truncation remain
explicit. Unwinding can hide an owner, so coverage is not proven complete.

Phase sample counts are descriptive CPU attribution under this probe. They are
not independently timed phases, wall-clock shares or an Amdahl model. Profiled
elapsed values stay separate from ordinary timing, and previous profile counts
are contextual evidence only. The result cannot establish fsync costs, cold
cache, broad producers, concurrency or general full-save speedup.

Five fresh probe quality gates precede release builds. Exact production quality
is reused from 0827 with source/lock/architecture and committed seal checks;
those are historical production checks, never reported as new Cargo runs.
Every root reader attempt retains its source snapshot and console output before
any correction. Frozen execution inputs and completed captures are immutable.
