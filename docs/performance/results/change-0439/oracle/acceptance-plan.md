# 0439 ODP existing append lifecycle acceptance plan

This is the independent acceptance contract for the opt-in
`odp_existing_append_lifecycle` selector. The machine-readable constants are in
`protocol.json`. The contract deliberately identifies the input archive as the
corpus and the committed archive as the operation output; it does not describe
the operation as a streaming or bounded-memory provider.

## Fixture and independent oracle

Use the existing 0437 buffered ODP title/body fixture without changing its
generator, text, or shape counts: 64, 4096, and 8192 slides. The source archive
has six members after adding the deterministic 64 KiB opaque member:

```
mimetype
content.xml
styles.xml
meta.xml
Opaque/litchi-perf-odp-existing-append-opaque.bin
META-INF/manifest.xml
```

The opaque bytes are regenerated by the verifier, byte by byte, with

```
for i in 0..65536:
    opaque[i] = (i as u8) * 37 + (i // 256 as u8) + 0x5b  # wrapping arithmetic
```

The verifier checks the full opaque bytes and SHA-256. It does not accept a
producer-supplied opaque hash as evidence. It also independently checks the
existing pinned `styles.xml` and `meta.xml` hashes, the exact ODF mimetype, and
the five manifest file entries. The archive must have six members, with
`mimetype` first and stored. XML compression claims are recorded only if the
archive reader exposes the method; the identity gate does not depend on an
unverified compression claim.

The source is reopened with an independent presentation/XML reader. Every
source slide must have exactly the expected title and body for its index. The
output must contain those same slides in the same order followed by exactly one
new slide. The appended title and body are the fixture functions evaluated at
`source_slide_count`, so the operation has no second corpus generator.

Three independent values are computed from the reopened text:

* the existing buffered semantic digest domain and length-framed title/body
  encoding, once for the source and once for the output;
* the canonical text projection, with `title + LF + body` per slide and `LF LF`
  between slides, with no trailing separator;
* a separate order digest containing each slide index and its length-framed
  title and body.

The source and output archive hashes, content XML hashes, semantic digests,
order digests, member bytes, and parsed manifest bindings are retained in the
source summary. The verifier computes these values itself from reopened
archives. A reported digest alone never passes a gate.

## Required operation behavior

Before warmups, build the source archive, validate it, and prepare one
expected output outside all measured iterations for the oracle. For each
iteration, clone the owned input bytes, construct the append title/body
strings, and create the sink before starting the clock. The measured region is
exactly:

1. `Snapshot::from_bytes` over the owned input clone;
2. `Snapshot::transaction()`;
3. one `transaction.add(append_title, append_body)`;
4. `transaction.commit()`;
5. writing every byte of the committed snapshot archive to the sink.

The clock starts immediately before `Snapshot::from_bytes` and stops
immediately after the sink accepts the final committed byte. Input cloning,
sink allocation, expected-output construction, hashing, diagnostics,
reopen/oracle checks, and drops happen outside the region. Process and
allocator endpoint observations happen before the source, transaction, commit,
and sink values are dropped. The sink must receive the actual committed bytes;
writing a precomputed expected archive is an acceptance failure.

After each measured operation, the verifier requires the sink length and digest
to equal the committed output archive length and independently computed output
SHA-256. It also requires the source bytes to remain unchanged. The operation
must report one changed/non-noop commit when that public signal exists, and
must always pass the independent one-appended-tail gate. It must not report
source read counters or imply source-backed access. An operation-scoped
committed-bytes-per-second value may be derived from accepted sink bytes and
the measured interval; it must not be described as end-to-end or physical-I/O
throughput.

## Report and sample acceptance

Keep the existing default selector count at 36. The new selector is opt-in and
must be included only when explicitly requested. The formal run contains 12
reports: normal and allocator modes, three shapes, and two repeats per
shape/mode. Each report has three warmups and 30 retained samples, for 360
retained samples total. Warmup samples must not enter latency or allocator
vectors. The planned CPU repetition count is two, with two separate large-shape
profiles.

Every report must include the existing operation metric schema. `sample_count`
is 30, `sample_indices` and elapsed samples are aligned by
`elapsed_ns.samples_by_elapsed_then_sample_index`, and every optional measured
allocator vector has the same 30 indices. Normal mode may omit allocator data
or mark it unavailable; it must not fill unavailable metrics with zeroes.
Allocator mode must provide allocation/deallocation/reallocation/failure
counts, byte totals, live endpoints, and region peak vectors. RSS scope must
identify the observed process phase and must not make a comparative claim.

The corpus manifest describes the source archive and source `content.xml`.
`CaseResult.output_sha256`, the source summary, and the sink identify the
committed output. For the lifecycle sink, `accepted_bytes` is output archive
length, `input_bytes` is the canonical output text projection length, and
`authored_part_bytes` is output `content.xml` length. This avoids confusing
source corpus bytes with the archive emitted by the edit operation.

## Focused tests required before measurement

These are source-level tests for the harness and oracle. They do not run the
formal benchmark.

1. **Selector isolation.** Parse the exact selector, reject unknown and
   duplicate arguments, prove the new selector is opt-in, and preserve the
   default 36-case count. Ensure the general synthetic corpus dispatch does
   not reach this dedicated lifecycle runner accidentally.
2. **Fixture determinism.** Generate each of the three source shapes twice and
   compare source archive bytes, member set, mimetype, styles/meta bytes,
   opaque bytes, manifest entries, semantic digest, and order digest.
3. **Source semantic gate.** Mutate a title, body, index order, duplicate a
   slide, remove a slide, and add unexpected text. The independent oracle must
   reject each mutation.
4. **Append gate.** Apply one transaction and require `changed`, a count of
   source plus one, and the exact prescribed tail title/body. Reject zero,
   two, or middle insertion edits; verify source bytes are unchanged.
5. **Untouched member and manifest gates.** Mutate or remove the opaque member,
   alter its bytes or length, alter styles/meta/mimetype, add a member, or
   change a manifest path/media type. The oracle must reject each output.
6. **Output binding.** Verify that a changed content archive with the source
   archive SHA, a sink with one truncated byte, a sink with one extra byte, and
   a sink containing expected bytes from another shape are all rejected.
7. **Timing and sink scope.** Use one tiny smoke iteration to verify that the
   sink receives committed bytes inside the timed operation, while oracle
   checks and all operation-owned drops occur after the endpoint. Verify the
   report says API plus committed-byte sink time, rather than whole lifecycle
   latency.
8. **Metric alignment.** Use a small synthetic sample vector to require 30
   entries, matching sample indices, warmup exclusion, and allocator fields in
   allocator mode. Reject missing, shifted, or zero-filled unavailable fields.
9. **Claim audit.** Reject a report that says bounded memory, source-backed,
   physical I/O, end-to-end throughput, or cancellation. An operation-scoped
   committed-bytes-per-second value derived from the measured interval is
   permitted.

## Reconciliation required from the append coder

Before applying the harness patch, reconcile only implementation names and
facts that the public API fixes:

* the exact `Snapshot` clone/transaction/commit accessors and the committed
  bytes accessor;
* whether the package writer preserves the six-member order and whether the
  opaque member is deflated or stored;
* the exact `SinkSummary` fields used for output archive bytes and canonical
  projection bytes;
* the existing report field name for the new `Odt/Odp` source summary;
* whether a public changed/non-noop commit predicate is available. If it is
  not, use the independent output identity and exact-one-tail gate rather than
  inventing a typed conflict or patch result.

These reconciliations must not weaken any identity gate or move any operation
across the clock boundary. If the writer uses a different ZIP member order,
the gate should continue to require the exact member set and `mimetype` first,
while recording the observed order rather than inventing an order guarantee.
