# 0508 semantic text-to-sink default expansion source review

This is a read-only source review of the proposed 0508 harness change. It
covers the existing `rtf_semantic_text_to_sink`, `odt_semantic_text_to_sink`,
`ods_semantic_text_to_sink`, and `odp_semantic_text_to_sink` selectors, their
generated corpora, timing boundaries, sink and output oracles, the default
identity update, and the conversion/export checklist mapping. No build, test,
benchmark, or production-source edit was performed for this review.

The source is coherent for adding these four existing selectors to the default
timing contract after the protocol's preflight and two full-run gates pass. The
change is harness coverage promotion. It does not add a format API, edit path,
producer compatibility result, or performance improvement claim.

## Supported harness scope

`SemanticShape::ALL` is the ordered set `tiny`, `medium`, `large`. The current
shape cardinalities are 24/200/10,000 paragraphs for the word/RTF fixtures,
3/12/100 slides for the presentation fixtures, and 1/2/2 sheets with
8/32/128 rows and the same number of columns for the spreadsheet fixtures
([`SemanticShape`](../../../../tools/perf-baseline/src/lib.rs#L712)). All four
default selectors use all three shapes.

| Selector | Corpus and shape closure | Semantic output and oracle | Default rows |
|---|---|---|---:|
| `rtf_semantic_text_to_sink` | Generated `litchi-rtf-semantic-v2`; plain RTF; 24/200/10,000 body paragraphs | UTF-8 body paragraphs joined with `\n`; the expected byte sequence is compared with the retained sink bytes and the report's byte/object counts | 3 |
| `odt_semantic_text_to_sink` | Generated `litchi-odt-semantic-v1`; 24/200/10,000 paragraphs | UTF-8 paragraphs joined with `\n`; the independent expected string, report counts, sink byte count, and SHA-256 digest are checked | 3 |
| `ods_semantic_text_to_sink` | Generated `litchi-ods-semantic-v1`; 64/2,048/32,768 stored cells, represented as 8/64/256 row objects | Each row joins stored cell text with tabs and rows with `\n`; the row oracle is derived independently from the full-cell oracle, then report counts, byte count, and SHA-256 are checked | 3 |
| `odp_semantic_text_to_sink` | Generated `litchi-odp-semantic-v1`; 3/12/100 slides | Each slide is title, `\n`, body; slides join with `\n\n`; report counts, byte count, and SHA-256 are checked | 3 |

The ODS row count is deliberately distinct from the cell count. The current
fixtures all have nonzero rows, so the writer's empty-sheet object rule is
represented in the oracle but is not exercised by a zero-row shape. The ODP
fixture builder replaces generated metadata with fixed bytes so its archive
identity is deterministic. All four fixtures are generated by the harness;
none is a native-producer file or an independent consumer round trip.

RTF's default `rtf_variants` configuration is `[plain]` ([`parse_options`](../../../../tools/perf-baseline/src/lib.rs#L11199)). The selector can be
run explicitly with `byte1252` and `lzfu`: CP-1252 contains a raw `0xe9` that
must become UTF-8 `café`, while LZFu decompresses to the same plain semantic
paragraph projection. The producer-watermark fixture is tiny-only and is
explicitly refused for this selector. Thus the default adds three plain RTF
rows; the optional transport coverage remains separate.

The four selector implementations are already routed through the existing
semantic runners. The RTF path is selected in `run_semantic_rtf`; the ODF
paths are selected in the corresponding ODT, ODS, and ODP runners. The default
list appends them after `odp_existing_append_lifecycle`
([`Case::DEFAULT`](../../../../tools/perf-baseline/src/lib.rs#L1538)). No
existing authoring, source-backed, filesystem, or iWork case is folded into
this expansion.

## Catalog metadata review

The frozen schema-2 input at
[`inputs/perf-corpus-manifest-v2.json`](inputs/perf-corpus-manifest-v2.json)
reproduces the prior 31 corpus objects and their existing catalog hashes. That
is the metadata baseline, not the final 0508 catalog. The preflight-derived
catalog must add one content object for each of the four selectors at each of
the three shapes, retain the old 31 objects byte-for-byte, and carry 43 corpus
objects with 213 timed bindings. `promote.py` then requires the Python
derivation to equal the Rust catalog emitted by the runner before it writes the
checked catalog and the coverage index.

The Python and Rust family maps agree on the four new generator IDs,
algorithm IDs, source functions, and shape parameters. New RTF rows retain
`legacy_v1.rtf_variant` and expose it as `generator.parameters.rtf_variant`;
the default rows therefore identify `plain` explicitly. If transport variants
are captured separately, `byte1252` and `lzfu` remain distinguishable corpus
objects rather than being collapsed into plain RTF. The `watermark` branch is
deliberately excluded from the deterministic family map: its bytes come from
the checked-in `test-data/rtf/watermark.rtf` fixture, so migration keeps the
legacy identity and archive hash but leaves generator kind, algorithm, seed,
source kind, and source path unknown. This prevents a producer fixture from
being presented as generated semantic coverage.

ODP uses the same catalog family label for two different generator IDs. Both
migration implementations discriminate on the full ID: `litchi-odp-existing-
append-lifecycle-v1` keeps its buffered base, append, and opaque-member
parameters, while `litchi-odp-semantic-v1` carries the 3/12/100 slide counts,
title/body templates, and the `\n`/`\n\n` text separators. The 0508 rows must
therefore resolve to `litchi-perf.odp-semantic-slides-v1`; they must not inherit
the existing-append algorithm or its 64/4096/8192 slide topology. Catalog
metadata leaves member inventories, relationship facts, security state, and
input validity explicitly unavailable or unknown where the runner has no
independent evidence.

## Timing and sink boundaries

Every runner constructs the expected semantic output, output/object ceilings,
and the parsed/preflight oracle outside the timed interval. The timed call is
the format owner's `write_text_to` method only. Report validation, digest
finalization, semantic verification, and retained-output comparison happen
after the clock stops.

The RTF boundary has a materially different sink than the ODF boundaries:

- `rtf_semantic_text_to_sink` parses each owned source before the clock,
  constructs `CountingSink::bounded(expected_bytes, expected_bytes)`, and
  reserves the complete `Vec<u8>` capacity before timing. The timed
  `Document::write_text_to` therefore measures the format's semantic traversal
  and conversion plus copying every output byte into the retained vector. The
  post-clock oracle compares `sink.bytes` byte-for-byte with the independently
  constructed UTF-8 text and checks the exact report byte/object counts
  ([`run_semantic_rtf`](../../../../tools/perf-baseline/src/lib.rs#L29206)).
  `CountingSink` reports `retained_output_bytes: None`; this row must not be
  described as zero-retention or as a hashing-only sink. The runner does not
  populate `CaseResult.output_sha256` for this text-to-sink case; its exact
  retained bytes and progress counters are the output oracle.

- The ODT, ODS, and ODP paths parse and fully validate their generated model
  before the sample loop. Each sample creates
  `HashingDiscardSink::without_authoring_window(expected_bytes)` and times
  only the format owner's `write_text_to`. The sink retains no output bytes,
  updates SHA-256 and scalar write counters, and reports
  `retained_output_bytes: Some(0)`. Digest finalization and deterministic
  write-call/largest-write checks are outside the clock
  ([`ODT`](../../../../tools/perf-baseline/src/lib.rs#L32075),
  [`ODS`](../../../../tools/perf-baseline/src/lib.rs#L33843), and
  [`ODP`](../../../../tools/perf-baseline/src/lib.rs#L35063)). These rows
  authenticate the expected semantic byte stream through its digest; they do
  not retain a complete output buffer for a later byte comparison.

The sink distinction makes the four latency series unsuitable for a direct
cross-format ranking. RTF includes a pre-reserved full-output memory copy;
ODF includes digest updates into a zero-retaining sink. Neither timer includes
archive parsing, RTF transport decoding, expected-output construction, package
serialization, or post-clock semantic verification. The ODF zero-retaining
sink bounds the caller's output buffer only; it is not a bound on the parsed
document model, semantic traversal scratch, or the whole process.

The positive harness paths use ceilings equal to the expected successful
output and do not add a 0508 partial-sink, over-limit, malformed-input, or
failure-injection matrix. Existing library contracts and earlier opt-in tests
remain their own evidence. No new failure-path or memory-efficiency claim
should be inferred from the default timing rows.

## Default identity preservation

The prior checked identity is 37 cases, 201 rows, and 31 corpora
([`prior manifest`](inputs/perf-regression-default-manifest-v1.json)). The
proposed `Case::DEFAULT` keeps that exact ordered prefix and appends the four
selectors in this order:

```text
rtf_semantic_text_to_sink
odt_semantic_text_to_sink
ods_semantic_text_to_sink
odp_semantic_text_to_sink
```

The 201 old rows remain 18 substrate cases × 4 corpus shapes × 2 payloads
(144), 3 writer cases × 3 shapes (9), 15 XLSX cases × 3 shapes (45), and the
3 existing ODP lifecycle rows. The new suffix is 4 selectors × 3 semantic
shapes (12), giving 41 cases, 213 rows, and 43 corpora: the prior 31 plus
three new generated corpora for each selector. The planned preflight and
full-run counts in [`protocol.json`](protocol.json) agree with those totals.

The preservation assertions in [`promote.py`](promote.py) are the right
identity gate: every prior case keeps its exact `case_corpora` list, every
prior corpus object remains equal, and only the four named selectors are added
to the default case set. The result-key digest must be recomputed for the new
213-row identity; it must not be presented as the old 201-row digest. Both
15-sample full reports must validate their actual rows before the four index
scenarios are promoted.

The 0508 documentation should update current default totals to 41/213/43 and
retain the historical 0501 and earlier 37/201/31 statements as historical
records. The prior 0286/0287/0288 records correctly describe the selectors as
opt-in, baseline-only evidence at the time; they should remain historical and
should not be rewritten into package or producer claims.

## Checklist mapping and blockers

The current `conversion-export` category names `Compact XML output` and
`Referenced XML is compact`. Those references are not applicable to these
selectors: the measured operation emits caller-owned semantic plain text, not
an XML package, relationship part, manifest, style part, or other referenced
XML. The runner has no package-output compactness oracle.

The planned [`promote.py`](promote.py) replacement with `Scope is explicit`
and `Performance claims are measured` is the appropriate mapping for this
default timing promotion. The exact format, shape, variant, output object
definition, sink, and timer are explicit above, and the full-run contract
requires actual report rows with at least 15 samples. `measured` here means a
checked default-baseline timing contract; it does not authorize a before/after
optimization claim or certify every CRUD checklist row. The index must retain
its representative coverage scope.

The following remain blockers to treating these rows as full format support
certification or as XML conversion certification:

1. The fixtures are generated semantic corpora only. There is no native
   producer version, independent consumer, native resave, source-backed
   provider, cold-cache, or filesystem evidence in this batch.
2. No package bytes are produced by the measured operation. Consequently,
   compact XML, referenced XML, package topology, untouched-member
   preservation, and raw archive identity are outside these rows.
3. The RTF default covers plain transport only. CP-1252 and LZFu are explicit
   read-only conversion controls; the watermark fixture is refused. They must
   not be silently counted as default coverage.
4. The simple generated ODF fixtures do not cover rich runs, tracked changes,
   notes, ruby, formulas, empty-row sheets, producer-specific extensions, or
   malformed/ambiguous structures. ODP's fused sink contract also documents
   that it does not promise full parser validation or error-precedence parity.
5. The zero-retaining ODF sink and pre-reserved RTF sink are output-boundary
   observations. They do not establish a whole-model, whole-transaction,
   allocator, RSS, physical-I/O, zero-copy, or fixed-memory claim.

These are scope boundaries, rather than blockers to adding the rows to the
default report once the custody, identity, and validator requirements pass.

One evidence-sequencing blocker remains in the capture workflow. `promote.py`
writes the checked identity, catalog, policy, and coverage index—and changes
the conversion category and scenarios to `measured`—immediately after
preflight, before either full report exists. The protocol requires mappings to
be promoted only after actual full reports validate. `verify.py` does perform
that later validation, so the files can be treated as provisional staging, but
they must not be published or sealed as a promoted result until `verify.py`
passes (or the measured-status write is deferred to that point).

## ADR applicability

| ADR | Applicability to 0508 |
|---|---|
| ADR-0003, snapshots/edits/patches | The selectors read immutable format snapshots and perform no mutation, patch, or concurrent composition. The snapshot boundary applies; edit/patch obligations are not newly claimed. |
| ADR-0004, semantic API design | `write_text_to`, `TextOutputOptions`, typed progress, and typed output-limit behavior are the semantic API used by all four rows. Formatting and active interpretations remain outside the plain-text projection. |
| ADR-0005, I/O, memory, and performance | Caller-owned sequential sinks, explicit output/object ceilings, and measured timer boundaries apply. The RTF retained `CountingSink` and the ODF zero-retaining `HashingDiscardSink` must remain separately labeled; neither supports a whole-process memory claim. |
| ADR-0006, validation, security, and compatibility | Visible semantic content is selected and inert/unsupported content is not interpreted. The harness does not add malformed, producer, signature, encryption, or preservation certification. |
| ADR-0007, Office object models | The rows exercise semantic conversion, separate from rendering and package authoring, with format-specific paragraph, row, and slide object models. |
| ADR-0008, migration and verification | The default expansion must keep the old identity exact and use actual full reports. The category remains representative; no format may be advertised as fully supported until its required checklist rows, including producer and preservation evidence, pass. |
| ADR-0009 through ADR-0011 | No detection ownership, generic facade archive ownership, or OOXML physical package ownership changes in this harness-only batch. |

All other ADR applicability remains unchanged from the current compliance
manifest. This review supports the bounded 0508 timing-coverage promotion with
the checklist-reference correction and the stated scope boundaries.
