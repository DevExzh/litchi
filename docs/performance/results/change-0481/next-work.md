## Implement the missing replay substrate

Follow `window-contract.md` with an OPC-owned decoded-member splice plan over
the existing preservation replay machinery. Keep decoded source insertion,
source/candidate hashes and lengths, source version, cancellation and output
limits explicit. DOCX must not acquire physical ZIP implementation types or
depend on ODF merely because its insertion owner provides a useful design.
Retain exact-source no-op and exact untouched compressed-member preservation.

Build the DOCX source and candidate scanners without complete XML or paragraph
range ownership. Bound tokens and parser scratch before proportional growth;
track only structure, counts, hashes and the decoded insertion point. Preserve
one final opaque section-properties span and insert before it. The authored
fragment must bind its chosen Word prefix locally using the source's admitted
Strict or Transitional namespace, so a source using another prefix remains
valid without changing its original namespace spelling.

One paragraph is the first substrate milestone. It cannot substitute for the
required replayable multi-paragraph producer, chunk release, durable patch
replay and large-stream scaling. Count caller-provided source/replay storage,
payload scratch, package metadata, compressor state and central-directory
storage separately. Missing replay or insufficient window capacity is a typed
refusal; no ambient plaintext spool is permitted.
