## 1. Slice 1: what landed

Slice 1 takes every property family whose engine already existed in
`litchi-iwa-style` or in a Numbers facade to all three formats, and moves the
Numbers-local property mappings into the shared engine so the three facades
share one vocabulary. 200 ledger rows flip (Keynote 96, Pages 96, Numbers 8).

| Crate | What |
|---|---|
| `litchi-iwa-style` | `series::{read, write}`: the bounded series-override engine for **any** `series::Property` (the symbol path's budget, now generic through a charged adapter: every payload a property reads or patches is admitted to the residual profile, and the generated-extension fields a patch changes join the source-derived `MutationScope` before publication); `series::visible_series` (the scatter/bubble series-count rule, formerly duplicated in Numbers and Pages); `series::Refusal` and `SymbolError::Refused`; `MutationScope::allowed_chart_fields`; object-container allocation and release now record the container object in the scope |

### 1.1 Public API (0351 shape)

| Format | Family | Read | Edit | Replay |
|---|---|---|---|---|
| Keynote | `chart::style` | `Package::slide_chart_style(slide, chart, PropertyKind)` | `edit_slide_chart_style(slide, chart)` → `Edit::{set(Property), reset(PropertyKind)}` | `apply_slide_chart_style` |
| Keynote | `chart::axis` | `slide_chart_axis(slide, chart, Axis, PropertyKind)` | `edit_slide_chart_axis` → `Edit::set(Axis, Property)` | `apply_slide_chart_axis` |
| Keynote | `chart::series` | `slide_chart_series(slide, chart, PropertyKind)` | `edit_slide_chart_series` → `Edit::{set(Property), reset(PropertyKind, series)}` | `apply_slide_chart_series` |
| Pages | `chart::{style, axis, series}` | `body_chart_{style, axis, series}(selector, …)` | `edit_body_chart_{style, axis, series}(selector)` (by-value builders, as the other Pages chart families) | `apply_body_chart_{style, axis, series}` |
| Numbers | `sheet::chart::{style, axis, series}` | unchanged | unchanged; series gains the affix and number-format properties | unchanged |

Each family has typed `Error`/`LimitKind`/`Refusal` (the Keynote and Pages
style and axis families share their format's chart-property error type,
re-exported per module), an exact-source `Patch` with `inverse()` and exact
no-op, candidate reopen and readback, and no native identifier, UUID,
archive name or protobuf value in a signature. Two existing signatures change
deliberately (no alias, per 0350): Keynote's `slide_chart_series` and Pages'
`body_chart_series` now take the `PropertyKind` to read, and Keynote's series
`Edit::set` takes a `Property` (it took a symbol vector). The parity and cost
callers migrate in the same slice; no other caller exists.

New refusals: `SeriesNotFound`, `NotResettable`, `SharedStyle` (Keynote),
`ImageFill`, `UnsupportedAxis`, `MissingStyle`. Image series and symbol fills
stay refused (`ImageFill`) until the media-backed image fill lands (§6).

### 1.2 Strict admission

The Keynote and Pages facades publish every new property through the same
path as their 0400/0401 symbol routes: the transaction budget admits the
workspace census and construction, the engine runs under the residual
profile and returns the bounded report (charged once), publication is
prepared and admitted before encoding, the candidate is reopened under the
source limits, and locality is verified against a plan built from the
engine's source-derived scope. For the generic properties the scope is the
series graph (as for symbols) plus every generated-extension field the
engine's own patch changes (computed on the source side before
publication); chart- and axis-level writes carry an in-place scope (the one
style object, its member and message type). The Numbers families keep
their 0378/0408 publication paths unchanged: the series-style publication
admission and accounting of 0408 are untouched (only the payload rules moved
into the engine), and the new affix/number-format properties use the
existing Numbers series-override path.

## 3. Parity

The Keynote and Pages cases are mechanical ports of the Numbers chart cases
(`numbers_chart_{style,axis,series,series_style}_cases.rs` →
`{keynote,pages}_chart_*_property_cases.rs`): the host routes differ only by
their container argument (slide index; none for Pages), the leaf position of
the host-added chart (Keynote: the slide's second chart; Pages: the body's
only discoverable chart) and the publication policy. The port script is kept
outside the repository (`.coord/iwa-w4c/tools/port_parity.py`) and records
every rewrite it applies. Properties the host does not have for a format are
dropped from its port (Keynote: legend visibility — a separate W1-C family —
and hidden data; Pages: hidden data).

Findings fixed while porting:

- Keynote's `inverse_mutation_plan` kept no deleted members, so replaying the
  inverse of an edit that created an object-container member (unstyled
  wedge/label overrides) failed locality; it now deletes the members the
  forward edit created.
- The engine did not record the object-container object in the scope; it
  now does (allocation and release).
- Pages' package-metadata check compared component registrations by
  position; a new container component shifted them. Registrations now match
  by component identifier, and additions/removals must be planned members.
- Numbers' patch replay table (`apply_series_patch`) had a fixed list of 12
  property kinds; it now covers the two new ones.

The full parity target passes: 875 tests, 128 ignored probes (§7).

## 4. Shared facade pattern

Keynote and Pages each have one private chart-property core (`Ledger` in
`slide_chart_series.rs` / `body_chart_series.rs`) with `target`, `read`,
`write` (engine closure → scope → publication), and `reopen` (patch replay
with locality), plus `artifacts`/`noop_artifacts`/`authorizes`. The style and
axis families (`slide_chart_style.rs`, `body_chart_style.rs`) are ~600 lines
each of family types around that core; the Pages file is derived from the
Keynote one with the selector and builder differences applied.
