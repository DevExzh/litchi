# 0362dvi — paired DrawingML raw qualification protocol

This record adds the source-fenced paired protocol and real endpoint adapters
for the five raw DrawingML lanes plus the four detached-owner transitions. The
adapter constructs or edits each lane
through the shared `litchi-drawingml` APIs, then performs the bounded read,
write, mutation, replay, and refusal checks outside the timed region. The
paired runner remains the only component allowed to make a source-fenced
performance claim; the endpoint itself fails closed when an API route or
typed refusal is missing.

The reviewed plan is
`drawingml-additional-qualification-plan-0b8e1744d1.json`, whose SHA-256 is
`d671c2dbd793d6b1b68c0aae25def384d6ceb44169be93b7daf848d6f13044f9`.

## Workload contract

`tools/native_qualification/manifests/drawingml-raw.json` describes the five
raw lane profiles, the theme-family route profile, and the four owner route
profiles. `drawingml_raw_paired_runner.py` materializes each endpoint profile
into the generic guarded native runner, retaining its Cargo path validation,
20-GB target/address-space limits, unrelated-process guard, fresh child
processes, and exact `baseline,candidate,candidate,baseline` order.

Each profile runs three warmups, five ABBA blocks, and twenty samples per leg;
the adapter must calibrate each accepted leg to at least 150 ms (target 500
ms). Normal and allocator probes are separate binaries. Allocator output is
non-claimable elapsed data and reports direct/reallocation bytes, live-balance,
incremental peak-live, and process RSS independently from normal timing.
Each report also records the kernel-maintained whole-process `VmHWM` high-water
mark; this independent receipt catches an allocation/RSS peak that falls
between the timed sample observations.

The required matrix is small/near-limit/at-limit/over-limit/malformed input;
entry/read and `read_shared` where supported; source-preserving no-op and
changed commit; forward, inverse, and stale replay; bounded `Vec` write and
`write_to` sink; and preflight refusal before allocation or the first sink
write. Fidelity and typed-refusal checks are outside the timed region. The
tracked fixture descriptor contains meaningful mutations; large boundary
inputs are generated by a final adapter and are never committed as evidence.

The endpoint matrix is capability-driven and raw and owner endpoints are
separate profile pairs. Raw-only parts never receive a
synthetic package-edit row: the diagram data model, text body, SVG blip,
model3d, image blip, theme palette codec, geometry, color, and `formatcode2`
rows are covered only by their raw endpoint. The actual DrawingML owner rows
use the production shared editors: chart
`Package::edit`/`Edit::commit`/`Package::apply`, theme-family
`Package::edit`/`Edit::commit`/`Package::apply`, strict InkML `Prepared` plus
`Edit::from_profile`/`commit`/`Prepared::apply`, and transform
`Package::edit`/`Edit::commit`/`Package::apply`. Their outside-clock proofs bind the
source, changed, forward, inverse, and typed stale-refusal identities. The
owner receipts retain the native stale-error identity (`Error::Invalid` with
the route-specific legacy reason before the owner transition, and
`Error::PatchConflict` after it) and verify that reason before normalizing the
paired classification.
chart, theme-family, InkML, and transform owner routes are deliberately
fragment-level; host package placement remains outside this paired raw
qualification.
Replay rows retain prebuilt source recipients (`Package`/`Snapshot`, or the
strict Ink `Prepared`) and apply only the already-prepared patch inside the
timed operation; source parsing and recipient preparation happen before the
first timing sample.
`read_shared_when_supported` is capability-driven as well: it times only the
formatcode2 and theme-family shared readers and emits an explicit N/A receipt
for lanes with no shared-reader API. The complete Theme-family raw route also
executes and records the source-backed `add_family`, `replace_family`, and
`remove_family` operations outside the timed rows, with source/output hashes
and parsed-owner checks. The 11728 baseline uses its explicit
`*_with_limit` entry points; the candidate uses the current `part::Limits`
policy. The 11728 baseline nevertheless enables only the independent
Package/Edit owner feature: that parent already has the current owner shape
but still lacks `part::Limits`. The candidate enables the owner, Theme-part,
Theme-owner, Ink-policy, and transform-policy gates. This
route is not conflated with the detached fragment owner pair.
The Ink action reader has a third, independent
`drawingml-ink-limits-current` gate: historical parents retain the
one-argument reader, while the candidate passes `actions::Limits::DEFAULT`
explicitly.
The transform owner has a separate `drawingml-transform-limits-current` gate:
historical `Package::from_xml` takes one argument, while the candidate passes
`transform::Limits::DEFAULT` by reference.
The Theme-family owner has its own
`drawingml-theme-family-owner-limits-current` gate because historical parents
already have the raw part limits while their detached `Package::from_xml`
constructor remains unbounded.

The adapter's capability matrix distinguishes production sink routes from
Vec/String-only codecs. Bounded-sink rows call only the former (chart,
formatcode2, SVG, model3d, theme-family fragments, Ink actions, and
transform); diagram, text body, image blip, theme palette, geometry, and
color remain raw read/Vec-write routes and receive an explicit sink N/A rather
than a synthetic stream claim. The chart boundary is the real MCE default
input policy (256 MiB, classified as `mce_input_bytes`), while geometry also
has a 1,025-path structural boundary against the 1,024-path reader limit.
Preflight records both the production typed refusal and, where a stream API
exists, a zero-write bounded-sink refusal.

Canonical raw fixtures are checked by an outside-clock second decode/encode
oracle. Routes promised source preservation must reproduce the exact source
bytes; diagram remains canonical while Ink action profiles retain and stream
their exact parsed source, including the changed lexical fixture.
Timed rows execute only their named production
operation: digesting, JSON receipt construction, and fidelity/refusal
validation occur in the detail pass after timing. Each RSS receipt is bound
to the child PID, command-line SHA-256, source revision, and kernel
whole-process `VmHWM`; allocator reports repeat those identities.

The endpoint coverage is explicit: chart authoring/reader/writer plus
`formatcode2`; SmartArt data-model edits and drawing relationships; text-body,
SVG blip, model3d, and image-blip readers/writers; theme palette/font codecs,
`themeFamily`, and strict InkML actions; and custom geometry, color,
`formatcode2`, and transform codecs. The allocator binary wraps the system
allocator only in its own process and records direct allocation/deallocation,
reallocation old/new bytes, live balance, peak-live delta, conservation, and
independent RSS. No std-only stand-in or all-unavailable adapter is accepted.

The validator rejects missing rows, altered ABBA/sample thresholds, short
accepted legs, allocator elapsed claims, missing source/fixture bindings, or
a qualified report without API-backed fidelity and typed refusal receipts.
It also requires the complete sample timer sum, exact source/changed/inverse
hash receipts, preflight zero-write evidence, and allocator conservation with
separate direct/deallocated/reallocation-old/reallocation-new/live/peak
counters. An unavailable report remains a valid non-claim control for source
preparation tests, but the real endpoint never emits one for a lane it was
asked to run.

Preparation (no Cargo or native execution) is performed per endpoint profile.
Raw and owner receipts are separate. Owner routes use the common pre-owner
`945eb1d6b9ef6c56fa26c82e12758d38c1b9015d` source for the before leg and the
current `Package`/`Edit` adapter feature for the candidate leg. The
`2d330c…`/`f40464c5…` chain is after that owner transition and is therefore not
an owner baseline; it can only support its typed-producer-limit history.

```sh
python3 tools/native_qualification/prepare_drawingml_raw_inputs.py \

  --candidate-revision "$FINAL_CANDIDATE_SHA" \
  --candidate-workspace-lock-sha256 "$DRAWINGML_CANDIDATE_WORKSPACE_LOCK_SHA256" \

  --perf-lock-sha256 "$DRAWINGML_CHART_PERF_LOCK_SHA256" \
```

bindings:

```sh

  --manifest tools/native_qualification/manifests/drawingml-raw.json \
  --phase build --cpu "$CPU"
python3 tools/native_qualification/drawingml_raw_paired_runner.py \
  --manifest tools/native_qualification/manifests/drawingml-raw.json \
  --phase abba --cpu "$CPU"
```

Outputs, binaries, targets, logs, and measurements remain external. Only a
small reviewed receipt may be committed later; no benchmark binary or large
raw evidence belongs in this repository.
