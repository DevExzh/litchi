## Timing clarification

The lazy ODM entry path intentionally moves one error boundary.  `edit_title`
no longer reads or decodes the raw `meta.xml` part while constructing an edit.
For a changed title, `title::Edit::commit` still performs that read, UTF-8
conversion, bounded parse, patch and readback, and returns the same family
error before publication when one fails.  An exact no-op now returns the
source without touching that raw part.  Thus the changed-commit error and
security/limit behavior is preserved, while raw `meta.xml` errors that could
previously occur at edit construction are deliberately deferred to changed
commit.  ODB mutator and commit errors retain their existing boundaries.
