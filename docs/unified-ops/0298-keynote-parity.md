## 1. ADR 0034 W1 for `litchi-keynote`

Commits `a7e561483c`, `bee0c2e0bc`. Every old public name is deleted, not
aliased; the glossary profiles `keynote-minimal` (253 bans) and
`keynote-full` (`internal-iwork-source`, 252 bans) enforce it.

- **Projection.** `Document` → `presentation::Presentation` (root
  re-export); `Package::presentation()` replaces `semantic_snapshot()`.
  `Presentation` keeps its archive-free ingress because it is the only
  reader of app-authored package directories (the facade's
  `litchi::iwork::Document` uses it). `presentation::{Stats, IoKind, Error,
  LimitKind}`.
- **Limits.** New `limits` module mirroring the ODF idiom:
  `SourceLimits`/`SourceLimitsBuilder`/`SourceLimitKind`,
  `SemanticLimits`/`SemanticLimitsBuilder`/`SemanticLimitKind`,
  `LimitKind::{Source, Semantic}`, `OpenOptions` (`Package`, `Presentation`
  and `MergeReader` take it); invalid values are
  `Error::InvalidLimit { kind, value, maximum }`. Defaults equal the former
  archive maxima (no behaviour change; the shared 512 MiB default is not
  adopted — follow-up). The IWA archive dimensions are named
  `ComponentObjects`, `ComponentMessages`, `MessageBytes`, `HeaderFields`
  (the leaf public-API checker rejects "archive" on the semantic surface).
  `Package::{open_with_limits, from_bytes_with_limits, limits,
  read_options}` deleted; `options()`, `source_limits()` added.
- **Wrong family.** `NotKeynote` → `UnexpectedFormat { detected: FileFormat }`
  in `ReadError` and `presentation::Error`.
- **Families.** 220 prefixed names (`SlideTextCommit`, …) moved to focused
  modules with `{Edit, Patch, Commit, Diagnostics, Error, LimitKind}`:
  `edit`, `chart::{arrangement, axis_title, caption, legend, title,
  value_axis, data, metadata}`, `background`, `build::order`,
  `slide::image::adjustments`, `slide::movie::{caption, geometry, playback,
  title, creation}`, `slide::audio::{position, creation}`,
  `slide::{notes, order, text}`, `slide::comment::transaction`,
  `slide::media::{data, properties, lifecycle}`,
  `slide::table::{appearance, dimension, lock, name, sort, title,
  number_format, merge, headers, physical_sort}::transaction`,
  `slide::table::cells`. 41 families are registered (including the new
  `slide::creation` and `slide::drawable`). Not registered: the media
  lifecycle and audio/movie creation families (their package methods return
  the commit directly, there is no `Edit`), and the error-only
  `chart::metadata` / `slide::table::cells`.
- **Create.** `Package::new()`, `builder::Builder`, `identity::Identity`
  (§2.4).
- Crate-internal code keeps a few prefixed spellings as private import
  aliases; public items, rustdoc, crate docs and examples use the new paths.

## 2. Leaf structural APIs (`litchi-keynote`)

### 2.1 Structural kernel (`src/package/structure/`)

Production litchi-keynote code may not use Prost (boundary checker), so
structural edits work on the wire:

- `schema.rs` is generated by `tools/gen_keynote_reference_schema.py`
  (`--check` in the gates) from the tracked `.proto` files: for each admitted
  native message type, where its `TSP.Reference`/`TSP.DataReference` fields
  live. The type-id → message mapping was verified on every Keynote file in
  `test-data/iwork/keynote`: each object's `MessageInfo.object_references` is
  contained in the references the schema walk finds. (`object_references` is
  not complete — a text storage's stylesheet reference is not listed — so
  payloads are always walked.)
- `refs.rs` visits/rewrites references schema-directed; `metadata.rs` edits
  `TSP.PackageMetadata` raw-preservingly (components, external/data
  references, object UUIDs, `DataInfo`, watermark, save tokens advanced like
  the existing save-token codec); `workspace.rs` stages components
  copy-on-write, allocates identifiers, clones objects with deterministic
  SHA-1-derived UUIDs and publishes one `reassemble_with_changes_to_bytes`
  pass; every published candidate is reopened, validated and read back.

### 2.2 `slide::creation` (request 8) — `baa85c9f33`

`Package::edit_slide_creation()`: `duplicate_slide(selector, Position)` and
`add_slide(LayoutSelector, Position)`, several per edit, one commit;
`Package::{slide_layouts, default_slide_layout, apply_slide_creation}`.
All 17 `basic.key` layouts are admitted (layout media materialized,
slide-number attachment prepared, title/body/notes cleared). Duplication
clones the slide's dedicated component; slides whose content lives in other
components (tables, charts, comments) are typed refusals
(`Unsupported::ExternalContent`/`UnmodelledContent`): 13 of 44 decks
duplicate slide 0, 31 refuse.

### 2.3 `slide::drawable` (requests 9, partially 10) — `9b57fea8bf`, `802995d7b7`, `29652e15e8`

`Package::slide_drawable_list(slide)` (kind, geometry, text, name, lock,
z-position, same source order as `DrawableSelector`),
`slide_drawable_text_runs` (read-only runs), `slide_layout_list`;
`Package::edit_slide_drawables()`: `set_geometry`, `set_text` (minimal span),
`remove` (text boxes, shapes, lines, images with their private closure,
UUIDs and data owners), `move_to` (z-order), `add_text_box`,
`add_shape(Preset::{Rectangle, RoundedRectangle, Ellipse})`,
`add_image` (PNG/JPEG/GIF; new `Data/` member and `DataInfo`), several per
edit, one commit. Typed refusals: tables/charts/groups/movies/placeholders
for removal, externally referenced drawables, unknown image formats,
**character-style writes** (`Unsupported::TextStyling`: the host only
styles whole storages through paragraph overrides and the corpus has no
native character-style table to validate against).

### 2.4 `Package::new()`, `Builder`, `Identity` (request 1) — `a9a28de158`

`Identity::generate()` is the only randomness in the crate;
`Identity::from_bytes` refuses nil/equal UUIDs; `Identity::BLANK` is a fixed
documented identity. `Package::new()` (one title-and-subtitle slide,
1920×1080, `Identity::BLANK`) is byte-deterministic.
`Builder::{identity, title, subtitle, notes, slide_size}.build()`;
building without an identity is `builder::Error::MissingIdentity`; equal
identities give equal bytes. The template `crates/litchi-keynote/assets/blank.key`
(9,642 bytes, SHA-256 `a76f8457…5e5376`) was generated once by the legacy
host builder at `802995d7b7` and stamped with `Identity::BLANK`; provenance
and the generator program are in `assets/README.md`. Its internal object
UUIDs are shared by every built document (only the three document UUIDs
change).

## 3. Unified layer (`litchi-ops`) — `3c57735c91`, `57b98ff8a8`, `b22ede3dfd`

Element and property names follow the PPTX/ODP registry.

| Element | Reads | Writes |
|---|---|---|
| `presentation` | `slideCount` | `create(Format::Keynote)` → `Package::new()` |
| `slide` | `name`, `title`, `hidden`, `layout` | `set hidden`; `add` (`layout` by name/number, theme default, or a copy via `from`; any position); `remove` (multi-slide decks: F8 closed); `move`, `swap` |
| `placeholder` (title, body) | `type`, `text`, `x`/`y`/`width`/`height`/`rotation`/`zorder` | `set text`, frame |
| `notes` | `text` | `set text` |
| `paragraph` | `text` | `set text`, `add`, `remove`, `move` within one text |
| `run` | `bold`, `italic`, `underline`, `size`, `color`, `font.latin` (on demand) | read-only (gap, request 10) |
| `shape` (text boxes, shapes) | frame, `text`, `name` | `set` text/frame; `add` text box / shape (`preset` rect/roundRect/ellipse); `remove`; `move` (z-order) |
| `picture` | frame | `add` (`src` data URI or path), `set` frame, `remove`, `move` |
| `connector`, `video`, `audio`, `chart`, `group` | kind, frame | remove of lines; others gaps |
| `table`/`tr`/`tc` | `name`, `rows`, `cols`, cell `text`/`type` | gaps |

- **Coalescing.** In one `edit`/`batch`, consecutive drawable sets/adds
  become one `slide::drawable` leaf commit plus one commit per changed text;
  consecutive slide adds become one `slide::creation` commit. Per-item error
  attribution and all-or-nothing atomicity are tested.
- **Typed gaps (with follow-ups):** run styling (request 10); table cell
  writes and table creation; table/chart/group removal; movie/audio
  removal, creation and frame (leaf families exist:
  `slide::media::lifecycle`, `slide::movie::geometry` — wire next);
  placeholder add/remove, slide-number/object placeholder elements;
  duplication of slides with external content; package directories
  (request 16); text/notes edits leave the stale thumbnail registry record
  (deletion now tolerates it; writers should clean it).

## 5. Performance

`crates/litchi-ops/examples/keynote_bench.rs`, `multi-slide.key`, release,
`taskset -c 27` on a shared 32-core host, ABBA × 8 rounds × 30 calls, three
runs; summary `results/0298/keynote-bench-summary.jsonl` (raw JSONL outside
the repository, sha256 recorded there; binary sha256 `5c24a724…`).

| Scenario | leaf | unified | ratio (3 runs) | Budget |
|---|---|---|---|---|
| open | 1.70 ms | 1.66 ms | 0.97–0.98 | met (≤5 %) |
| open + get | 1.72 ms | 1.87 ms | 1.085–1.089 | **missed** (see below) |
| set title | 4.97 ms | 5.15 ms | 1.035–1.040 | met (≤10 %) |
| set notes | 2.85 ms | 3.06 ms | 1.075 | met |
| set frame | 2.97 ms | 3.19 ms | 1.055–1.057 | met |
| 1k-op batch | 7.87 ms | 8.43 ms | 1.070–1.072 | met (≤2×) |
| duplicate slide | 3.35 ms | 3.56 ms | 1.061–1.064 | — |
| add slide | 16.4 ms | 16.5 ms | 1.008–1.012 | — |
| add text box | 3.08 ms | 3.25 ms | 1.052–1.060 | — |
| remove slide | 6.06 ms | 6.24 ms | 1.029–1.033 | — |

The 1k-op batch leaf leg is hand-written as one minimal-span text edit plus
one frame edit, i.e. the same coalesced leaf work. **Miss:** `open + get` is
≈150 µs (8.5–8.9 %) over the leaf; callgrind (`results/0298/callgrind-open-get.txt`)
shows the first read builds every slide's drawable list and layout
(≈41 % of the tree build). Follow-up: build drawables and layouts per slide
on demand. `add text box` was 1.105–1.110 before `b22ede3dfd` removed a
second tree build.
