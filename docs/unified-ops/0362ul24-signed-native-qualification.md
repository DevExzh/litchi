# 0362ul24 — signed native no-op/replay qualification

- Status: protocol and capability matrix; no native timing result is claimed
  until a protected build runs the guarded runner.
- Scope: the signed exact-no-op, content-bound replay, signature-preserving
  publication and explicit `Signed::unsign` + write routes introduced by
  [0362w](0362w-signed-noop-replay.md), for every signed format in the current
  signature policy test matrix.
- Required companion files: `results/0362ul24/signed_native_probe.rs`,
  `signed_native_qualification.py`, `validate_signed_native.py` and their
  failure-case tests. `signed_native_memory.py` is the external allocation
  collector and `signed_native_finalize.py` is the only completion collector:
  a latency manifest ends at `status = latency_complete` and can be inspected
  on its own, but the final status cannot become `complete` without the
  endpoint-bound memory summary. The probe is an
  external qualification consumer; it does not change a format crate or the
  frozen 109-route W8 probe.

## 1. Evidence boundary

The signed opener is deliberately a metadata policy, not a cryptographic
verifier. `File::is_signed()` and `Signed::origin()` establish that the
current opener found the expected OPC or compound-file signature graph. They
do not establish that a certificate, digest or XML signature value verifies.
The producer fixtures below are known signed inputs from the Apache POI corpus,
but this qualification records `signature_presence = detected` and
`cryptographic_verification = not_performed` for both producer and synthetic
inputs. A result may not upgrade that field merely because the package has an
`_xmlsignatures` member or a dummy `<Signature/>` stream.

The probe creates the synthetic wrappers with the same safe public builders as
the policy test (`crates/litchi-ops/src/tests/signature.rs:140-248`). It does
not hand-author a pass receipt, re-mark an unsigned package as signed, or use
a synthetic patch in place of a native edit. The timed region begins after
fixture construction, input opening and native target/value discovery.

## 3. Route/capability matrix

Each row is run for every fixture where the format's policy test demonstrates
the route. `leaf` means the public format-bearing `File` below `File::Signed`
(`Signed::file()`); `facade` means the outer `File::Signed`. This is an
intentional public leaf/facade pairing and does not pretend that the wrapper
is a direct format-crate `Package` benchmark. The direct native package
checks listed in §4 are separate correctness preflights.

For `unsign_write`, `Signed::unsign(self)` necessarily consumes the signed
wrapper and returns its underlying owner. The leaf and facade labels both
exercise that returned public owner after the explicit consume; they do not
invent a second wrapper or claim that `Signed::file()` can consume itself.

| route | operation | required correctness proof | baseline f2 status | timing status |
|---|---|---|---|---|
| `signed_leaf/noop_commit` | native same-value setter through `Signed::file().edit(...)` | `diagnostics.changed = false`; patch is native no-op; output remains signed and byte-identical | `unsupported/refused` if the old source cannot admit signed no-op; never time an error as a pass | final leaf/facade comparison; no historical ratio |
| `signed_facade/noop_commit` | same setter through `File::Signed.edit(...)` | same as leaf, plus result remains `File::Signed` | `unsupported/refused` unless old route passes the same proof | final leaf/facade comparison; no historical ratio |
| `signed_leaf/noop_replay` | apply leaf no-op patch to independently reopened signed leaf | same format and exact recorded base; replay remains signed and bytes equal | `unsupported/refused` if no signed patch admission | final leaf/facade comparison; no historical ratio |
| `signed_facade/noop_replay` | apply facade no-op patch to independently reopened signed facade | same as leaf, including wrapper/origin and bytes | `unsupported/refused` | final leaf/facade comparison; no historical ratio |
| `signed_leaf/refusal` | real native change on signed leaf | `RefusalKind::ProtectedDocument`, fixed reason/code; source bytes unchanged; no output publication | correctness only; an expected refusal is not a timed success | correctness only |
| `signed_facade/refusal` | real native change on signed facade | same refusal and no publication | correctness only | correctness only |
| `signed_leaf/unsign_write` | consume `Signed::unsign`, changed native setter, stream `write_to` | unsigned result; signature graph/streams absent; changed semantic marker present; reopen is unsigned; source clone still refuses | existing explicit `Signed::unsign` route is paired only when this proof passes; a failed old route is a preflight failure, not a timed refusal | final leaf/facade comparison; no historical ratio |
| `signed_facade/unsign_write` | same through facade-owned signed handle, then write | same byte/signature/source proof; facade source clone remains protected | existing explicit `Signed::unsign` route; same proof and pairing rule as the leaf | final leaf/facade comparison; no historical ratio |
| `signed_leaf/unsigned_negative` | apply an authorized unsigned no-op patch to signed recipient | `PatchConflict`, classified `invalid_input`; no signature re-marking | not applicable | correctness only |
| `signed_facade/unsigned_negative` | facade counterpart | same | not applicable | correctness only |
| `signed_leaf/source_freshness` | path-backed signed no-op/replay after external source mutation | `SourceChanged`, classified `io_error`; no publication | not applicable | correctness only |
| `signed_facade/source_freshness` | facade counterpart | same | not applicable | correctness only |
| `signed_leaf/budget` | same-value native setter under finite `EditOptions`/`SemanticLimits` | authored operation/snapshot charge is retained; budget refusal is typed; no bypass by no-op collapse | not applicable | correctness only |
| `signed_facade/budget` | facade counterpart | same | not applicable | correctness only |

“Final-only” is a capability classification, not a historical before/after
ratio. Every final-only route is still qualified with an actual final binary
leaf/facade ABBA pair: `[leaf, facade, facade, leaf]`, five or more blocks,
independent 500 ms calibrations and the reported `facade_leaf_ratio`. The
manifest carries no `after_before_ratio` for these routes. A route cannot be
left permanently unqualified merely because the historical f2 endpoint could
not admit a signed no-op.

## 4. Direct format-native preflight

The timed leaf/facade pair is the public unified leaf/facade boundary. Before
the timing window, the probe also runs the format-crate route documented by
the existing policy test. This prevents the pair from hiding a missing native
capability:

| format | direct native route | expected signed result |
|---|---|---|
| DOCX | `litchi_docx::Package::from_reader(...).edit().commit()` and source-backed `Package::from_read_at(...).edit().commit()` | exact no-op, signed bytes preserved |
| PPTX | eager `litchi_pptx::Package` and `litchi_pptx::source::Package` edit/commit | exact no-op, signed bytes preserved |
| XLSX | eager `litchi_xlsx::Package::edit().commit()` and source-backed defined-names edit/commit | exact no-op, signed bytes preserved |
| XLSB | `litchi_xlsb::Package::edit_cell_values(...).resolve().commit()` | exact no-op, signed bytes preserved |
| XLS | `litchi_xls::Package::from_bytes(...).edit().commit()` | exact no-op, signed bytes preserved |
| DOC | `litchi_doc::source_backed::Package::from_bytes(...)` | refusal is expected for the signed source-backed editor; the facade route is the supported signed no-op path |
| PPT | `litchi_ppt::text_edit::SourceSnapshot::open(...)` | refusal is expected for the signed source snapshot; the facade route is the supported signed no-op path |

The direct DOC/PPT refusals are visible capabilities, not silently converted
to successful no-op timings. The probe records the typed result and the runner
requires the matrix's expected disposition.

## 5. Timing and memory protocol

1. Build two clean, release, pinned endpoint binaries from full source commits
   with the reviewed external consumer preparation driver. The f2 endpoint is
   exactly `f2bbbc8d07ab5da26c180f1ff74813d39f632d54`; the final endpoint is
   exactly `472b6705475b073e7fe08f6e11ee17fb1e29f838` from the immutable
   `final-api-capture-472b670547/source` checkout. The driver verifies a clean
   tree, writes a separate external package, runs `cargo generate-lockfile
   --offline`, `cargo metadata --offline --locked --format-version=1`, and
   `cargo build --offline --locked --release`, then executes `--mode list` and
   every `--mode validate` route to derive the endpoint capability map. The
   endpoint manifests bind the source root/ref/tree hash, source archive,
   adapter/probe, lock, normalized dependency projection, build receipt,
   tracked fixture tree and binary SHA-256. No target directory is shared
   between endpoints; the adapter selects the f2 public-field/limits and
   XLSB `Option<Edit>` APIs through its consumer feature rather than changing
   a production crate.
   The staged fixture root and its canonical `fixtures.json` are external to
   both immutable source trees. Their artifact path and SHA-256 are passed to
   the probe as `LITCHI_SIGNED_FIXTURE_MANIFEST` and
   `LITCHI_SIGNED_FIXTURE_MANIFEST_SHA256`; `LITCHI_SIGNED_FIXTURE_ROOT` is a
   separate root-containment input.
   The endpoint `Cargo.lock` files remain role-specific; validation does not
   compare their bytes. It compares each generated selected closure against
   the fixed `tools/w8_projection_policy.py` registry identities, checksums
   and dependency edges, and permits only the reviewed local edge delta plus
   the external `signed-native-consumer` package.
2. Run correctness/preflight and direct native checks before timing. A route
   that fails any byte, signature-state, refusal, source-freshness or budget
   proof is rejected before calibration.
3. For timed routes, fixture construction, opening, target discovery, props
   construction, patch replay recipient opening and correctness validation are
   outside the clock. `noop_commit` clocks only the native commit operation;
   `unsign_write` clocks the authorized changed commit and bounded streaming
   publication as separate routes. The probe's digest sink retains no output
   buffer and reports bytes, writes and maximum write size.
4. The guarded Python runner pins one CPU, requires a quiet process window,
   rejects Cargo/rustc/rustdoc/profilers/other probes and records full `/proc`
   snapshots before, during and after each child. Children have explicit
   timeout, RSS and stdout/stderr caps; every timeout or guard failure kills
   the process group, waits for it, records the failed-after receipt and then
   checks the host again. Validation binds the exact taskset/mode/route argv,
   raw stdout object and retained output-byte/RSS values to that canonical,
   hash-bound child receipt; a child receipt with a changed route, JSON, cap,
   timeout or failed-after field is rejected. The runner is a Linux child
   subreaper and tracks the complete descendant tree, including `setsid` and
   reparented children; every owned descendant is killed and reaped before a
   receipt can report an empty process tree. This ownership helper is scoped
   to the standalone serial controller: one Python thread, one live tracker
   and one `Popen` subtree at a time. It records the pre-existing direct-child
   set before that `Popen`; new direct children during that owned window are
   target descendants. It is not a generic concurrent-embedding claim, and a
   second tracker or controller thread is rejected. Each route calibrates to
   at least 500 ms, rejects samples below 150 ms, and runs at least five outer
   blocks. Final-only blocks are exactly leaf, facade, facade, leaf.
5. Allocation evidence is separate and per fixture. The probe introduces no
   allocator or `unsafe` code. The external memory runner profiles the same
   uninstrumented final binary with identical setup for each fixture, route
   and call count `1`, `8` and `128`; its scope is explicitly the whole
   process, including fixture open and setup, and profiler overhead is
   reported. It runs `/usr/bin/heaptrack --record-only` followed by the
   reviewed `tools/perf_resource_profile.py` parser (SHA-256
   `e80c9706189f942ccce645685dafea8612e5e0dc6ea5e659bd1490ffc3256cc4`; an
   owner-approved valgrind Massif equivalent would require a new reviewed
   parser identity), keeps raw captures outside Git, and commits only
   hash-bound reduced summaries. The validator recomputes every retained
   allocation/heap/RSS metric from the retained print and histogram and
   requires the final memory summary itself to be canonical JSON. Every row's
   label, work directory, capture prefix, parser outputs, stdout/stderr and
   ordered host snapshots are bound to its unique fixture/route/call tuple;
   no retained artifact may be reused by another row. These profiles are
   bounded-retention evidence, not native latency samples.

6. Run `signed_native_finalize.py` only after both receipts have been checked.
   It revalidates endpoint archives, role-specific lock closures and registry
   identities, every latency child receipt, every external memory artifact and
   the exact fixture/route/call matrix before writing `status = complete`.

## 7. Acceptance rules

- A producer or synthetic signature-presence fixture is accepted only when
  `signature_presence`, `origin`, format and source bytes all match the
  manifest. Cryptographic verification remains explicitly `not_performed`.
- A signed no-op is accepted only when diagnostics, native patch identity,
  signature state, exact output bytes and replay base identity all pass.
- A changed signed operation that returns an expected refusal is a correctness
  result, never a timed “before” value.
- `unsign_write` is accepted only when the output is semantically changed,
  signature parts are absent, the reopened output is unsigned and an
  independently retained signed clone still refuses.
- Source freshness, patch conflict and limits must retain their typed
  dispositions and fixed codes. Any error hidden by a generic protected
  refusal fails the route.
- Final-only signed routes report only the truthful final leaf/facade ratio;
  no historical before/after ratio is fabricated or required.
