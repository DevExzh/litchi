# 0361fda native IWA qualification harness

This directory contains the replacement for the interrupted 0361fd native
qualification attempts. The constructor probe retains all 15 routes from the
0361fb retained-header protocol. The owner probe retains the four measured
routes: Numbers header settings, Keynote media replacement, Pages footnote
insertion, and Pages section-name replacement.

The probes do all semantic and byte checks before starting their timed loops:

- constructor routes prove canonical and retained-header round trips and
  report an accepted header limit plus the exact typed one-below rejection;
- owner routes prove changed output, replay, inverse, and an exact no-op in the
  same edit family (including the inserted body footnote);
- every timed result carries source/output SHA-256 identities and a semantic
  checksum.

`iwa_native_qualification.py` snapshots both source commits and records an
`integrated-route` source delta containing the full resolved baseline and
candidate commit ids plus every changed, added, or removed archived source
file with its byte count and SHA-256. Build admission verifies this delta
before starting Cargo. Each endpoint copies the recorded seed and runs
`cargo metadata --offline --format-version=1` once to add only the external
probe package and source-local closure; this deliberately unlocked preparation
must preserve the seed's registry pins. Before any release build, the runner
requires every common registry identity, and every registry identity required
by the selected source closure, to match the pinned seed by name, version,
source, and checksum. It also requires identical endpoint common identities
and every added/removed registry package and local edge/feature to match the
selected source dependency delta. The required registry edges and complete
selected local closure must be present in both endpoint locks and the pinned
seed; the constructor's reviewed `smallvec` lock addition is pinned to
version 1.16.3 and its recorded crates.io checksum. The owner source adds the
same edge but already has that identity in its baseline closure, so its lock
delta records no registry addition while still checking the exact required
identity. Lock edges must be declared by the corresponding source manifest;
inactive target and development edges are admitted only when declared, and
unrelated lock edges are rejected. Release builds use `--locked`; validation, timing, and collection
recompute both comparisons from retained source and lock artifacts. There is
no shared-prefix or blanket lock-drift exception. The runner also freezes the
lockfile identities, records toolchain and binary hashes,
requires native and allocation validation for both endpoints, and then runs
the fixed five-block ABBA protocol (two warmups, 500 ms calibration target,
150 ms sample minimum, and a 120 s child bound). A build/profiler/benchmark
process seen before, during, or after a leg aborts the attempt; no
contaminated block is retained as qualified timing. Calibration and warmup
legs are checked for the same cross-side source/output/checksum identities as
measured blocks. A route subset or changed protocol must be passed with
`--diagnostic`; it is recorded but can never set `qualified`.

All generated projects, binaries, receipts, raw output, and timing evidence
must live outside this checkout. The owner fixture directory must contain
these files. The four native inputs are copied from tracked `test-data/iwork`
fixtures; `footnote-fixture.pages` is generated by the tracked
body-footnote graph builder used by the existing lifecycle test:

```text
basic.numbers
media-replacement-native.key
tone.wav
footnote-fixture.pages
basic.pages
```

It must also contain `manifest.json` with schema
`litchi.iwa.owner-fixtures.v1`, a `provenance` artifact row for
[`fixture-provenance.json`](fixture-provenance.json), and an absolute,
SHA-256/byte-count artifact row for each of the five files. The four native
rows carry a `source` identity matching the tracked provenance; the generated
`footnote-fixture.pages` row carries `generated` identities for the tracked
Cargo/example/test sources and [`generate_footnote_fixture.py`](generate_footnote_fixture.py).
The runner replays this generator and byte-compares its output before
validation/timing, so a manifest cannot self-authorize a replacement fixture.
The generator writes only outside the checkout, for example:

```sh
python3 docs/unified-ops/results/0361fda/generate_footnote_fixture.py \
  --output /outside/iwa-fixtures/footnote-fixture.pages
```

To copy all tracked inputs and write the checked manifest in one step, use:

```sh
python3 docs/unified-ops/results/0361fda/iwa_native_qualification.py \
  prepare-fixtures /outside/iwa-fixtures
```

The runner checks those identities before validation and again before timing,
and retains/rechecks every build and validation command receipt plus both
source snapshots. `build --fixtures` is intentionally not accepted: fixtures
are an input to validation and timing, never a hidden build dependency.

After a complete native attempt, collect the handoff packet with:

```sh
python3 docs/unified-ops/results/0361fda/iwa_native_qualification.py \
  collect owner /outside/iwa-owner --attempt native-a1 \
  --out /outside/iwa-owner/collection.json
```

Collection verifies the same source delta, source refs, build and validation
identities retained by the run manifest.

Run the Python unit tests without Cargo:

```sh
python3 -m unittest discover -s docs/unified-ops/results/0361fda -p 'test_*.py'
```

The host coordinator must supply a quiet window before the `run` phase. The
build phase is deliberately separate so source and binary provenance can be
reviewed before any native timing is attempted.

Before native timing, collect the required operation-allocation packet for
every route. The allocation binary is a separate counting-allocator build;
the native binary is never used for this phase. Each route runs exactly 100
operations in an `ABBA` order, with the same CPU pinning and before/during/after
quiet-host guards as native children. The packet retains `peak`, `retained`,
`allocated`, and `allocations` from the operation closure. It makes no latency
claim and fails closed if the owner probe does not report real allocation
metrics or if either endpoint changes its paired metrics:

```text
python3 docs/unified-ops/results/0361fda/iwa_native_qualification.py \
  allocation constructor /outside/0361fda --attempt allocation-a1 --cpu 29
python3 docs/unified-ops/results/0361fda/iwa_native_qualification.py \
  allocation owner /outside/0361fda --attempt allocation-a1 --cpu 29 \
  --fixtures /outside/iwa-fixtures
```

The constructor packet covers all 15 routes and the owner packet all four.
The allocation attempt must complete before the fixed native `run` command;
native timing remains a separate quiet-window operation.
