# ADR 0017: Format-owned deterministic OOXML producer templates

- Status: Accepted
- Date: 2026-08-03

## Context

The OOXML migration host invoked `xml-minifier` from production template code.
That made generated DOCX, PPTX, XLSX, and XLSB packages depend on a build-time
text transformation owned outside the format crate. XLSB also synthesized
core-property timestamps from ambient wall-clock time and formatted them
through an infallibility assumption.

Producer templates are format assets. Their exact generated bytes, update
workflow, and review boundary should belong to the format that emits them,
while the minifier remains a development tool with an executable parity test.

## Decision

Readable XML sources remain beside each format. Their minified counterparts
are deterministic checked-in files below format-local `resources/generated`
directories and are embedded with `include_str!`. DOCX, PPTX, XLSX, and XLSB
template modules own the embedded assets they emit. The production
`litchi-ooxml -> xml-minifier` dependency and its executable boundary-debt
entry are removed.

`xml-minifier` retains one responsibility in this workflow: its integration
test regenerates every listed asset and requires exact byte equality with the
checked-in output. Its macro emits an `include_str!` dependency marker so an
input change invalidates expansion even when the caller uses the tool in a
different format.

Fresh core-property templates represent a present but semantically empty
document. They do not invent a creator, revision, modification time, or other
history. XLSB application and theme payloads retain their previous exact bytes;
only their ownership and construction path change. Runtime clock access and the
timestamp-formatting `unwrap` are removed from XLSB creation.

## Consequences

- Production package creation has no text-minifier dependency or ambient-time
  input.
- Source XML remains readable, while emitted bytes are reviewable and stable.
- Updating an asset requires updating its generated peer; parity tests reject
  drift.
- Checked-in generated XML increases repository size. This is an intentional
  trade for deterministic builds and explicit review.
- The change establishes ownership and determinism, not faster creation or
  lower memory use. Those claims require measurement. It also does not by
  itself certify every template in Microsoft Office.

## Verification

All 39 generated assets pass exact regeneration and source-parity tests.
Focused `xml-minifier` tests and the three XLSB producer regressions pass.
Warning-denied Clippy and rustdoc are green for `xml-minifier` and
`litchi-ooxml`; formatting, manifest sorting, diff validation, the executable
dependency policy, and a dependency-tree audit are also green.

The boundary checker accepts 35 packages, 106 direct internal dependency
declarations, and 13 explicit migration debts after removing this edge. Per
explicit user direction, the previously green full-workspace suite is not
repeated.
