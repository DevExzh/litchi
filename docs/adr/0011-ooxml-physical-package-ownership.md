# ADR 0011: Physical package ownership below the OOXML migration host

- Status: Accepted
- Date: 2026-08-03

## Context

The `litchi-ooxml` migration host still declared `soapberry-zip` after its OPC
implementation moved to `litchi-opc`. Three remnants kept that edge alive: a
PowerPoint chart helper wrote an embedded XLSX package with a concrete ZIP
writer, an XLSX fixture test filtered a broken thumbnail with concrete ZIP
readers and writers, and the XLSB migration error accepted a concrete ZIP
error even though no production path constructed that variant.

The target topology gives physical OPC packaging to `litchi-opc`. A format
crate may own the semantic graph of an embedded workbook, but it must not bind
that graph to a ZIP implementation or expose the implementation's error type.

## Decision

`litchi-ooxml` has no direct archive-implementation dependency. Complete
logical packages use `litchi_opc::PackageWriter`. Focused code that must emit a
small already-validated physical package, or inspect a deliberately malformed
test fixture that cannot form an `OpcPackage`, uses the typed
`litchi_opc::phys_pkg::{PhysPkgReader, PhysPkgWriter}` boundary.

The chart workbook helper keeps its existing semantic XML generation but
passes canonical `PackURI` values and package bytes through the OPC owner. OPC
errors remain typed as `OoxmlError::Opc`; they are not flattened into formatted
strings. The unused `XlsbError::Zip(String)` path and concrete-error conversion
are deleted rather than retained as compatibility surface.

Tests may sanitize a malformed third-party package through the same physical
OPC boundary. They do not call or name the underlying archive reader, writer,
or error type. A generated embedded workbook is reopened as an `OpcPackage` and
its workbook and worksheet parts are asserted, rather than treating a four-byte
ZIP signature as sufficient validity evidence.

Boundary-debt order 044 is deleted only after the manifest and source tree have
no direct `soapberry-zip` reference.

## Consequences

- Within the OOXML stack, `litchi-opc` is the only owner that translates between
  OPC operations and the selected ZIP implementation.
- The OOXML migration host can change physical archive implementations without
  changing its dependency graph or public errors.
- Removing the implementation edge keeps the remaining vertical-format
  migration independent of the selected archive crate at its direct boundary.
- This ownership correction makes no throughput, allocation, compression-ratio,
  or compatibility claim. Representative measurements and native Office gates
  remain separate evidence.

## Verification

The chart-workbook tests must reopen generated bytes through `OpcPackage`; the
connections regression must still parse the curated malformed fixture after
removing only its broken thumbnail edge. Warning-denied Clippy, rustdoc, the
boundary-checker regressions, and a manifest/source assertion must all pass.
